# 자주 겪는 문제

전부 실제로 겪은 것들입니다. 증상 → 원인 → 대처 순으로 적었습니다.

---

## 상태창이 아예 안 뜬다

가장 흔합니다. 원인이 보통 둘 중 하나이고, **둘 다 고쳐야** 합니다.

**원인 1 — 시작 프롬프트에 언급이 없음.** 도입부에서는 더 구체적인 지시가 이깁니다. 통합 프롬프트에 "매 응답 필수"라고 써도, 시작 프롬프트에 상세한 5단계 절차가 있으면 그쪽이 이깁니다.

→ 시작 프롬프트에도 한 줄 넣습니다. "모든 응답 끝에 상태창을 붙인다."

**원인 2 — 템플릿이 `출력 예:` 아래에만 있음.** 예시 구역 안에 있는 것은 요구사항으로 읽히지 않습니다.

→ `# 상태창`이라는 **자체 섹션**을 만들고, 그 안에 요구사항 문장과 채워넣을 틀을 둡니다.

일반 규칙: **필수 출력 블록은 예시 구역 안에만 존재하면 안 됩니다.** 요구를 진술하는 자기 섹션이 있어야 합니다.

---

## 상태창을 매번 내는 게 낭비 아닌가

작품의 출력 계약에 따라 다릅니다. 상태창은 별도 대화기록이나 저장 API가 아니라 플레이어에게 보이는 현재 상태 표시입니다.

- 장식용 요약이면 비었을 때 생략해도 됩니다.
- **고정 HUD를 약속한 작품이면 매 응답에 냅니다.** 바뀐 값이 없어도 직전 공개값을 그대로 옮겨 적습니다.

고정 HUD가 필요 없는 작품에 연속성을 이유로 상태창을 강제하지 마세요. 어느 쪽을 택했는지와 위치·형태·생략·갱신 규칙을 프롬프트에 명시하세요.

## 메타 발언이 샌다

세계 안의 태블릿 양식에 `(선택사항, OOC)`가 찍히거나, 상태창 위에 없던 `INFO` 라벨이 생기거나, 첫 줄에 작품 제목이 나옵니다.

**원인.** 컴파일된 프롬프트가 모델에게 작업 어휘를 가르칩니다 — `ⓤ`, `ⓒ`, `OOC`, `SAFE`/`UNSAFE`, 섹션 이름, 상태창을 가리키는 단어 자체. 명시적으로 금지하지 않으면 이게 픽션으로 샙니다. 그리고 **프롬프트가 가장 빽빽한 도입부에서 가장 심하게** 샙니다.

**대처.** `# 메타 금지` 섹션을 만들고 **실제 금지어 목록**을 적습니다.

```
ⓤ에게 보이는 출력에 제작 용어를 쓰지 않는다.
금지어: OOC, 프롬프트, 시스템, 규칙, 세션, 턴, SAFE, UNSAFE,
키워드북, ⓤ·ⓒ·AI 같은 이 문서의 약어와 섹션 이름.
```

## 턴이 짧고, 이야기가 안 나아가고, 내가 안 한 행동을 한다

세 증상이 **한 원인**입니다. 프롬프트에 금지만 쌓이고 **"매 응답에 무엇이 반드시 달라져야 하는가"가 없는 상태**입니다.

금지는 플레이할 때마다 하나씩 늘어납니다. 메뉴 금지, 갈림길 금지, 질문으로 끝내기 금지, 두 사건 동시 시작 금지… 반면 적극 규칙은 늘지 않습니다. 그러다 보면 모델에게 **허용된 땅이 거의 남지 않습니다.**

그런데 모델은 뭐라도 써야 합니다. 정당한 재료가 다 막히면 **울타리가 없는 유일한 땅 — 플레이어의 내면과 행동 — 으로 들어갑니다.** 주도권 규칙이 있는 프롬프트가 주도권을 침해하는 경로가 이겁니다. 내레이터를 굶기면 그렇게 됩니다.

**진단.** 프롬프트에서 `×` 개수를 세고 적극 요구와 비교하세요. 몇 배 차이가 나면 개별 금지가 아무리 옳아도 과잉 제약입니다.

**대처.** 천장이 아니라 **바닥**을 적습니다.

```
매 응답은 상황을 실제로 움직인다. ⓒ의 행동·환경 변화·직전 행동의 결과·시간 경과·새 정보 중
최소 하나가 응답 끝에 달라져 있어야 한다. 아무것도 안 달라진 응답×.
ⓤ의 입력이 짧아도 세계는 제 속도로 움직인다→빈자리를 ⓤ의 행동·심경·판단으로 채우지 않는다.
채울 것은 언제나 ⓤ 바깥에 있다.
```

두 가지가 동시에 작동합니다. **정당한 재료를 나열**해서 갈 곳을 주고, **아무것도 안 달라진 응답 자체를 위반으로** 규정합니다.

그리고 새 규칙과 **충돌하는 문장을 찾아 지우세요.** `매 턴 사건 발생 강제×` 는 원래 페이싱 강요를 막으려던 것인데, 이제는 빈 응답을 허가하는 문장이 됩니다.

분량도 같이 올리세요. 800~1,400자는 사건 하나를 제대로 굴리기에 짧습니다.

## 템포가 너무 느리다 — 측정 하나에 5턴

**원인 둘이 곱해집니다.**

1. 통합본의 `한 응답에 주요 사건 둘 이상 시작×` 에 **절차 예외가 없습니다.** 접수·대기·호출·측정·통보가 각각 한 턴을 먹습니다.
2. 시작 프롬프트가 단계를 번호로 나열하고 `한 응답에서 여러 단계를 몰아 끝내지 않는다` 까지 붙이면 **최소 턴 수를 명령한 셈**이 됩니다.

의도는 옳았습니다 — 전환을 몰아치면 무게가 사라지니까요. 문제는 그 예산을 **서류에도 똑같이 쓴다**는 것입니다.

**대처.**

```
한 응답에 주요 전환 둘 이상 시작×. 단 절차·대기·이동·행정은 전환이 아니다→몰아 처리하고 요약한다.
턴은 ⓤ의 결정이 결과를 바꾸는 지점에만 쓴다.
```

판별 기준은 하나입니다. **플레이어가 받기만 하는가, 정하는가.** 측정 결과·타인의 반응·행정 통보는 받는 것이라 장면을 따로 만들지 않습니다.

그리고 도입부를 **번호 목록이 아니라 도달 지점으로** 적으세요.

```
1→2→3→4→5 (나쁨)              세 번째 응답 안에 등급이 나오고 소속이 확정된다 (좋음)
```

번호를 주면 모델이 단계 수를 목표로 삼고, 시점을 주면 시점을 목표로 삼습니다.

## 엑스트라 대사가 지문 안에 묻힌다

```
*누군가 뒤에서 외쳤다. "물러나! 통제선 밖으로!"*
```

**원인.** 대사 형식을 `이름: "대사"` 로만 규정했기 때문입니다. 이름이 없는 엑스트라·군중·방송의 말은 **갈 곳이 없어서** 가장 가까운 형식인 지문으로 흡수됩니다. 규칙을 어긴 게 아니라 규칙에 구멍이 있는 것이고, 모델은 구멍을 만나면 항상 가장 가까운 형식으로 메웁니다.

**대처.** 이름 대신 **역할**을 화자 자리에 쓰게 합니다.

```
말한 것은 전부 대사다. 이름 없는 인물·군중·방송의 말도 지문 안에 넣지 않는다
→화자 자리에 역할을 적는다. 보안팀원: "뒤로!" / 안내방송: "…"
```

형식이 유지되면서 인물 명부도 오염되지 않습니다. 이미지 규칙과도 자연스럽게 맞물립니다 — 슬러그가 없는 화자는 이미지 없이 대사만 내면 됩니다.

일반화하면 이렇습니다. **형식 규칙을 만들 때는 그 형식에 안 맞는 경우를 어디로 보낼지 같이 정하세요.** 안 정하면 모델이 알아서 어딘가에 밀어 넣습니다.

## 매 응답이 번호 선택지로 끝난다

```
1. 심가을의 요구에 응한다. (광역 제압을 시도한다)
2. 주하빈과 연계했던 방식을 제안한다. (더 안전하고 검증된 방법을 택한다)
3. 아직 불가능하다고 솔직하게 말한다. (S급의 명예보다 생존을 우선한다)
```

**원인.** 출력 계약이 "선택이 갈릴 때만 결정 지점"처럼 **허용**만 하고 있으면 사실상 허가로 읽힙니다. 상황을 극화하는 것보다 나열하는 쪽이 언제나 싸기 때문에, 몇 턴 안에 매 응답이 메뉴로 끝나기 시작합니다.

**더 나쁜 부분은 괄호입니다.** `(S급의 명예보다 생존을 우선한다)` 는 무엇을 고를 수 있는지에 더해 **그 선택이 무슨 뜻인지까지** 내레이터가 정해버립니다. 같은 대사를 전혀 다른 동기로 할 수 있다는 사실이 지워지므로, 형식과 무관하게 주도권 침해입니다.

**대처.** 금지만 적지 말고 **대안을 함께** 주세요. 목록을 뺀 자리에 무엇으로 맺을지 지정하지 않으면 장면이 흐지부지 끝납니다.

```
번호 선택지·보기 목록×. 열거도, 괄호로 의도를 풀어 쓴 보기도 만들지 않는다.
결정이 필요하면 장면으로 압력을 만들어 맺는다:
ⓒ의 질문 · 닫히는 시간 · 눈앞의 변화 중 하나로 끝내고 ⓤ의 답을 기다린다.
```

셋 다 "지금 답하라"는 압력은 그대로 주면서 답의 형태는 열어 둡니다. 출력 순서에서도 `결정 지점` 항목을 빼세요 — 순서에 남아 있으면 계속 채우려 듭니다.

비주얼노벨식 메뉴를 의도적으로 쓰는 작품이라면 선택지를 두되 **행동만 적고 동기는 플레이어 몫으로 남깁니다.**

### 목록을 없앴는데 산문으로 갈림길을 지목한다

```
상황은 당신의 대답을 기다려주지 않고 흘러가고 있었다.
대피할 것인가, 규정을 어기고 남을 것인가.
```

메뉴 금지의 **부작용**입니다. "결정이 필요하면 압력으로 맺어라"라고만 쓰면 모델이 그걸 **매 응답의 마감 형식**으로 받아들입니다. 번호만 사라지고 하는 일은 같습니다 — 내레이터가 선택지를 정리해 플레이어 앞에 세웁니다.

**대처.** 두 줄을 더 넣습니다.

```
매 응답을 결정 지점으로 만들지×→대부분은 상황이 한 걸음 나아가고 끝난다.
장면은 ⓤ가 답하지 않아도 흘러간다.
갈림길을 본문에서 지목×. 「A할 것인가 B할 것인가」로 맺지 않는다
→압력만 남기고 답의 형태는 열어 둔다.
```

**결정 지점은 드물어야 무게가 생깁니다.** 매 턴이 갈림길이면 어느 것도 갈림길이 아닙니다.

같은 이유로 `각 단계 사이에 ⓤ의 개입점을 남긴다` 같은 문장도 조심하세요. 의도는 주도권 보장인데 모델은 **단계마다 멈춰 서라는 지시**로 읽습니다.

## 상태창과 본문이 모순된다

상태창에는 이름이 찍혀 있는데 본문에서 NPC가 이름을 또 묻습니다.

**원인.** "필드가 다 찰 때까지 완료하지 않는다"는 규칙만 있고 **이미 받은 값 처리**가 없습니다.

**대처.** 둘 다 넣습니다.

- 필수 필드와 선택 필드를 나눕니다. 선택 필드가 비었다고 진행이 막히면 안 됩니다.
- **이미 받은 값은 다시 묻지 않는다**를 명시합니다.
- 아직 안 받은 값은 선언된 미지 토큰(`미상`)으로 둡니다. 계정 표시명이나 임의값으로 채우지 않고, 나중에 조용히 바꾸지도 않습니다.

## 의미 없는 이모지가 나온다

다른 작품 예시에서 가져온 기호가 그대로 남아 있는 경우입니다.

**원칙.** 상태창의 모든 이모지는 **안정적인 상태 ID**여야 합니다. 뜻이 없으면 빼거나 뜻을 부여합니다.

```
🟢 즉각적 위협 없음 / 🟡 전조·경계·시간 압박 / 🔴 전투·부상·즉각 대응 필요
😐중립 🙂호의 😄친밀 🥰애착 🫂신뢰 😳동요 🤨의심 😠적대
```

진입 조건도 함께 적습니다. "본문에 근거가 있을 때만 올리거나 내린다."

**다른 작품에서 복사한 기호는 반드시 재유도하세요.** 그 작품에서의 뜻이 내 작품에서도 성립하는지 확인하지 않으면, 뜻 없는 장식이 규칙인 척 남습니다.

## 압축 표기를 모델이 잘못 해석한다

`→`, `·`, `|` 같은 기호를 정의 없이 쓰면 모델이 문맥으로 추측합니다.

**대처.** `# 표기` 섹션을 **문서 맨 앞**에 둡니다. 정의는 첫 사용보다 앞에 있어야 합니다. 끝에 붙은 범례는 앞부분을 해석해주지 않습니다.

```bash
python3 check_symbols.py build/integrated-prompt-safe.md
```

이 스크립트가 정의 없이 쓰인 기호, 정의보다 먼저 쓰인 기호, 정의만 있고 안 쓰이는 기호를 잡습니다. 실제로 예제 빌드에서 **범례는 `|`를 정의하는데 본문은 `/`와 `｜`를 쓰는** 상태를 찾아냈습니다.

## 모델이 인물 이름을 지어낸다

키워드북에 항목이 있는데도 모델이 다른 이름을 씁니다.

**원인.** 항목 **제목은 주입되지 않습니다.** `# kb.ban-hosik — 반호식「不壊」`에서 제목은 등록 메타데이터일 뿐이고, 로드되는 것은 `## Entry text` 본문뿐입니다. 이명이 제목에만 있으면 모델에게는 존재하지 않는 이름입니다.

또는 **3슬롯 경합에서 밀린** 경우입니다.

**대처.**

- 모델이 말해야 하는 고유명사는 전부 본문 안에 넣습니다.
- `check_kb_slots.py`로 시뮬레이션해서 그 장면에서 밀리는지 확인합니다.
- 밀린다면, 그 항목의 핵심 정보가 통합 프롬프트에 한 줄 씨앗으로 있는지 봅니다. 없으면 넣거나 등록 순서를 바꿉니다.

## 프롬프트가 7,000자를 넘는다

**번역은 절대 해법이 아닙니다.** 한국어를 영어로 옮기면 글자수가 약 두 배가 됩니다. 상한이 토큰이 아니라 **글자수**라서 토큰 절약 직관이 반대로 작동합니다.

줄이는 순서:

1. 중복 산문 제거 — 같은 규칙이 두 섹션에 있는 경우
2. 현재 아크에 안 나오는 인물·세력의 씨앗 제거
3. 긴 목록(슬러그 명부 등)을 키워드북으로 이동
4. 키워드북 항목과 겹치는 설명 삭제
5. 산문 압축

3·4번은 **도달성을 확인하고** 하세요. 통합본에서 뺀 이름이 키워드북에서도 밀리면 모델이 지어냅니다.

그리고 7,000은 천장이지 목표가 아닙니다. 여백을 채우려고 로어를 넣지 마세요.

## 인물이 서로 구별되지 않는다

이미지에서 절반이 같은 사람으로 보입니다.

**원인.** 개별로 설계해서 그렇습니다. 하나씩 보면 다 그럴듯합니다.

**대처.** 명부 전체를 표로 늘어놓고 봅니다.

- 색을 지우고 실루엣만 남겨도 구분되는가
- 축(머리·체격·복장 실루엣·액세서리·자세)마다 값이 뭉쳐 있지 않은가
- 인물마다 **다른 누구도 갖지 않는 시각 특징 하나**가 있는가
- 이미지 베이스 프롬프트의 **앞 두세 태그**만 읽어도 서로 다른 인물임이 드러나는가

두 인물이 같은 축에서만 다르면 구분되지 않습니다. 머리 색만 다른 두 사람은 썸네일에서 같은 사람입니다.

## 인물 명부에 빈칸이 있다

성별처럼 당연해 보이는 칸이 몇 명에게 비어 있는 일이 실제로 생깁니다. 10명을 넘어가면 개별 검토로는 안 보입니다.

**대처.** 명부를 표로 뽑아 빈칸을 눈으로 확인합니다. 그리고 **구성 비율은 손으로 세지 말고 스크립트로 세세요.** 인상은 틀립니다.

## 확인할 수 없는 것

아래는 크랙 UI에서 직접 봐야 합니다. 추측해서 규칙을 만들지 마세요.

- 상태창 코드펜스 안 들여쓰기(`ㅤ` U+3164) 렌더링
- 이모지 렌더링
- 마크다운 외부 이미지(`![](url)`) 로딩 여부
- `activation_setting`의 실제 선택지 문자열

확인되지 않았다면 그렇게 표시하고, **그것이 안 되는 경우에도 플레이가 성립하는지** 확인하는 것이 맞습니다.
