# 이미지 자산

스토리챗은 외부 호스팅 이미지를 조합 주소로 부를 수 있습니다. 이 문서는 **그 이미지를 실제로 만드는 방법**입니다. 프롬프트에서 어떻게 부르는지는 [artifacts.md](artifacts.md)에 있습니다.

> 이미지는 항상 선택 사항입니다. **한 장도 없어도 텍스트만으로 플레이가 성립해야 합니다.** 이 조건을 못 지키면 자산 제작이 출시를 막습니다.

---

## 조합 주소 방식

에셋 목록을 프롬프트에 길게 나열하지 않고, 축의 조합으로 주소를 만듭니다.

```
{IMG}/인물/상황.png     →  {IMG}/ju-habin/combat.png
{IMG}/scene/장면.png    →  {IMG}/scene/hq-lobby.png
```

- `{IMG}`는 치환 자리표시자로 남깁니다. 실제 주소를 통합 프롬프트에 하드코딩하지 않습니다.
- **각 축의 값은 닫힌 목록으로 프롬프트에 명시합니다.** 모델이 슬러그를 창작하면 전부 깨진 링크가 됩니다.
- **부분 커버리지를 전제합니다.** "해당 조합 파일이 없으면 그 자리만 생략" 규칙을 반드시 넣습니다. 그래야 일부만 만들고도 안전하게 출시됩니다.

---

## 축을 먼저 닫습니다

축 조합은 곱셈입니다. 프롬프트를 쓰기 전에 값 목록을 확정하세요.

```
인물 15 × 상황 6  = 90장
장면 6 + 배경 6 + 위협 6 = 18장
                    합계 108장
```

상황 축은 6개 안팎에서 멈춥니다. 7번째 상황은 인물 수만큼 곱해져 들어옵니다.

예제(`examples/hunter/.assets/image-prompts.md`)가 쓰는 상황 6종: `normal` 평상 / `serious` 경계 / `combat` 전투 / `hurt` 부상 / `soft` 이완 / `guard` 적대.

---

## 프롬프트는 계층으로 조립합니다

한 장의 프롬프트를 통째로 쓰지 않습니다.

```
품질 프리픽스 + 그림체 프리셋 + 베이스(축1) + 모디파이어(축2) + 공통 서픽스
네거티브 = 공통 네거티브 + 종류별 추가
```

계층으로 나누는 이유는 **그림체를 바꿀 때 한 줄만 고치기 위해서**입니다. 통째로 쓰면 화풍 변경이 108장 전수 수정이 됩니다.

베이스에는 변하지 않는 것만 넣습니다. 현재 감정·부상·위치는 모디파이어의 몫입니다.

### 베이스의 앞부분이 식별 포인트여야 합니다

뒤쪽 태그는 가중치가 낮아 묻히고, 썸네일 크기에서는 미묘한 차이가 전부 사라집니다.

베이스 목록을 위에서 아래로 훑었을 때 **앞 두세 태그만 읽어도 서로 다른 인물임이 드러나야** 합니다. 안 드러나면 생성된 이미지도 서로 닮습니다. 인물 베이스를 다 쓴 뒤 명부 단위로 한 번 검토하세요.

---

## 모델 계열이 프롬프트 방언을 정합니다

체크포인트 **이름**이 아니라 **계열**이 문법을 정합니다. 이름만 보고 프리셋을 고르면 안 됩니다.

| 계열 | 품질 프리픽스 | 본문 |
|---|---|---|
| Illustrious / NoobAI | `masterpiece, best quality, amazing quality` | 단부루 태그 |
| Pony | `score_9, score_8_up, score_7_up` **필수** | 단부루 태그 |
| SDXL / Animagine | 가벼운 품질어 | 태그·자연어 혼용 |
| Flux | 없음 | 완전한 자연어 문장 |

계열을 잘못 적용하면 **오류 없이 조용히 품질만 떨어집니다.** 발견이 늦습니다. 그래서 품질 프리픽스는 설정 파일의 교체 가능한 프리셋으로 둡니다.

같은 이름의 모델이 EPS 판과 V-Pred 판으로 나뉘어 배포되기도 합니다. 실행 환경 요구가 다르므로 어느 쪽인지 확인하고 기록하세요.

## 배치 생성 도구

```bash
cd tools/imagegen

python batch.py --list-models     # 설치된 체크포인트 정확한 이름
python batch.py --check           # 체크포인트·로라·샘플러 존재 확인
python batch.py --dry-run         # 생성 없이 프롬프트만 출력
python batch.py                   # 전부 생성

python batch.py --only ju-habin --situations normal combat
python batch.py --scenes-only
python batch.py --backend comfy   # 백엔드 전환
```

출력은 `out/<인물>/<상황>.png` 구조로 떨어집니다. **프롬프트의 URL 패턴과 같은 축**이라 업로드가 단순 복사가 됩니다.

설정은 `prompts.json`에 있습니다. 체크포인트·로라·스텝·CFG·샘플러·프리셋 전부 여기서 바꿉니다.

### 백엔드 차이

| | A1111 / Forge | ComfyUI |
|---|---|---|
| 로라 전달 | 프롬프트에 `<lora:이름:가중치>` | `LoraLoader` 노드 체인 |
| 체크포인트 | `override_settings` | 로더 노드 |
| 기본 포트 | 7860 | 8188 |

A1111은 반드시 `--api` 옵션으로 띄워야 합니다 (`./webui.sh --api`).

### GPU 없이 검증하기

```bash
python mock_a1111.py &     # 7860
python batch.py --check
```

목 서버는 **성공만 흉내내면 쓸모가 없습니다.** 실제 서버처럼 없는 모델·로라·샘플러에 404를 돌려줘야 합니다. 이 조건을 지킨 목이 실제로 잡아낸 결함이 둘 있습니다.

- `--dry-run`이 특정 조합에서 실제로 파일을 생성했습니다. 분기 순서 문제였고 목 없이는 발견되지 않았습니다.
- `--check`는 통과하는데 생성이 404였습니다. WebUI가 체크포인트를 `파일명.safetensors [해시]` 형태 제목으로 관리하는데, 확인 단계와 생성 단계가 서로 다른 문자열을 비교하고 있었습니다.

목으로 잡히지 않는 것은 실제 하드웨어·드라이버·수치 정밀도입니다. 그건 검증했다고 하지 않고 인계 사항으로 남깁니다.

## 배포

이미지를 폴더에 정리해두면 `deploy.py`가 전용 깃헙 저장소로 올리고 jsDelivr CDN 주소를 만들어 줍니다.

```bash
python deploy.py --check                          # 검사만
python deploy.py --repo 계정/이미지저장소 --create  # 저장소 만들고 배포
python deploy.py --verify                         # 주소가 실제로 열리는지 확인
```

폴더 구조는 `batch.py` 출력과 같습니다. 직접 그린 그림을 올릴 때도 이 구조만 지키면 됩니다.

```
out/<인물>/<상황>.png   out/scene/<장면>.png   out/bg/<배경>.png   out/mob/<위협>.png
```

마지막에 통합 프롬프트에 넣을 값을 출력합니다.

```
{IMG} = https://cdn.jsdelivr.net/gh/계정/이미지저장소@main
```

### 올리기 전에 축 계약을 검사합니다

**이게 배포 도구의 핵심입니다.** 프롬프트는 축의 닫힌 목록을 싣고 모델은 그 안에서만 슬러그를 조합합니다. 파일 이름이 한 글자만 달라도 그 조합은 영원히 깨진 링크이고, 플레이 중에는 **그냥 이미지가 안 뜨는 것으로만 보여서** 원인을 찾기가 매우 어렵습니다. 파일을 올리는 순간이 이 계약을 기계로 검사할 수 있는 마지막 지점입니다.

| 상황 | 판정 |
|---|---|
| 목록에 없는 슬러그의 파일 | **중단** — 오타이거나 축 목록이 낡음 |
| 목록에 있는데 파일이 없음 | **통과** — 부분 커버리지는 정상 |
| 과도하게 큰 파일 | 경고 또는 중단 |

없는 파일을 실패로 치면 안 됩니다. 프롬프트가 이미 "조합이 없으면 그 자리만 생략"을 규정하므로 **부분 배포가 정상 상태**입니다. 반대로 목록에 없는 파일은 반드시 막습니다 — 프롬프트와 자산이 갈라졌다는 신호니까요.

### 캐시

jsDelivr는 브랜치 주소를 최대 12시간 캐시합니다. 이미지를 교체하고 즉시 반영하려면 `--tag v2`로 새 태그를 쓰세요. 태그 주소는 불변이라 지연이 없습니다.

**jsDelivr는 공개 저장소만 서빙합니다.** 비공개로 두시려면 다른 호스팅이 필요합니다.

### 다른 호스팅을 쓸 때

정적 파일이면 무엇이든 되지만 셋을 확인하세요.

- **핫링크 허용 여부** — 이미지 호스트 상당수가 외부 직접 참조를 막습니다
- **주소가 축 구조를 표현할 수 있는가** — 업로드마다 임의 ID를 주는 호스트는 조합 주소 방식과 안 맞습니다. 그러면 에셋 목록을 프롬프트에 나열해야 하고, 조합 주소로 아꼈던 글자 예산이 사라집니다
- **캐시 수명과 무효화 수단**

## 이미지가 안 나올 때

프롬프트부터 의심하면 시간을 크게 버립니다. **먼저 범위를 가르세요.**

| 증상 | 결론 |
|---|---|
| 모든 모델에서 실패 | **환경 문제.** 프롬프트·모델 무관 |
| 특정 모델만 실패 | 모델 계열·설정 불일치 |
| 특정 조합만 실패 | 자산·슬러그 문제 |

그다음 **최소 재현**으로 좁힙니다. 확장 기능·로라·리파이너·업스케일을 전부 끄고 기본 해상도로 한 장. 여기서 정상이면 하나씩 되돌리며 범인을 찾습니다.

증상별 1순위 원인:

- **완전한 회색·검은 단색** → VAE의 fp16 NaN. `--no-half-vae`
- **컬러 노이즈로 발산** → 디노이징 발산. V-Pred 모델을 EPS로 돌렸거나, 리파이너가 켜져 있거나, 계열 불일치
- **형체가 뿌옇게 녹음** → CFG 과다 또는 해상도 부족 (SDXL은 1024 기준)
- **후반 스텝에서 무너짐** → 리파이너 `Switch at` 지점 확인. 스텝 25에 0.8이면 정확히 20스텝

관리가 멈춘 실행기는 신형 하드웨어에서 실패합니다. 최신 애플 실리콘에서 A1111이 낡은 torch를 고정해 fp16이 NaN을 뱉은 사례가 있습니다. 증상은 **모든 체크포인트에서 노이즈**였고 모델·프롬프트와 무관했습니다.

## 로라 학습용 데이터셋

조합 생성만으로는 동일 인물성이 완전히 유지되지 않습니다. 정확한 재현이 필요하면 로라 학습을 전제합니다.

```bash
python batch.py --dataset --only ju-habin --count 24
```

생성 이미지로 학습할 때:

- **변형 축을 넓게 벌립니다.** 구도·조명·표정·의상. 서로 닮은 12장은 과적합을 보장합니다.
- **에포크마다 저장합니다.** 최고 성능 체크포인트는 마지막 에포크가 아닙니다. 대개 중간이고 그 뒤로는 내려갑니다.
- 같은 시드·같은 프롬프트로 에포크별 비교 격자를 만들어 **눈으로 고릅니다.** 하이퍼파라미터 조정보다 빠릅니다.

샘플이 좋아지다 무너지면 대개 학습률이 높거나 총 스텝이 과다한 것입니다. 캐릭터 로라는 1,500~2,500 스텝이 적정선이고, `network_dim`은 8~32면 충분합니다.
