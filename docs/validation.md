# 검증

전부 파이썬 표준 라이브러리만 씁니다. 설치할 것이 없습니다.

```bash
./scripts/validate.sh examples/hunter     # 전부 한 번에
```

---

## 스크립트별 사용법

### `check_project_layout.py`

원본 2개 + 산출물 5개 구조를 강제합니다. 중간 계층 파일이 생기면 잡습니다.

```bash
python3 check_project_layout.py <프로젝트>
python3 check_project_layout.py <프로젝트> --allow-unbuilt   # 컴파일 전
```

점(`.`)으로 시작하는 디렉터리는 무시하므로, 작업용 자산은 `.assets/`에 두면 됩니다.

### `check_build.py`

산출물 다섯 개가 정확히 존재하는지, 각각 상한을 지키는지 봅니다. 파일별로 다른 상한을 알아서 적용합니다.

```bash
python3 check_build.py <프로젝트>/build
```

### `check_prompt_length.py`

개별 파일 글자수를 코드포인트와 UTF-16 양쪽으로 셉니다.

```bash
python3 check_prompt_length.py build/integrated-prompt-safe.md
```

> 키워드북 파일에 이걸 돌리면 7,000자 기준으로 재서 실패합니다. 키워드북은 등록 시트라 프롬프트 상한이 적용되지 않습니다. `check_build.py` 나 `crack-emu lint` 를 쓰세요.

### 키워드북: `crack-emu lint`

항목 형식, 400자(권장 360자), 키워드 1~5개, 중복을 봅니다. 여기에 더해 정적 검사만으로 잡히는 슬롯 결함도 함께 잡습니다.

```bash
crack-emu --project build lint
```

| 규칙 | 뜻 |
|---|---|
| `entry_too_long` · `entry_near_limit` | 400자 상한, 360자 권장선 |
| `entry_keyword_overflow` | 키워드 5개 상한 |
| `keyword_collision` | 같은 키워드가 두 항목에 등록됨 |
| `keyword_substring_hazard` | 키워드가 다른 낱말에 묻혀 오발동 — `라임`이 `슬라임`에 걸리는 종류. 조사가 붙은 정상 매칭은 걸러냅니다 |
| `priority_module_low` | 19+·키스 등 우선 모듈이 3슬롯 밖에 등록됨 |
| `always_on_trigger` | 상태창 고정 항목명을 트리거로 써서 슬롯 1개를 영구 점유 |
| `adult_code_in_main_prompt` | 성인 A코드가 메인 프롬프트에 노출됨 |
| `shortcut_name_slash` | 단축어 이름 앞 `/` — 크랙 UI가 자동으로 붙이므로 `//` 가 됨 |

### `check_symbols.py`

**정의 없이 쓰인 기호를 잡습니다.** 압축 표기를 쓰는 프롬프트에서 가장 조용히 새는 결함입니다.

```bash
python3 check_symbols.py build/integrated-prompt-*.md
python3 check_symbols.py build/*.md --legend "# 표기"    # 범례 제목이 다를 때
python3 check_symbols.py build/*.md --strict             # 장식 글리프도 필수로
```

기호가 "정의됨"으로 인정되는 경우:

| 형태 | 예 |
|---|---|
| 범례 섹션 안 | `# 표기` 아래 |
| 등호 정의 | `⌛=응답 번호` |
| 닫힌 집합 선언 | `날씨=☀️🌤️☁️🌧️❄️ 중 1개` |
| 인라인 코드로 언급 | `` `━` 구분선 `` |
| 이모지 척도 목록 | `😐중립 🙂호의 😄친밀` (한 줄에 3개 이상) |

**한글이 붙어 있다는 것만으로는 정의로 안 칩니다.** 조사가 붙은 기호(`ⓝ는`)와 주석(`😐중립`)이 구별되지 않아 진짜 결함을 덮어버리기 때문입니다. 이건 실제로 이 스크립트의 첫 판이 부정 대조에서 놓쳤던 지점입니다.

### 3슬롯: `crack-emu replay` + `report`

**가상 장면 목록 시뮬레이션은 폐지했습니다.** 실제로 턴을 돌려서 측정합니다. 항목을 하나씩 검토해서는 절대 못 찾는 결함이고, 지어낸 장면 목록으로는 진짜 대화에서 무엇이 트리거되는지 알 수 없습니다.

```bash
crack-emu --project build replay qa1 scenarios/onboarding.txt
crack-emu --project build report
```

시나리오 파일 형식 — 한 줄에 유저 입력 하나, `#`은 주석:

```
라임 대리님, 안녕하세요. 신입 이정민입니다.
사랑의 묘약 기획서를 좀 볼 수 있을까요?
/상태창
```

`report` 가 내놓는 것:

| 규칙 | 뜻 |
|---|---|
| `slot_overflow` | 매칭이 3슬롯을 넘겨 항목이 드롭된 턴. 어떤 항목이 밀렸는지까지 |
| `entry_never_fired` | N턴 동안 한 번도 안 걸린 항목 — 키워드가 실제 대화 어휘와 어긋남 |
| `entry_always_fired` | 매 턴 걸리는 항목 — 메인 프롬프트로 옮길 후보 |
| `high_match_entry_registered_high` | 자주 걸리면서 목록 상단에 등록 — 남의 슬롯을 계속 뺏음 |

턴마다 발동 기록이 `<store>/../logs/<세션>.jsonl` 에 남습니다. 어떤 키워드가 **직전 턴에서** 걸렸는지 **이번 입력에서** 걸렸는지까지 들어 있습니다.

출력에서 등록 순서대로 앞 3개가 `loaded`, 나머지가 `DROPPED`로 나옵니다.

```
FAIL 길드장 회합: 4/3 — loaded [kb.baek-haram, kb.ha-mujin, kb.yun-seola] DROPPED [kb.ban-hosik]
```

**밀린 항목이 있다고 곧바로 결함은 아닙니다.** 밀려도 안전한지가 관건입니다.

- 밀린 항목의 핵심 정보가 통합 프롬프트에 한 줄 씨앗으로 있으면 → 안전
- 통합 프롬프트에 이름조차 없으면 → **모델이 지어냅니다.** 이게 진짜 결함입니다

대응은 셋 중 하나입니다. 등록 순서를 바꿔 손실을 서로 다른 진영·주제로 흩뿌리거나, 키워드를 좁히거나, 항목을 합칩니다.

## 스크립트가 못 잡는 것

문서로만 확인해야 하는 항목이 훨씬 많습니다. 스킬의 `references/validation.md`에 전체 체크리스트가 있습니다. 특히 이런 것들:

- 플레이어 주도권 침해 (모델이 플레이어의 대사·동의를 대신 씀)
- 지식 범위 위반 (인물이 알 수 없는 것을 앎)
- 상태창과 본문의 모순
- 관계 단계가 행동을 실제로 바꾸는지
- 실패·거절·지연이 처리되는지

## 음성 대조

> **통과했다고 보고하는 검사기를 믿기 전에, 실패해야 마땅한 입력을 먹여보고 실제로 실패하는지 확인하세요.**

모든 것을 조용히 통과시키는 검사기는 없는 것보다 나쁩니다. 탐색을 끝내버리기 때문입니다.

기호 검사기의 음성 대조 예:

```bash
sed 's/^# 세션 목표/# 세션 목표\nⓝ ⇒ 🦊/' build/integrated-prompt-safe.md > /tmp/negative.md
python3 check_symbols.py /tmp/negative.md    # 반드시 실패해야 정상
```

이 저장소의 CI가 푸시마다 이걸 돌립니다. 검사기가 주입된 미정의 기호를 놓치면 빌드가 깨집니다.

같은 원칙이 직접 짜는 일회용 검증 스크립트에도 적용됩니다. 실제 사례 하나 — 부분 문자열을 찾으려던 검사가 튜플 멤버십 검사로 잘못 쓰여서, 불일치 3건을 숨긴 채 "이상 없음"을 출력했습니다. 음성 대조 한 번이면 바로 드러났을 결함입니다.

## 숫자는 손으로 세지 않습니다

인물 구성비, 항목 수, 글자수 — 전부 스크립트로 세고 그 숫자를 보고합니다. 인상으로 센 결과는 틀립니다. 이 저장소를 만드는 과정에서도 성비를 손으로 세다 틀린 적이 있습니다.

---

## 확인되지 않은 것은 확인되지 않았다고 적습니다

크랙 UI에서 직접 보지 않고는 알 수 없는 것들이 있습니다.

- 상태창 코드펜스 안 들여쓰기(`ㅤ` U+3164) 렌더링
- 이모지 렌더링
- 마크다운 외부 이미지 로딩 여부
- `activation_setting`의 실제 선택지 문자열

플랫폼 동작을 추측해서 규칙을 만들지 마세요. 인계 사항으로 남기고, 그것이 안 되는 경우에도 플레이가 성립하는지 확인하는 것이 맞습니다.
