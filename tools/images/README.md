# 이미지 자산 정리·배포

이미지를 **만드는 도구는 없습니다.** 어떤 그림체로 어떤 도구를 써서 그릴지는 제작자가 정할 일이고, 생성기는 몇 달 단위로 바뀝니다. 여기 있는 것은 그것과 무관하게 필요한 두 가지입니다 — **어디에 무엇을 넣어야 하는지 알려주는 것**과 **넣은 것을 검사해서 올리는 것**.

프롬프트 자체는 `<작품>/build/assets/image-prompts.md` 와 `prompts.json` 에 있습니다. 컴파일이 생성하며 외형은 `characters.md` 에서 파생됩니다. 그 프롬프트를 어느 도구에 붙여넣든 상관없습니다.

```bash
export CRACK_PROMPTS=<작품>/build/assets/prompts.json
```

## 1. 폴더를 깐다

```bash
python3 deploy.py --scaffold --root ~/내이미지폴더
```

축 목록대로 폴더를 만들고, 폴더마다 **그 안에 들어갈 정확한 파일 이름**과 뜻·권장 해상도를 적어둡니다. 전체 배치표도 한 장 나옵니다.

```
~/내이미지폴더/
  _배치표.md          전체 자리 목록 + 채움 상태
  ju-habin/
    README.md         normal.png 평상 (832×1216) …
  scene/  bg/  mob/
```

폴더 이름을 손으로 타이핑하면 반드시 오타가 나고, 오타는 **오류 없이 조용히 깨진 링크**가 됩니다. 축이 닫히는 순간 배치는 이미 확정돼 있으므로 손으로 만들 이유가 없습니다.

여러 번 돌려도 안전합니다. 기존 파일은 건드리지 않고 배치표의 채움 상태만 갱신하므로 **진행 현황판**이 됩니다.

## 2. 그림을 넣는다

`_배치표.md` 와 각 폴더의 `README.md` 가 작업 지시서입니다. 직접 그리든, 생성기를 쓰든, 외주를 주든 상관없습니다.

**전부 채울 필요는 없습니다.** 프롬프트가 "조합이 없으면 그 자리만 생략"을 규정하므로 부분 커버리지가 정상 상태입니다.

## 3. 검사한다

```bash
python3 deploy.py --check --root ~/내이미지폴더
```

```
## 커버리지
  인물        12/90  ← 78장 없음      통과
  scene      6/6

## 목록에 없는 파일 1개 — 슬러그 오타이거나 축 목록이 낡았다
  X scene/hq-loby.png                  중단
```

판정이 비대칭인 이유가 있습니다. **없는 파일은 정상**이고, **목록에 없는 파일은 프롬프트와 자산이 갈라졌다는 신호**입니다.

## 4. 올린다

```bash
python3 deploy.py --root ~/내이미지폴더 --repo 계정/이미지저장소 --create
python3 deploy.py --root ~/내이미지폴더 --verify     # 주소가 실제로 열리는지
```

전용 깃헙 저장소에 올리고 jsDelivr CDN 주소를 만들어, 마지막에 통합 프롬프트에 넣을 값을 출력합니다.

```
{IMG} = https://cdn.jsdelivr.net/gh/계정/이미지저장소@main
```

- **jsDelivr는 공개 저장소만** 서빙합니다.
- 브랜치 주소는 최대 12시간 캐시됩니다. 그림을 갈아끼우고 즉시 반영하려면 `--tag v2` 로 새 태그를 쓰세요. 태그 주소는 불변이라 지연이 없습니다.

## 프롬프트를 쓸 때

`prompts.json` 의 `quality_presets` 는 **모델 계열별 관용 프리픽스**입니다. 체크포인트 이름이 아니라 계열이 문법을 정하므로, 쓰는 도구에 맞는 것을 골라 앞에 붙이세요.

| 계열 | 프리픽스 |
|---|---|
| Illustrious / NoobAI | `masterpiece, best quality, amazing quality` |
| Pony | `score_9, score_8_up, score_7_up` (필수) |
| SDXL / Animagine | 가벼운 품질어 |
| Flux | 없음 — 자연어 문장 |

계열을 잘못 적용하면 오류 없이 품질만 떨어져서 발견이 늦습니다.

**인물 베이스의 앞 두세 태그는 그 인물의 식별 포인트입니다.** 뒤쪽 태그는 가중치가 낮아 썸네일에서 묻히므로 순서를 바꾸지 마세요.
