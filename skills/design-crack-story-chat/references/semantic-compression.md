## 1. 압축 철학: 한도에 갇히지 않는 정보 밀도 오버 기획

> ⚡ **골든 룰**: **처음부터 글자 수 제한(7,000자 / 1,000자 / 400자)을 의식하고 쓰면, 뇌가 위축되어 앙상하고 뻔한 빈 껍데기 규칙만 남는다. 모든 산출물은 일단 한도를 완전히 초과(130~150%)하도록 모든 정보와 디테일을 쏟아부은 뒤, 압축해서 우겨넣고, 더 넣고, 다시 우겨넣는 과정을 거쳐야 극한의 정보 밀도(Maximum Information Entropy)가 완성된다.**

* **프롬프트는 문학적 미문이 아니다**: 문장미, 장황한 설명, 친절한 연결사는 시스템 프롬프트에서 불필요한 토큰 낭비일 뿐입니다.
* **압축은 단순 삭제가 아니다**: `긴 서술형 문단 ➡️ 표준 Syntax 구조(표·기호) + 고유 편차`로 치환하여 모델이 원본 의미를 100% 온전히 복원하게 만드는 공학입니다.
* **여유 공간이 생기면 끝이 아니다**: 1차 압축으로 공간이 남으면 절대 방치하지 말고, 즉시 **새로운 관계성·엣지 케이스·티키타카·감각 디테일**을 추가로 더 밀어 넣고 다시 쥐어짜야 합니다.

## 2. 4단계 반복 압축 루프 (The Squeeze-Overload-Squeeze Loop)

메인 프롬프트, 시작 프롬프트, 키워드북 항목, 단축어, 프롤로그 등 **모든 산출물**은 다음 4단계를 반복 순환하며 빌드됩니다:

```
┌────────────────────────────────────────────────────────────────────────┐
│  Step 1. 정보 밀도 오버 기획 (Over-Spec Design)                          │
│  - 글자 수 상한선을 완전히 무시하고 130~150% 분량으로 풍부하게 작성       │
│  - 상황 인과, 인물 성격, 수치 기준, 대사 톤, 신체 감각, 제약을 총망라      │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│  Step 2. 1차 압축 우겨넣기 (First Squeeze & Packing)                     │
│  - 문장·조사·중복 주어(플레이어는, NPC는) 전면 제거                      │
│  - 전역 공유 기호(ⓤ, ⓒ, →, ·, /, ｜, ×) 및 표(Table)로 문법 승격        │
│  - 1차 목표 한도 안쪽으로 우겨넣기 성공 (여유 마진 확보)                   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│  Step 3. 추가 정보 밀어 넣기 (Inject More Information - Second Overload) │
│  - ★ 남은 공간을 방치하지 않고, 추가 디테일을 더 우겨넣어 다시 한도 초과!  │
│  - NPC간 상호작용 티키타카, 엣지 케이스 방어, 세부 물가/경제 수치 주입     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│  Step 4. 2차 극한 재압축 (Second Extreme Squeeze - Final Polish)        │
│  - 다시 초과된 내용을 치환표, 인라인 약어, 고밀도 전보체로 재압축         │
│  - 최종 한도의 95~98% 수준까지 꽉 채워 정보 밀도 극대화 완료!             │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. 모든 산출물의 전역 기호 체계 공유 (Global Shared Syntax)

크랙 스토리챗에서 **메인 프롬프트, 시작 프롬프트, 키워드북, 단축어, 프롤로그는 모두 하나의 동일한 런타임 생태계**에서 동작합니다. 따라서 메인 프롬프트 `# 표기`에서 선언한 기호 체계를 모든 산출물이 **재정의나 설명 없이 100% 공유**합니다.

```
                  ┌─────────────────────────────────────┐
                  │   메인 프롬프트 (# 표기 기호 정의)    │
                  │   ⓤ, ⓒ, →, ·, /, ｜, ━, ⌛, 💬, ×  │
                  └──────────────────┬──────────────────┘
                                     │
           ┌─────────────────────────┼─────────────────────────┐
           ▼                         ▼                         ▼
┌─────────────────────┐   ┌─────────────────────┐   ┌─────────────────────┐
│    시작 프롬프트     │   │     키워드북        │   │       단축어        │
│  T1 앵커링 & HUD    │   │  치환표·수치표·페어 │   │  장부·사칭교정 포맷  │
│  동일 기호 즉시 적용 │   │  동일 기호 즉시 적용 │   │  동일 기호 즉시 적용 │
└─────────────────────┘   └─────────────────────┘   └─────────────────────┘
```

### 전역 공유 기호 명세표
| 기호 | 원래 표현 | 모든 산출물 공유 활용 예시 |
|:---:|---|---|
| `ⓤ` | 플레이어, 유저, 주인공, 점주 | 메인: `ⓤ 자율성 6중 잠금` / 시작: `ⓤ 첫 행동 유도` / 키워드북: `ⓤ 동의 전 유도만` |
| `ⓒ` | NPC, 상대 인물, 손님, 단골 | 메인: `ⓒ 선제적 개입 장려` / 키워드북: `현장 ⓒ 둘 이상 모이면 시비·티키타카` |
| `→` | ~하면 ~한다, ~이므로 ~로 전환 | 메인: `IF(조건)→결과` / 키워드북: `날개·후광→큰 등산가방·조명 역광`, `충격→확인→침묵` |
| `·` | ~함과 동시에, 그리고, 와/과 | 메인: `대사·행동·생각 대리서술 금지` / 키워드북: `대사·접촉·호흡에 연결` |
| `/` | 또는, 대안, 각각, 슬롯 열거 | 메인: `남/여`, `S코드 열거` / 키워드북: `a01정상위/a02기승위/a03후배위...` |
| `｜` | 구분선, 카테고리, 슬롯 | 메인: `▶인물:[성별｜직책｜나이...]` / 상태창: `[점장]: ♂｜27세｜개업1일` |
| `×` | 절대 하지 않는다, 금지, 없음 | 메인: `대리서술×`, `재인용×` / 키워드북: `남성·미보유×`, `초자연적 돈 해결×` |
| `↑ / ↓` | 상승한다, 하락한다 | 상태창: `호감도↑` / 키워드북: `의심 수치↑`, `체류 시간↓` |
| `⌛` | 턴/응답 번호 | 시작: `[⌛1]` / 메인: `[⌛n]` / 키워드북: 턴 경과 연동 |

## 5. 실전 압축 4대 테크닉 (치환표·수치표·파이프슬롯·대조문)

### 테크닉 1: 치환표(Table) 압축
* **원리**: 구구절절한 서술형 조건문을 `대상A→치환A, 대상B→치환B` 형태의 테이블로 묶습니다.
* **예시**:
  ```text
  치환표: 날개·후광→큰 등산가방·조명 역광, 뿔→특이한 머리띠, 꼬리→벨트끈, 여우귀→헤어밴드, 세로동공→컬러렌즈, 반투명 발끝→바닥 반사광.
  ```

### 테크닉 2: 수치 기준표(Cost & Damage) 압축
* **원리**: 경제 및 손해 기준을 서술하지 않고, 수치와 결과를 직결합니다.
* **예시**:
  ```text
  복구비용: 워크인 정지 200만, 쇼케이스 파손 80만, 매대 완파 30만. 일일 매출 40만. 사고 1건=며칠치 순익 증발.
  ```

### 테크닉 3: 1인 1줄 10대 슬롯 파이프(｜) 인물 압축
* **원리**: 인물 소개를 줄글로 풀지 않고, 10대 슬롯을 파이프(`｜`)로 묶어 1인 1줄로 패킹합니다.
* **규격**:
  ```text
  ▶[번호 이름]:[성별]｜[소속/직책]｜[나이/외견]｜[복장/소지품]｜[MBTI·에니어]｜[성격키워드]｜[능력/제약]｜[외형]｜[말투/특징]
  ```

### 테크닉 4: 금지선과 예외의 1문장 대조 (Prohibition + Allowance)
* **원리**: 금지 문단과 허용 문단을 나누지 않고 1줄로 통합 대조합니다.
* **예시**:
  ```text
  -금지선: 서술자가 ⓤ를 비하·비꼼·평가·논평·훈계하지않음. 서사내 불이익·패배·거절·갈등은 금지대상 아님
  -결정권: 자발적 사건의 최종 결정은 ⓤ 권리. 단, ⓒ의 선제적 개입(질문, 제안, 기습, 흥정)은 적극 장려
  ```

## 6. 실전 반복 압축 시연 (Before ➡️ Squeeze ➡️ Add ➡️ Final)

실제 `convenience/build`의 키워드북 모듈이 완성된 4단계 과정입니다:

### [Step 1] 정보 밀도 오버 기획 (530자 — 400자 한도 초과)
> 이 세계관에는 인지저해라는 현상이 있어서 일반 인간들은 천사나 악마 같은 초자연적 존재의 외형을 목격하더라도 일상적인 상식에 맞춰 왜곡해서 기억합니다. 예를 들어 날개나 후광을 보면 큰 등산가방이나 조명 역광으로 착각하고, 뿔은 특이한 머리띠로, 꼬리는 길게 늘어뜨린 벨트 끈으로, 여우귀는 헤어밴드로, 세로동공은 컬러렌즈로 봅니다. 반투명한 발끝은 바닥 반사광으로 치환됩니다. 초자연적 존재들은 자신의 외형을 굳이 숨기지 않으며, 일반인들의 상식이 깨지는 것은 비행이나 마법, 괴력으로 기물을 파괴하는 등의 물리적 사건이 터졌을 때뿐입니다. 만약 사건이 발생하면 치환이 무너지고 관리 부서가 개입하여 은폐 수습에 들어갑니다. 일반인 관찰자는 이상 현상이 반복될수록 의심이 깊어지고 질문이 길어집니다. 플레이어가 실체를 알고 있다는 사실을 눈치채면 단골들은 신기해하거나 약점을 잡힌 것처럼 경계하게 됩니다.

### [Step 2] 1차 압축 우겨넣기 (252자 — 여유 마진 148자 발생!)
> 치환표: 날개·후광→등산가방·역광, 뿔→머리띠, 꼬리→벨트끈, 여우귀→헤어밴드, 세로동공→렌즈. 인간은 초자연 외형을 상식에 맞춰 왜곡 치환한다. 존재는 외형을 숨기지 않고, 깨지는 것은 외형이 아닌 사건(비행·파괴)이다. 사건 시 치환이 붕괴되어 은폐 수습이 개입한다. ⓤ가 실체를 아는 것을 눈치채면 단골들은 경계한다.

### [Step 3] 추가 정보 밀어 넣기 (다시 440자로 초과!)
> 치환표: 날개·후광→큰 등산가방·조명 역광, 뿔→특이한 머리띠, 꼬리→길게 늘어뜨린 벨트끈, 여우귀→헤어밴드, 세로동공→컬러렌즈, 반투명 발끝→바닥 반사광.
> 인간 대중은 초자연적 외형을 목격해도 일상 상식에 맞추어 자동 왜곡·치환해 기억한다. 초자연 존재는 외형을 숨기지 않으며, 깨지는 것은 외형이 아닌 사건(비행·마법·괴력 파괴)이다.
> 사건 발생 시 치환이 붕괴되어 각 조직의 은폐 수습이 개입한다. **[추가 주입] 한지수는 아직 필터가 두터워 억지 납득하나 이상 현상이 반복될수록 치환이 지연되고 점장에게 질문이 길어진다. 점장이 실체를 본다는 것을 알아챈 단골들은 신기해하거나 약점을 잡힌 듯 경계하며 태도를 바꾼다.**
