# 전역 의미 압축 및 반복 압축 루프 (Global Semantic Compression & Iterative Squeeze Loop)

플랫폼 글자 수 상한을 지키면서 의미를 보존하는 압축 방법을 정의합니다.

---

## 공유 지식으로 복원하고 차이만 쓰기

기본 원칙은 **공유 지식 앵커 + 작품 고유 편차 + 필요한 실행 조건**이다. 설명을 기호로 바꾸기 전에 모델이 이미 아는 내용을 다시 가르치고 있는지 확인한다.

| 대상 | 짧게 호출할 지식 | 실제로 더 적을 것 |
|---|---|---|
| 성격 | MBTI·에니어그램·알려진 성격 원형 | 그 유형과 다른 가치·관계·비밀·개별 경험 |
| 말투 | 하십시오체·해요체·해체·하오체·데드팬·반어 | 특정 상대에게만 바뀌는 호칭 등 고유 편차 |
| 문체 | 작가·작품·장르·서술 기법 | 맡길 특성·시점·필요한 보정;본문을 앵커 작품의 정사로 만들지 않음 |
| 세계 | 무협·스페이스 오페라·궁정극 등 장르 관습 | 자체 등급·세력·특수 법칙·보통 관습과 다른 조건 |
| 규칙 | 이해 가능한 단문·정의된 연산자 | 주체·발동·허용/금지 범위·예외 |

`하십시오체` 뒤에 격식 존댓말의 정의를 반복하거나, `ISTJ·6w5` 뒤에 일반 특성을 다시 나열하지 않는다. MBTI는 생성 단서이며 특정 행동을 반드시 예측하는 공식은 아니다. 알려진 앵커로 충분하면 멈추고, 해석이 갈리거나 실사용에서 어긋난 부분만 짧게 보정한다. 낯선 고유명사·작품 고유 정사는 모델 지식으로 대체하지 않는다.

표는 **열 이름·기호 의미 한 번 → 행에는 값만**. 자주 쓰는 개념은 `戀·慾`, `高·中·低`처럼 정의 후 압축한다. 기호를 늘려 독해 비용이 더 커지면 익숙한 단어를 유지한다. 상시 공통 엔진은 한 번만 쓰고, 각 캐릭터에 같은 심리 생성 절차를 반복하지 않는다.

설계의 깊이≠상시 프롬프트 분량. 두 원본에는 고유 설정을 보존하고, 메인은 압축 명부·핵심 불변식, 키워드북은 상황별 상세를 맡는다. 키워드북이 없어도 현재 장면의 기본 연기가 유지되어야 하지만, 그 이유로 전체 상세 시트를 메인에 복제하지 않는다.

## 1. 압축 목표

플랫폼 상한 안에서 행위자·조건·결과·예외·플레이어 결정권이 복원되어야 한다. 분량이나 약어 밀도 자체가 품질은 아니다. 숨은 규칙은 간결하게, 플레이어가 읽는 프롤로그·설명·대사는 자연스럽게 쓴다.

## 2. 필요한 만큼 압축하고 멈추기

1. 필수 세계 조건·인물 차이·실행 규칙을 먼저 쓴다. 초고가 길어도 되지만 일부러 한도를 넘길 의무는 없다.
2. 이미 상시 들어가는 사실·규칙의 사본을 제거한다. 관련 조건과 예외는 같은 문장이나 블록에 둔다.
3. 불필요한 설명을 줄이고 표·짧은 한국어·정의된 기호를 사용한다. 주체나 적용 범위가 흐려지면 풀어 쓴다.
4. 실제 글자 수와 의미 복원성을 검사한다. 빠진 필수 정보가 있을 때만 보충하고 다시 측정한다. 공간을 채우기 위한 새 규칙·장애·경제 수치 추가는 하지 않는다.

서사 제어처럼 함께 판단해야 하는 내용은 한 블록에 모은다. 다른 파일로 옮겼다는 사실만으로 출력 모델이 읽을 수 있는 것은 아니다. 최종 컴파일에는 실제 규칙 문구를 펼친다.

## 3. 모든 산출물의 전역 기호 체계 공유 (Global Shared Syntax)

크랙 스토리챗에서 **메인 프롬프트, 시작 프롬프트, 키워드북, 단축어, 프롤로그는 모두 하나의 동일한 런타임 생태계**에서 동작합니다. 따라서 메인 프롬프트 `# 표기`에서 선언한 기호 체계를 모든 산출물이 **재정의나 설명 없이 100% 공유**합니다.

```
                  ┌─────────────────────────────────────┐
                  │   메인 프롬프트 (# 표기 기호 정의)    │
                  │   ⓤ, ⓒ, →, ·, /, ｜, ━, ⌛, 💬, ×  │
                  └──────────────────┬──────────────────┘
                                     │
           ┌─────────────────────────┼─────────────────────────┐
           ▼                         ▼                         ▼
┌─────────────────────┐   ┌─────────────────────┐   ┌─────────────────────┐
│    시작 프롬프트     │   │     키워드북        │   │       단축어        │
│  T1 앵커링 & HUD    │   │  치환표·수치표·페어 │   │  장부·사칭교정 포맷  │
│  동일 기호 즉시 적용 │   │  동일 기호 즉시 적용 │   │  동일 기호 즉시 적용 │
└─────────────────────┘   └─────────────────────┘   └─────────────────────┘
```

### 전역 공유 기호 명세표
| 기호 | 원래 표현 | 모든 산출물 공유 활용 예시 |
|:---:|---|---|
| `ⓤ` | 플레이어, 유저, 주인공, 점주 | 메인: `ⓤ 자율성 6중 잠금` / 시작: `ⓤ 첫 행동 유도` / 키워드북: `ⓤ 동의 전 유도만` |
| `ⓒ` | NPC, 상대 인물, 손님, 단골 | 메인: `ⓒ 선제적 개입 장려` / 키워드북: `현장 ⓒ 둘 이상 모이면 시비·티키타카` |
| `→` | ~하면 ~한다, ~이므로 ~로 전환 | 메인: `IF(조건)→결과` / 키워드북: `날개·후광→큰 등산가방·조명 역광`, `충격→확인→침묵` |
| `·` | ~함과 동시에, 그리고, 와/과 | 메인: `대사·행동·생각 대리서술 금지` / 키워드북: `대사·접촉·호흡에 연결` |
| `/` | 또는, 대안, 각각, 슬롯 열거 | 메인: `남/여`, `S코드 열거` / 키워드북: `a01정상위/a02기승위/a03후배위...` |
| `｜` | 구분선, 카테고리, 슬롯 | 메인: `▶인물:[성별｜직책｜나이...]` / 상태창: `[점장]: ♂｜27세｜개업1일` |
| `×` / `禁` | 절대 하지 않는다, 금지, 없음 | 메인: `설명과잉 禁`, `대리서술 禁` / 키워드북: `프롬프트 직용 禁`, `미래 예지 绝对禁` |
| `必` | 반드시 ~한다, 필수 충족 | 메인: `서술·어조 必 자연스럽게` / 키워드북: `잠금 진실 必`, `출처 必` |
| `既` | 이미 발생한, 기판정된 | 메인: `既发生·既判定=Canon` (사후 수정·무효화 금지) |
| `依` | ~에 의거하여, 기준 | 메인: `판정=능력·장비·환경에 依` |
| `時` | ~할 때 (조건절 압축) | 메인: `D↑時 전조 발동`, `침입자 조우時` |
| `限` | ~에 한정함 | 메인: `성인장면 限`, `1회 限` |
| `無 / 可` | 없음 / 가능함 | 메인: `피해 無`, `협상 可`, `도주 可` |
| `↑ / ↓` | 상승한다, 하락한다 | 상태창: `호감도↑` / 키워드북: `의심 수치↑`, `체류 시간↓` |
| `⌛` | 턴/응답 번호 | 시작: `[⌛1]` / 메인: `[⌛n]` / 키워드북: 턴 경과 연동 |

## 4. 산출물별 상한과 편집 참고 범위

| 산출물 | 상한 | 충분한 정보가 있을 때의 편집 참고 범위 |
|---|---:|---:|
| 통합 프롬프트 각 변형 | 7,000자 | 6,500~6,850자 |
| 키워드북 개별 항목 | 400자 | 360~395자 |
| 시작 프롬프트 | 1,000자 | 900~980자 |
| 프롤로그 | 1,000자 | 920~985자 |
| 단축어 본문 | 400자 | 350~395자 |

상한은 계약이며 참고 범위는 최소량이 아니다. 짧아도 정보와 행동 조건이 충분하면 완성이다. 연구가 검증한 최적 점유율로 해석하지 않는다.

## 5. 실전 압축 4대 테크닉 (치환표·수치표·파이프슬롯·대조문)

### 테크닉 1: 치환표(Table) 압축
* **원리**: 구구절절한 서술형 조건문을 `대상A→치환A, 대상B→치환B` 형태의 테이블로 묶습니다.
* **예시**:
  ```text
  치환표: 날개·후광→큰 등산가방·조명 역광, 뿔→특이한 머리띠, 꼬리→벨트끈, 여우귀→헤어밴드, 세로동공→컬러렌즈, 반투명 발끝→바닥 반사광.
  ```

### 테크닉 2: 수치 기준표(Cost & Damage) 압축
* **원리**: 경제 및 손해 기준을 서술하지 않고, 수치와 결과를 직결합니다.
* **예시**:
  ```text
  복구비용: 워크인 정지 200만, 쇼케이스 파손 80만, 매대 완파 30만. 일일 매출 40만. 사고 1건=며칠치 순익 증발.
  ```

### 테크닉 3: 헤더 공유 인물 명부

[character-personality.md](character-personality.md)의 최소 명부를 사용한다. 열은 한 번 정의하고 행에는 값만 쓴다. 나이·유형·戀·慾·화법이 기본이며, 신분·이미지 ID·현재 관계처럼 작품에 필요한 열만 추가한다. 상세 외형·과거·욕망·능력 설명은 키워드북으로 배치한다.

### 테크닉 4: 금지선과 예외의 1문장 대조 (Prohibition + Allowance)
* **원리**: 금지 문단과 허용 문단을 나누지 않고 1줄로 통합 대조합니다.
* **예시**:
  ```text
  -금지선: 서술자가 ⓤ를 비하·비꼼·평가·논평·훈계하지않음. 서사내 불이익·패배·거절·갈등은 금지대상 아님
  -결정권: 자발적 사건의 최종 결정은 ⓤ 권리. 단, ⓒ의 선제적 개입(질문, 제안, 기습, 흥정)은 적극 장려
  ```

### 테크닉 5: 한자 혼용 기반 전보체 압축 (Sino-Korean Semantic Operator Packing)
* **원리**: 한국어 조사/어미("~는 절대로 해서는 안 되며, 반드시 ~해야 한다")의 문맥적 거품을 걷어내고, LLM이 강하게 인식하는 **단음절 한자 연산자(`禁, 必, 既, 依, 時, 限, 無, 可, 全`)**를 섞어 고밀도 전보체로 작성합니다.
* **한계**: 짧아지는 정도는 문장별로 측정합니다. 한자나 기호가 준수율을 높인다는 보장은 없으며, 모호하면 짧은 자연어가 우선입니다.
* **비교 시연**:
  - *장황한 서술문 (88자)*:
    `서술자가 상황을 너무 길게 설명하는 것은 절대 금지하며, 인물의 과거 비밀이나 감정은 반드시 명확한 출처가 있을 때에 한하여 자연스럽게 드러나야 한다.`
  - *한자 혼용 전보체 (41자 — 53% 절감)*:
    `설명과잉 禁; 인물 비밀·감정=출처 必; 무출처 비밀 인지 禁; 서술·어조 必 자연스럽게`
* **자주 쓰이는 실전 결합 패턴**:
  - `설명과잉 禁`, `미래예지 绝对禁`, `성공편향 禁`, `프롬프트 직용 禁`
  - `잠금진실 必`, `출처 必`, `장면전환·취침+1일 必`
  - `既发生·既判定=Canon` (이미 일어난 사건/판정은 캐넌 확정, 사후 번복 불가)
  - `성인장면 限`, `1회 限`, `위험도D↑時 전조 압박`

### 테크닉 6: 유명 작가·작품 앵커링을 통한 문체/서술 압축 (Literary Style Anchoring)
* **원리**: 문체, 분위기, 문장 호흡, 감각 묘사 방식을 길게 설명하느라 수백 자를 낭비하지 않고, **LLM의 사전학습 가중치에 이미 깊게 각인된 유명 작가의 고유명사를 지렛대로 삼아 1~2줄로 전이**시킵니다.
* **하이브리드 조합 공식 (`[작가A + 작가B]`)**:
  - 단일 작가에 그치지 않고 두 거장의 상반된 특성을 묶으면 독창적이면서도 모델이 즉각 이해하는 고유 문체가 생성됩니다.
  - `[무라카미 하루키 + 마르키 드 사드]`: 서정적 몽환감 + 퇴폐적·노골적 에로티시즘과 신체 감각 집중.
  - `[다자이 오사무 + 레이먼드 챈들러]`: 우아한 절망과 자조 + 하드보일드 건조함과 도시의 차가운 물성.
  - `[니시오 이신 + 어니스트 헤밍웨이]`: 자의식 과잉 티키타카와 말장난 + 감정을 드러내지 않는 극단적 빙산 이론 서술.
* **효과**: "문체를 어떻게 쓸 것인가"를 설명하는 데 500자 이상을 쓰던 것을 **"혼합문체: [작가A + 작가B] + 핵심 원칙 2줄"**로 줄여 100자 이내로 압축할 수 있습니다.

## 6. 실전 반복 압축 시연 (Before ➡️ Squeeze ➡️ Add ➡️ Final)

아래는 기존 제작 예시입니다. 수치는 당시 표기이며 현재 텍스트의 실측으로 사용하지 않습니다. 추가 주입 단계는 선택사항이고, 이미 충분한 항목을 다시 늘릴 필요는 없습니다.

### [Step 1] 정보 밀도 오버 기획 (530자 — 400자 한도 초과)

## 7. 손실 검증 및 글자 수 측정 도구

- **글자 수는 UTF-16 code unit 기준입니다.** 이모지 대부분은 서로게이트 페어라 **1글자가 2 단위**를 먹습니다. 유니코드 코드포인트로 세면 과소 측정되어, 통과했다고 판단한 산출물이 크랙 UI에서 초과로 잘립니다. 기호를 적극 쓰는 이 스킬의 산출물에서 실제로 자주 발생합니다 — 한 세션에서 세 건이 이 방식으로 새어 나갔습니다.
- **글자 수 측정 도구**: `scripts/check_prompt_length.py`를 실행합니다. codepoints 와 utf16 을 함께 출력하고 **둘 중 큰 값으로 판정**합니다(`max(codepoints, utf16_units)`). 400자 항목 한도에도 같은 기준이 적용됩니다.
- **최종 검증 기준**:
  - 통합 프롬프트 7,000자 초과 시 즉시 빌드 실패 (Error)
  - 키워드북 개별 항목 400자 초과 시 즉시 빌드 실패 (Error)
  - 프롤로그 / 시작 프롬프트 1,000자 초과 시 즉시 빌드 실패 (Error)
  - 단축어 프롬프트 400자 초과 시 즉시 빌드 실패 (Error)
- **압축 품질 판별**: 필요한 사실·조건·예외가 복원되는지 확인합니다. 상한 점유율이 낮다는 이유만으로 규칙을 추가하지 않습니다.
