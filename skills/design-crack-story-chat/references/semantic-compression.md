## 목표

프롬프트는 잘 쓴 글이 아니라 모델이 정확히 복원할 수 있는 최소 문자열이다. 문장미·친절한 설명·자연스러운 연결어는 사용자에게 보이지 않는 원본과 통합 프롬프트에서 우선순위가 낮다.

압축은 정보 삭제가 아니라 `긴 설명→공유된 개념명+작품 고유 편차`로 치환하는 작업이다.

## 보이는 글과 숨은 글 분리

- 보이는 글: 프롤로그, 실제 서술·대사, 사용자 안내. 자연스러움·몰입·가독성을 지킨다.
- 숨은 글: 통합 프롬프트, 캐릭터 원본, 상태 규칙, 키워드북. 전보체·키값·표·기호 사용 가능.
- 대사 예시는 보이는 문체 표본이므로 자연스럽게 쓴다. 예시 주변 설명은 압축한다.
- 시작 프롬프트에 사용자에게 실제로 보이는 문장이 있다면 그 문장만 자연스럽게 유지한다.

## 압축 순서

1. 중복 정사, 재설명, 수사, 제작자 메모, 예고 문구를 삭제한다.
2. 항상 필요하지 않은 세계관·인물·이능·사건은 본문 400자·키워드 5개 한도의 키워드북으로 이동한다.
3. 긴 일반 설명을 널리 알려진 장르·서사·성격·문체 용어로 치환한다.
4. 작품 고유의 차이, 예외, 금지선만 덧붙인다.
5. 문장을 `키=값`, `조건→행동`, 표, 안정된 기호로 바꾼다.
6. 같은 조건·주체를 묶고 주어·조사·연결어를 생략한다.
7. 마지막에만 단어를 줄인다. 핵심 규칙을 먼저 축약하지 않는다.

동의어는 강화 효과를 기대해 겹치지 않는다. `자연스럽게·유기적으로·매끄럽게 이어라`는 하나의 검증 가능한 명령(예: `직전 결과→다음 행동의 원인으로 연결`)으로 바꾼다. 같은 규칙의 다른 표현을 2~3회 반복하지 말고 한 소유 위치에서 한 번 정확히 쓴다.

## 손실 검증 압축 반복

각 반복에서 다음 셋으로 분류한다.

- 빠지면 결과가 달라짐→유지.
- 없어도 복원됨→삭제.
- 필요하지만 김→공용 용어·짧은 기호·키워드북으로 치환.

권장 순서: `서술 연결어·종결어 제거→핵심어화→조건/효과 기호화→공백·제목 정리→재측정`. 띄어쓰기 삭제나 한자 치환은 대상 모델이 오해하지 않고 실제 UTF-16 글자 수가 줄 때만 사용한다. 보이는 문장에는 적용하지 않는다.

각 단계 뒤에 원문과 축약문을 역설명해 비교한다. 행위자, 조건, 예외, 비용, 금지선, 출력 구문 중 하나라도 달라지면 직전 버전으로 되돌린다.

## 공용 지식을 압축 사전으로 사용

모델이 일반적으로 복원 가능한 명칭을 우선한다.

- 장르: 헌터물, 아카데미물, 로맨틱 코미디, 느와르, 밀실 추리.
- 역할/트로프: 라이벌, 냉소적 멘토, 츤데레, 믿을 수 없는 화자.
- 서사: 3막, 미드포인트 반전, 체호프의 총, 제한시간.
- 시점/문체: 제한적 3인칭, 건조한 문체, 빠른 호흡, 하드보일드.
- 성격: 익숙한 유형 코드+짧은 편차. 자세한 규칙은 `character-personality.md`를 따른다.
- 세계 규칙: 현실의 상식이 그대로면 다시 설명하지 않고, 현실과 다른 점만 쓴다.

예:

```text
현대 한국과 동일하되 20년 전 게이트 발생; 헌터=국가면허 위험직+스타산업
톤=직장물×헌터물, 건조한 블랙코미디
```

용어가 다의적·유행성·소수 커뮤니티 전용이면 5~20자 풀이를 붙인다. 풀이가 길어 원문보다 커지면 용어를 쓰지 않는다.

## 반드시 풀어 쓸 것

공용 지식에 맡기면 안 되는 항목:

- 플레이어 권한, 동의, 행동·대사 대행 금지.
- 능력의 비용·한계·실패 처리·판정 예외.
- 작품 고유 정사와 현실 상식에서 벗어난 점.
- 비밀의 지식 범위와 공개 조건.
- 상태값 범위·변화량·전이 조건.
- 사건 트리거·차단 조건·효과.
- 출력 순서·구분자·기계 파싱 문법.
- 플랫폼에서 실제 지원 여부가 불확실한 변수·미디어 문법.

`널리 알려짐`은 중요한 규칙을 생략하는 면허가 아니다. 기본값만 맡기고 결과를 바꾸는 편차는 명시한다.

## 압축 문법

권장:

```text
A→B        조건→행동/효과
A|B|C      같은 칸의 병렬 특성/선택지
A·B        동시에 성립하는 짧은 속성
X↑/X↓      정의된 수치·단계의 증가/감소
≤, ≥, ±    수치 한계
역할=값; 목표=값; 압박→행동
```

원칙:

- 기호 하나에 뜻 하나만 부여한다.
- 비표준 약어는 한 번 정의하고, 재사용으로 실제 글자 수가 줄 때만 쓴다.
- `/`와 `|`를 같은 병렬 의미로 섞지 않는다. 한 작품에서 하나를 택한다.
- 표는 정확한 대응이 3개 이상일 때 사용한다.
- 완전한 문장보다 단문·명사구를 우선한다.
- Markdown 장식, 빈 줄, 반복 제목도 최종 글자 수에 포함한다.
- 이모지는 장식이 아니라 안정된 상태 ID일 때만 사용한다. 실제 UTF-16 길이도 측정한다.

장문:

```text
그녀는 평소에는 냉정한 태도를 보이지만 상대방에게 호감을 느끼는 경우 말로 표현하기보다는 실질적인 도움을 제공한다.
```

압축:

```text
냉정; 호감→말 대신 실무 도움
```

## 정형화 압축

산문으로 쓰인 통합 프롬프트는 문장 하나하나가 그럴듯해 보여서 줄일 데가 없어 보인다. 실제로는 **어미와 연결어가 전체의 10% 이상을 먹는다.** 문서 전체를 한 번에 정형 문법으로 옮기면, 규칙을 하나도 잃지 않고 그만큼이 빠진다.

### 반복되는 어미를 기호로 승격한다

한 번 정의하고 수십 번 회수하는 기호를 먼저 찾는다. 부정형이 거의 항상 1순위다.

| 승격 | 원래 | 회당 절감 |
|---|---|---|
| `×` | `~하지 않는다` / `~를 금지한다` | 5~7자 |
| `≠` | `~는 ~를 뜻하지 않는다` | 8자 이상 |
| `=` | `~는 ~이다` / `~란 ~를 말한다` | 3~6자 |
| `→` | `~하면 ~한다` / `~이므로 ~한다` | 3~5자 |

기호 하나를 범례에 추가하는 비용은 10~15자다. **네 번 이상 회수되면 이득**이므로, 도입 전에 원문에서 등장 횟수를 세어 판단한다.

### 문장에서 걷어낼 것

- 주어가 문맥상 자명한 경우의 주어 반복 (`AI는`, `모델은`)
- `~하되`, `~이며`, `~고`, `~므로` 같은 연결어 → 줄바꿈이나 `·`
- 같은 문단에서 이미 말한 조건의 재진술
- 부드럽게 만드는 표현 (`~하는 것이 좋다` → `~한다` 또는 `×`)
- 예시가 규칙과 같은 내용을 반복하는 경우의 예시

### 압축 강도를 내용에 따라 다르게 준다

**이것이 정형화 압축의 유일한 안전장치다.**

| 내용 | 압축 강도 |
|---|---|
| 세계 설정, 배경, 인물 소개, 절차 서술 | 세게 |
| 분량·형식·순서 같은 기계적 규칙 | 세게 |
| 플레이어 주도권, 동의, 금지 경계, 안전 관련 | **약하게** |

주도권과 동의 규칙을 기호로 뭉개면 압축이 아니라 손실이다. 이 규칙들은 모델이 **애매할 때 기본값으로 돌아갈 자리**여야 하므로, 몇 글자 아끼자고 해석 여지를 만들지 않는다. `잠긴 행동은 제안·암시·완료하지 않는다`는 `잠긴 행동×`보다 길지만 그대로 둔다.

### 실측

한 작품의 통합 프롬프트를 위 방식으로 정형화한 결과, **6,921자 → 6,208자(-10.3%)** 였다. 규칙은 55개 전부 보존됐다. 확보한 여백에는 그동안 예산이 없어 못 넣던 세계 시스템 두 개(경제 구조, 성장 체계)와 인물 명부가 들어갔다.

압축의 목적은 여백을 만드는 것이지 여백을 없애는 것이 아니다. 줄인 만큼을 전부 다시 채우지 않는다.

## 규칙 지문으로 손실을 검증한다

압축은 **손실이 조용히 일어나는 작업**이다. 읽어보면 다 있는 것 같고, 없어진 규칙은 없어졌다는 사실 자체가 눈에 띄지 않는다. 눈으로 대조하지 않는다.

방법은 단순하다. 원본의 규칙을 하나씩 **지문(핵심어 집합)** 으로 적고, 압축본에서 그 지문이 살아있는지 기계로 확인한다.

```python
RULES = {
  "시도 접수":   ["시도", "판정", "자동 확정"],
  "4축 분리":    ["정서적 신뢰", "물리적 근접", "성적 동의", "관계 약속", "함축"],
  "동의 아님":   ["거절", "주저", "침묵", "화제 전환", "중단"],
}
# 지문이 전부 사라짐 → 규칙 소실
# 일부만 사라짐 → 표현만 바뀌었는지 사람이 확인
```

- 지문은 **그 규칙에만 나오는 단어**로 고른다. 흔한 단어를 넣으면 다른 규칙에 걸려 통과한다.
- 부분 누락은 자동 판정하지 않는다. 표현을 바꾼 것인지 규칙이 빠진 것인지는 사람이 본다.
- 한자·이모지·전각 문자는 표기가 갈리므로 지문에 쓸 때 실제 문서의 형태를 확인한다.
- 이 검사도 [validation.md](validation.md)의 음성 대조 대상이다. 일부러 한 규칙을 지우고 검사기가 잡는지 먼저 확인한다.

## 글자 수와 토큰을 구분

이 프로젝트의 하드캡은 **글자 수**다. 토큰 추정치로 7,000자 검사를 대신하지 않는다.

- 한자 치환은 `설정→設定`, `금지→禁`처럼 실제 UTF-16 길이가 줄고 대상 모델이 즉시 복원할 때만 사용한다.
- `한글 2토큰=한자 1토큰` 같은 고정 환산은 모델·토크나이저마다 달라 규칙으로 쓰지 않는다.
- 이모지·결합문자·일부 특수기호는 화면상 한 글자여도 UTF-16에서 2개 이상일 수 있다.
- 최종 판정은 `scripts/check_prompt_length.py`의 코드포인트/UTF-16 중 큰 값으로 한다.

30% 같은 압축률을 목표로 삼지 않는다. 압축 후 의미 복원과 실제 측정값이 좋아질 때만 채택한다.

## 최소 의미 경계 유지

숨은 프롬프트도 파싱 경계는 남긴다.

```text
좋음: ⓤ=플레이어; ⓒ=NPC; IF(ⓤ도주)→ⓒ추격; 실패→경보
나쁨: ⓤ플레이어ⓒNPCIFⓤ도주ⓒ추격실패경보
```

- 필드 사이에는 `;` 또는 줄바꿈, 조건과 결과 사이에는 `→`, 병렬값 사이에는 `|`를 둔다.
- 조사·종결어는 줄여도 고유명사, 부정 범위, 수치 단위, 예외 경계는 붙이지 않는다.
- `한다`/`할 것`/명사구 중 가장 짧고 명확한 한 형태를 섹션 안에서 통일한다. 존댓말 제거 자체가 준수율을 보장하지 않는다.

## 압축 판정

각 축약을 다음 순서로 검사한다.

1. 복원: 다른 모델이 같은 행동·제약을 설명할 수 있는가.
2. 편차: 일반 용어와 작품 설정의 다른 점이 남아 있는가.
3. 충돌: 코드와 명시 규칙이 충돌할 때 우선순위가 있는가.
4. 비용: 정의까지 포함한 실제 글자 수가 줄었는가.
5. 표면: 플레이어에게 보이는 문장만 충분히 자연스러운가.

SAFE/UNSAFE 각 통합본은 **최소 분량 목표 없이**, 가능하면 6,500자 이하에서 조립하고 실제 문자열을 따로 측정한다. 7,000자를 채우기 위해 내용을 추가하거나 플레이어 주도권, 능력 한계, 현재 상태, 지식 범위, 사건 조건, 출력 문법을 희생하지 않는다.
