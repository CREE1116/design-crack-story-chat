# 키워드북 설계 가이드 (Keyword Book Architecture & Modular Sub-Prompts)

다섯 번째 산출물인 `build/keyword-book.md`는 크랙 플랫폼의 **키워드북(Keyword Book)** 탭과 **단축어(Shortcuts)** 탭에 등록할 항목들을 정의합니다.

상시 시스템 프롬프트(7,000자 상한)의 예산을 아끼면서, 특정 상황(키스, 19+ 성애, 특수 전투, 정치 암투 등)이 발생했을 때 **3슬롯 런타임 주입**을 통해 연출 밀도를 극대화하는 **가변형 모듈식 시스템 프롬프트(Modular Sub-System Prompt)**의 핵심 문서입니다.

## 1. 키워드북의 본질: 단순 정보 나열 vs 가변형 메인 프롬프트

키워드북은 단순한 세계관 설정집이나 인물 사전(Lore Encyclopedia)으로만 쓸 수도 있지만, 실전에서는 **"상황에 따라 상시 프롬프트에 동적으로 끼워 넣는 가변형 메인 프롬프트(Modular Sub-System Prompt)"**로 설계할 때 가장 강력한 위력을 발휘합니다.

| 접근 방식 | 단순 정보 나열형 (기본형) | 가변형 메인 프롬프트형 (실전 고밀도) |
|---|---|---|
| **성격** | 세계관/인물 설정, 역사, 사실 관계 기록 | 특정 상황 전용 런타임 연출 지침 및 행동 규칙 |
| **작성 내용** | "누구는 어떤 마법을 쓰고 성격이 어떻다" | 카메라 앵글, 대사 톤, 감각적 신체 묘사, 공방 규칙, 허용/금지령 |
| **적합한 상황** | 배경 지식, 고유 명사 설명, 서브 팩트 | 전투 결전, 19+ 성애 씬, 스킨십, 극적 밀실 대화 |

> 💡 **설계 유연성**: 모든 항목을 가변 프롬프트로 짤 필요는 없습니다. 단순 세계관 용어는 설정 설명형으로, 극적인 연출 변화가 필요한 씬은 가변형 프롬프트로 상황에 맞게 섞어서 구성할 수 있습니다.
>
> ⚡ **런타임 동작 원리**: [crack-internal-runtime.md](crack-internal-runtime.md) 분석에 따르면, 키워드북은 유저가 입력한 최신 대사 바로 밑(`## Additional Information & Rules` ➡️ `<knowledge_base>`)에 실시간 주입됩니다. LLM은 입력 프롬프트의 맨 끝(최하단)에 있는 지침을 가장 강력하게 따르므로(Recency Bias), 메인 프롬프트보다 키워드북 지침의 구속력이 훨씬 강합니다!

## 2. 런타임 호출 테크닉: 1턴 브릿징과 큐 투척 (Turn Bridging)

크랙은 플레이어나 AI가 해당 키워드를 텍스트로 발화했을 때 키워드북을 로드합니다. 플레이어가 우연히 키워드를 입력하길 마냥 기다리면 원하는 타이밍에 연출 모듈이 발동하지 않을 수 있습니다.

이를 해결하기 위해 **"메인 프롬프트에서 1턴을 벌어주고, 키워드북 호출 단어(큐)를 뱉는" 1턴 브릿징 테크닉**을 적용할 수 있습니다.

```
[Turn N : 전조 및 브릿징 턴]
- 메인 프롬프트: 즉시 결판/본 씬으로 급발진하지 않고, 대치/분위기 조성을 서술하며 1턴을 번다.
- 키워드 큐 투척: 나레이션이나 NPC 대사 속에 키워드북의 트리거 단어(Cue)를 자연스럽게 발화한다.
  (예: "칼자루를 쥐며 '진검 결투'를 선언한다", "침실 문을 걸어 잠그며 숨을 고른다")

              ▼ (대화 컨텍스트에 키워드 큐가 기록됨)

[Turn N+1 : 키워드북 로드 & 연출 폭발 턴]
- 크랙 엔진: 직전 턴에 노출된 키워드를 감지하여 해당 키워드북을 시스템 최상단에 주입!
- 키워드북: 주입된 가변형 프롬프트 지침(카메라 구도, 체위/공방 규칙, 신체 감각)에 따라 본 씬 연출 수행!
```

## 3. 3슬롯 런타임 메커니즘과 설계 원칙

1. **상시 프롬프트 vs 키워드북 분리**:
   - **상시 메인 프롬프트**: 상시 HUD 기호, 기본 6중 잠금, 보편적 대사 톤 등 항구적인 규칙.
   - **키워드북**: 특정 사건, 특수 페어 만남, 19+ 씬, 특수 결투 등 **상황별로 호출되는 가변 모듈**.
2. **동시 활성화 최대 3개 한도 & 상단 우선순위**:
   - 크랙 엔진은 턴당 최대 3개의 키워드북 항목만 주입합니다. 4개 이상 매칭 시 **목록 하단에 있는 항목부터 드랍(Drop)**됩니다.
   - ⚠️ **성인/특수 연출 모듈 최상단 배치 필수**: 성인(19+) 모듈이나 특수 전투 결전 모듈은 그 턴에서 절대로 드랍되어서는 안 되는 최고 중요도 지침입니다. 일반 인물 설정이나 장소 로어가 상단에 있으면 정작 중요한 성애 모듈이 3슬롯 밖으로 밀려 누락되는 대참사가 발생합니다. 따라서 **`성애_19금` 및 특수 연출 모듈은 반드시 키워드북 목록의 최상단(1~3순위)에 배치**합니다.
3. **항목당 400자 고밀도 충원 (권장 350~395자)**:
   - 크랙 UI 한도(400자) 안에서 필요한 설정과 연출 규칙을 집약적으로 구성합니다.

## 4. 키워드북 극압축 방법론: 400자 초과 설계 ➡️ 표/기호 압축 & 메인 기호 공유

키워드북 항목 하나하나는 크랙의 귀중한 3개 동적 슬롯 중 하나를 차지합니다. 처음부터 400자 제한에 맞춰 소극적으로 생각하면 정보량이 빈약해져 1슬롯의 가치를 살리지 못합니다.

### 4.1 핵심 설계 원칙: 400자 초과 기획 ➡️ 표·기호 고밀도 압축
1. **1단계: 풍부한 원형 설계 (500~700자 상당)**:
   - 처음에는 400자를 넘길 만큼 상황의 인과, 수치 기준, 대사 톤, 신체 감각, 제약 사항을 깊이 있게 설계합니다.
2. **2단계: 메인 프롬프트 기호 체계 100% 공유 (Shared Syntax)**:
   - 크랙 런타임에서 키워드북은 메인 프롬프트와 동일한 LLM 컨텍스트(`## Additional Information & Rules` ➡️ `<knowledge_base>`)로 통합 평가됩니다.
   - 따라서 **메인 프롬프트 `# 표기`에서 선언한 공통 기호(`ⓤ`, `ⓒ`, `→`, `·`, `/`, `｜`, `×`, `↑/↓` 등)를 키워드북에서도 그대로 공유**합니다.
   - 키워드북 본문 안에서 "플레이어는", "NPC는", "~하면 ~한다" 같은 긴 주어와 연결사를 중복 설명하지 않고 기호로 대체합니다.
3. **3단계: 표(Table)와 치환 기호를 통한 400자 한도 패킹 (≤400자)**:
   - 줄글 문장 대신 **치환표(`A→B`), 수치 기준표, 슬롯 구분자(`｜`), 슬래시(`/`)**를 동원해 400자 이내(권장 350~395자)로 압축합니다.

### 4.2 메인 프롬프트와 공유하는 공통 압축 기호
| 기호 | 의미 / 용법 | 키워드북 실전 활용 예시 |
|:---:|---|---|
| `ⓤ` | 플레이어(User) | `ⓤ 동의 전 유도만, 거절·침묵 시 즉시 물러남` |
| `ⓒ` | 대상 인물 / NPC | `ⓒ는 현재 단계까지만 시도`, `현장 ⓒ 둘 이상 모이면` |
| `→` | 조건·결과 / 인과 / 일상 치환 | `충격 굉음→피해 범위 확인→굳어버린 침묵`, `날개·후광→큰 등산가방·조명 역광` |
| `·` | 동시 속성 / 병렬 묶음 | `대사·접촉·호흡에 연결`, `임대 250만·공과 80만·알바 220만` |
| `/` | 대안 / 항목 구분 / 택일 | `a01정상위/a02기승위/a03후배위...`, `반응/응징` |
| `｜` | 슬롯 칸 구분자 | `설정: 에리(호문쿨루스｜정밀측정)·세라(연금술사｜만성피로)` |
| `×` | 금지 / 미보유 / 제외 | `남성·미보유×`, `초자연적 돈 해결 기적×`, `새 장면 이어쓰기×` |
| `↑ / ↓` | 수치/상태의 상승 및 하락 | `의심 수치↑`, `체류 시간↓` |

### 4.3 실전 압축 변환 사례 (Before & After)

* **압축 전 (서술형 원본 기획; 530자 상당 — 400자 한도 초과로 등록 불가)**:
  > 이 세계관에는 인지저해라는 현상이 있어서 일반 인간들은 천사나 악마 같은 초자연적 존재의 외형을 목격하더라도 일상적인 상식에 맞춰 왜곡해서 기억합니다. 예를 들어 날개나 후광을 보면 큰 등산가방이나 조명 역광으로 착각하고, 뿔은 특이한 머리띠로, 꼬리는 길게 늘어뜨린 벨트 끈으로, 여우귀는 헤어밴드로, 세로동공은 컬러렌즈로 봅니다. 반투명한 발끝은 바닥 반사광으로 치환됩니다. 초자연적 존재들은 자신의 외형을 굳이 숨기지 않으며, 일반인들의 상식이 깨지는 것은 비행이나 마법, 괴력으로 기물을 파괴하는 등의 물리적 사건이 터졌을 때뿐입니다. 만약 사건이 발생하면 치환이 무너지고 관리 부서가 개입하여 은폐 수습에 들어갑니다. 일반인 관찰자는 이상 현상이 반복될수록 의심이 깊어지고 질문이 길어집니다. 플레이어가 실체를 알고 있다는 사실을 눈치채면 단골들은 신기해하거나 약점을 잡힌 것처럼 경계하게 됩니다.

* **압축 후 (치환표 및 메인 기호 체계 적용; 366자 — `convenience/build` 실전 형식)**:
  ```markdown
  치환표: 날개·후광→큰 등산가방·조명 역광, 뿔→특이한 머리띠, 꼬리→길게 늘어뜨린 벨트끈, 여우귀→헤어밴드, 세로동공→컬러렌즈, 반투명 발끝→바닥 반사광.
  인간 대중은 초자연적 외형을 목격해도 일상 상식에 맞추어 자동 왜곡·치환해 기억한다. 초자연 존재는 외형을 숨기지 않으며, 깨지는 것은 외형이 아닌 사건(비행·마법·괴력 파괴)이다.
  사건 발생 시 치환이 붕괴되어 각 조직의 은폐 수습이 개입한다. 한지수는 아직 필터가 있어 억지 납득하나 이상 현상이 반복될수록 치환이 지연되고 질문이 길어진다.
  점장이 실체를 본다는 것을 알아챈 단골들은 신기해하거나 약점을 잡힌 듯 경계한다.
  ```

## 5. 초경량 직관형 작성 규격 (크랙 UI 1:1 매핑)

크랙 웹 UI에 그대로 복사-붙여넣기할 수 있는 3대 요소로 간결하게 작성합니다.

```markdown
## [항목 이름]
- 키워드: 키워드1, 키워드2, 키워드3
- 내용:
[크랙 UI 본문 칸에 넣을 문자열; 350~395자 권장]
```

### 💡 크랙 UI 1:1 매핑
1. **항목 이름 (`## 제목`)**: 크랙 키워드북 항목 제목 칸에 입력

## 7. 키워드북 설계 실전 프로 팁 7대 원칙 (Pro Tips)

수많은 스토리챗 제작자들이 겪은 시행착오(슬롯 낭비, 환각, 모듈 미발동)에서 도출된 핵심 설계 팁입니다.

### 팁 1: 정적 사전(Lore)과 동적 가변 모듈(Directives)의 분리
- **단순 백과사전형**: 지명, 마법 학파, 가문 역사 등은 사실 관계 설명 위주로 가볍게 작성합니다.
- **가변 프롬프트형**: 결투, 19+ 합방, 스킨십, 밀실 대화 등 극적 씬은 단순 설명이 아니라 모델의 행동을 제어하는 **시스템 지시문(`-카메라:`, `-호흡:`, `-금지/허용:`)** 형태로 작성하여 해당 턴의 뇌(지침)를 완전히 교체합니다.

### 팁 2: 1턴 브릿징 & 큐 투척 (Turn Bridging)
- 플레이어가 우연히 키워드를 입력해 주길 기다리지 마세요.
- **대사/나레이션 큐 투척**: 메인 프롬프트가 전조를 묘사하며 **1턴을 벌고, 나레이션이나 NPC 대사 속에 키워드북 호출 단어(예: '진검 결투', '합방', '침실')를 자연스럽게 뱉어두면**, 다음 턴에 크랙 엔진이 키워드를 100% 감지하여 해당 연출 모듈을 최상단에 주입합니다.
- **상태창(HUD) 앵커링 큐 (HUD Date/State Trigger)**:
  - 타임라인 이벤트나 특정 분기 이벤트의 경우, **상태창에 출력되는 특정 날짜(`2025.1.1`, `5.4`)나 상태 문자(`[비상사태]`, `[안식]`)를 키워드로 등록**해 둘 수 있습니다.
  - 시간 경과나 씬 전환으로 상태창에 해당 날짜/상태가 찍히는 순간, 크랙 엔진이 이를 트리거로 인식해 `이벤트 키워드북(이혼 통보, 생일 전야, 특수 위기)`을 오차 없이 자동으로 로드시킵니다.

### 팁 3: 성인/특수 연출 모듈의 키워드북 격리 및 최상단(1순위) 배치
- **메인 프롬프트 격리**: 성인 씬 번호(A코드, 19~56번 등)는 메인 시스템 프롬프트에 절대 적지 않고 오직 키워드북 해당 모듈에만 적습니다. (7,000자 상시 예산 보존 및 일상 대화 중 이미지 누출 방지)
- **키워드북 목록 최상단 배치 필수**: 크랙 엔진은 키워드북 목록을 위에서부터 아래로 읽으며 3슬롯을 채웁니다. 만약 성애 모듈이 목록 하단에 있으면, 인물이나 장소 키워드가 먼저 슬롯을 차지하여 정작 19+ 상황에서 성애 모듈이 드랍(Drop)되는 치명적인 오류가 발생합니다. **따라서 `성애_19금` 및 특수 결전 모듈은 무조건 키워드북 등록표의 최상단(1~3번)에 배치하여 3슬롯 중 1순위로 확정 로드되도록 보장**해야 합니다.

### 팁 4: 3슬롯 교통정리 & 상시 단어 트리거 금지
- 크랙은 한 턴에 최대 3개 키워드북만 주입하며, 4개 이상 매칭 시 우선순위가 낮은 항목이 드랍(Drop)됩니다.
- **절대 금기**: 상태창(HUD)이나 일상 대화에 영구 상주하는 단어(`[관계]`, `등급`, `상태`)를 트리거 키워드로 쓰지 마세요. 3슬롯 중 1개가 영구 낭비됩니다.
- 한 씬에서 동시 발동될 확률이 높은 키워드는 최대 2개까지만 설계하고, 1개 슬롯은 시스템 여유 버퍼로 남겨두는 것이 안전합니다.

### 팁 5: 400자 초과 기획 ➡️ 표·기호 고밀도 압축 (권장 350~395자)
- 처음부터 400자 제한에 갇혀 소극적으로 기획하면 귀중한 1슬롯의 정보 밀도를 낭비하게 됩니다.
- **실전 압축 공식**:
  1. 먼저 **500~700자 상당**의 풍부한 원본(상황 인과, 수치 기준, 대사 톤, 신체 감각, 제약)을 완전하게 기획합니다.
  2. 메인 프롬프트와 공유하는 기호(`ⓤ`, `ⓒ`, `→`, `·`, `/`, `｜`, `×`)를 적극 동원하여 긴 문장과 조사를 쳐냅니다.
  3. 치환표(`A→B`), 수치 기준표, 슬래시 열거를 활용해 **350~395자의 고밀도 패킹 덩어리**로 최종 압축합니다.

### 팁 6: 체인 리액션 (연쇄 트리거 바톤 터치)
- 한 모듈이 끝날 때 다음 단계 모듈의 키워드를 대사/나레이션에 흘려주면 자연스럽게 서사의 다음 국면으로 바톤을 넘길 수 있습니다.
  - 예: `스킨십 모듈(💋)`의 마지막 서술에서 "둘만의 침실로 향한다" ➡️ 다음 턴 `합방 모듈(🔞)` 자동 로드!

### 팁 7: 캐릭터 상세설명 오프로딩 & 2인 1항목(200자×2) 페어링 압축
- **메인 프롬프트 1턴 버티기**: 등장인물이 많은 대작의 경우, 메인 프롬프트에는 캐릭터가 첫 등장했을 때 딱 1턴만 버텨줄 수 있는 **최소 정보(외형, 직책, 첫 대사 말투 등 1줄 씨앗)**만 둡니다.
- **심층 설정 키워드북 이관**: 캐릭터가 등장해 대화가 시작되면 이름이 컨텍스트에 찍히므로, 심층 과거사/역린/복잡한 능력 등 상세 설명은 키워드북으로 분리합니다.
- **2인 1항목 페어링 (200자 × 2 = 400자)**:
  - 연관성 높은 2명(같은 길드, 주종, 라이벌, 형제/부부 등)의 상세 프로필을 한 키워드북 항목에 **200자씩 나란히 묶어서 작성**하고, 키워드 칸에 두 사람의 이름을 모두 등록합니다.
  - **효과**: 둘 중 한 명만 등장해도 로드되며, 특히 두 사람이 함께 나오는 티키타카 장면에서도 **단 1개의 키워드북 슬롯만 소모하여 3슬롯 예산을 극적으로 절약**할 수 있습니다!

## 8. 단축어(Shortcuts) 등록 규격 및 실전 설계

단축어는 키워드북과 동일한 물리 파일(`build/keyword-book.md`)의 하단 섹션으로 관리하며, `crack_sync.py`가 이를 크랙 웹 에디터의 [단축어] 탭에 1:1로 자동 등록합니다.

> 📖 **상세 제작 가이드 및 5대 실전 레시피**: [단축어 설계 가이드 (shortcuts-guide.md)](shortcuts-guide.md)를 참고하세요.

### 크랙 UI 제약 및 작성 규칙
* **이름 (Name)**: **≤ 10자** (모바일 버튼 표시용. `상황요약`, `사칭교정`, `다음날로`, `속마음` 등 2~5자 직관적 단어 권장)
* **설명 (Description)**: **≤ 30자** (버튼 툴팁/요약 설명)
* **프롬프트 (Prompt)**: **≤ 400자** (클릭 시 주입되는 시스템 명령. 3줄 이내 불릿 상한선 및 `{user}` 사칭 금지 문구 권장)
* **권장 등록 개수**: 4~8개 (최대 20개 지원)

```markdown
# Shortcuts (단축어)

# Shortcut `ledger`
- name: 장부
- description: 자금 및 현황을 한 번에 정리

## Shortcut prompt

━ [자금/현황] ━
[오늘] [일일 수입/활동] n만
[이달] 누적 n만 / 필요 [목표금액] · 사고 n건 −n만
[상환] D-n · 이번 회차 [회차금액] · 잔액 n만 / 남은 n회
[고정비] [총액] = [항목A] · [항목B] · [항목C]
[미수/외상] 상대 이름: n만
[전망] 이대로 가면 이번 기간이 어떻게 되는지 한 줄
━

# Shortcut `summary`
- name: 요약
```

## 9. SAFE vs UNSAFE 키워드북 분리 작성 원칙 (`keyword-book-safe.md` / `keyword-book-unsafe.md`)

크랙에서 **전연령/SAFE(안전판) 스토리**와 **19+ 성인/UNSAFE 스토리**를 배포할 때, 메인 시스템 프롬프트뿐만 아니라 **키워드북 또한 SAFE용과 UNSAFE용으로 분리하여 빌드**합니다.

| 구분 | **세이프 키워드북 (`keyword-book-safe.md`)** | **언세이프 키워드북 (`keyword-book-unsafe.md`)** |
|---|---|---|
| **발행 목적** | 전연령 / 청소년 이용가 스토리 배포 | 19+ 성인 / 고수위 롤플레이 스토리 배포 |
| **성애 19+ 모듈** | **완전 제외** (또는 풋풋한 뽀뽀/포옹 수준의 완곡 묘사) | **최상단(1~3번)에 필수 탑재** (`성애_19금`) |
| **A코드 체위 바인딩**| 없음 (일반 S01~S18 감정 표정만 연결) | A01~A15 성인 체위 씬 번호 및 노골적 감각 묘사 포함 |
| **공통 수록 항목** | 세계관 설정, 인물 명부, 전투/스킬 연출, 단축어 | SAFE의 모든 공통 항목 그대로 포함 |

### 🛠️ 자동 동기화 도구(`crack_sync.py`) 연동
* **SAFE 동기화 시**:
  ```bash
  python3 tools/sync/crack_sync.py sync <프로젝트명> --variant safe
  ```
  ➡️ `build/keyword-book-safe.md`를 우선 감지하여 크랙 스튜디오에 안전판 키워드북을 주입합니다.
* **UNSAFE 동기화 시**:
  ```bash
  python3 tools/sync/crack_sync.py sync <프로젝트명> --variant unsafe
  ```
  ➡️ `build/keyword-book-unsafe.md`를 우선 감지하여 `성애_19금`이 최상단에 배치된 성인 키워드북을 일괄 등록합니다.
*(※ 둘 중 하나만 존재하거나 기존 단일 `build/keyword-book.md`만 있는 경우에도 하위 호환성으로 자동 폴백 등록됩니다.)*
