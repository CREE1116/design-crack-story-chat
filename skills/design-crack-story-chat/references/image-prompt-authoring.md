# 이미지 프롬프트 작성: 캐릭터·감정·행동

캐릭터 이미지, 감정 프리셋, 장면별 행동 프롬프트를 작성하거나 수정할 때 적용한다. 사용자가 제공한 V4.5 가이드와 후속 교정을 반영한 작성 기준이다. 아래 실무 기본값과 공식 문법을 구분한다.

## 1. 고정 외형과 이번 장면 분리

- **Identity:** 머리·눈·종족·체형·고유 특징. 같은 인물은 동일한 태그 표현을 재사용한다.
- **Outfit:** 의상·액세서리·소재·색. 의상 교체 시 외형까지 다시 쓰지 않는다.
- **Expression/Action:** 이번 순간의 눈썹·눈매·입·시선·고개·동작. 고정 외형에 섞지 않는다.
- **Scene/Style:** 공통 장소·조명·구도·그림체. 특정 인물의 외형을 공통 Base에 넣지 않는다.

태그를 `, `로 구분하고 Danbooru의 밑줄은 공백으로 바꾼다. 중요한 태그는 사전 정의를 확인한다. 설치된 NovelAI 스킬의 wiki 검색 도구가 있으면 활용하고, 없으면 검증 가능한 출처를 찾거나 미검증 표현임을 표시한다. 자연스러운 영어를 공식 태그로 단정하지 않는다. 태그로 표현하기 어려운 미묘한 반응은 짧은 영어 문장으로 보완한다.

## 2. 감정 이미지: 얼굴이 메인, 행동은 보조

**감정은 얼굴에서 읽혀야 한다.** 기본은 `close-up, face focus`처럼 얼굴이 크게 보이는 구도다. 전체 얼굴이 읽히도록 하고, 눈·입만 잘라내는 극단적 크롭은 요청 시에만 사용한다. 상반신·허벅지·전신 구도를 감정 프리셋의 기본 랜덤 선택지로 넣지 않는다.

눈썹의 안쪽/바깥쪽 변화, 눈꺼풀·시선, 입꼬리·입술 긴장·입 벌어짐, 턱의 긴장으로 감정의 차이를 만든다. 모든 감정에 홍조·땀·눈물·반쯤 감긴 눈을 일괄 추가하지 않는다.

- **차분:** 편안한 눈썹, 느슨한 턱, 미세한 미소. 강한 변형도 과장된 흥분으로 바꾸지 않는다.
- **웃음:** 눈가가 접힘, 올라간 볼, 열린 입. 참는 웃음과 터지는 웃음을 얼굴 반응으로 구분한다.
- **분노:** 눌러 다문 입과 긴장한 턱 / 이를 악문 얼굴 / 말을 쏟는 순간의 열린 입. 세 상태를 동시에 요구하지 않는다.
- **슬픔:** 맺힌 눈물, 안쪽이 들린 눈썹, 참는 입술. 오열과 구분한다.

행동은 고개 기울임·얼굴 방향·작은 턱 움직임 등 얼굴 구도를 유지하는 보조 요소로 쓴다. 손이 꼭 필요하면 얼굴을 가리지 않고 프레임 가장자리에 들어오는 정도로 제한한다. 팔짱·허리 손·배를 잡기·다리 자세를 보여주려고 얼굴을 작게 만들지 않는다.

‘풍부하게/다이내믹하게’는 먼저 **같은 감정 안의 강도·미묘한 반응·연출 차이**를 개선하라는 뜻으로 해석한다. 요청 없이 감정 항목·상황 코드 수를 늘리거나 새로운 감정 파일을 만들지 않는다. 기존 이름·순서·코드 매핑을 보존한다.

## 3. 시선과 구도 충돌 제거

`looking at viewer`는 카메라 응시, `eye contact`는 화면 속 인물끼리 눈맞춤이다. 둘을 습관적으로 함께 넣지 않는다. `closed eyes`나 `averting eyes`와 카메라 응시를 같은 변형에 넣지 않는다. 눈을 감았으나 얼굴은 카메라 방향이면 `facing viewer`를 고려한다.

정면 대화 구도에 무조건 `pov`를 붙이지 않는다. 실제 1인칭 장면에서만 카메라 주인·높이·보이는 신체 부위를 정한다. 순수 감정 컷에 POV 증거용 손·다리를 억지로 추가하지 않는다.

행동이 주목적인 장면은 별도로 필요한 접촉 부위와 지지면이 보이는 구도를 선택한다. 한 이미지에는 하나의 순간을 잡고, 연속 동작은 특정 순간으로 좁힌다.

## 4. 랜덤 문법: 일관된 연출 묶음을 선택

NovelAI 랜덤 문법은 `||선택지1|선택지2|선택지3||`다. 태그 여러 개나 짧은 문장도 한 선택지로 묶을 수 있다. 외형·의상·인물 수·행동 주체는 임의로 랜덤화하지 않는다.

서로 의존하는 **눈 상태+시선+입 상태+고개/구도**를 한 선택지 안에 묶는다. 눈·시선·입을 각각 랜덤화해서 충돌을 만들지 않는다. 가중치 구문도 선택지 안에서 완결한다.

```text
close-up, face focus, ||laughing, closed eyes, open mouth, facing viewer|light smile, closed mouth, looking at viewer, head tilt||
```

이는 얼굴 중심 웃음 변형의 문법 예시이며 생성 성공을 확인한 프리셋은 아니다. 서로 다른 캐릭터 슬롯의 랜덤 선택은 동기화된다고 가정하지 않는다. Seed를 고정해도 선택지가 바뀔 수 있으므로 재현 시 실제 선택된 프롬프트를 기록한다.

## 5. source# / target# / mutual#

접두사는 **각 Character Prompt에서 그 인물의 행동 역할**을 표시한다. `#` 뒤는 행동이며 캐릭터 이름이나 번호가 아니다.

| 연출 | Character A | Character B |
|---|---|---|
| A가 B를 안음 | `girl, source#hug` | `girl, target#hug` |
| A가 B에게 안김 | `girl, target#hug` | `girl, source#hug` |
| 서로 안음 | `girl, mutual#hug` | `girl, mutual#hug` |

Base에는 전체 수(`2girls` 등)와 공통 장면을 넣고, 각 인물에는 숫자 없는 `girl`, `boy`, `other`와 해당 인물의 특징을 넣는다. A/B는 설명용 라벨이다. `target#B`, `target2#hug` 같은 임의 대상 지정 문법을 만들지 않는다.

같은 행동명을 양쪽에 쓰는 것을 기본으로 하되, 공식 문서의 `source#pointing at another` / `target#pointing`처럼 비대칭 예도 있다. wiki에 행동 태그가 존재하는 것과 해당 NovelAI 방향성 조합이 잘 작동하는 것은 별개다. 역할 표시는 감정·동의·성격을 지정하지 않는다.

3명 이상이면 같은 행동의 대상이 모호해질 수 있다. 위치와 짧은 자연어로 보완하되 특정 쌍 연결을 보장하지 않는다. 순수 얼굴 감정 컷에는 상호작용 문법이나 두 번째 인물을 억지로 추가하지 않는다.

V4/V4.5에서 단일 텍스트 입력이 필요하면 `2girls | girl, source#hug | girl, target#hug`처럼 분리할 수 있다. 전용 Character Prompt 입력란과 이 구분 방식을 혼용하지 않는다. 랜덤 구간의 `||...||`와 인물 구분용 단일 `|`를 구별한다.

## 6. 가중치·제외 항목·납품 검수

가중치 없이 시작하고 필요한 얼굴 특징·감정만 소폭 강조한다. `1.1~1.3`은 실무 시작값이지 공식 최적값이 아니다. 강한 가중치로 충돌을 덮지 않는다. 음수 수치 강조는 V4.5 이상에서 사용하며 특정 감정의 정확한 반대를 보장한다고 설명하지 않는다.

감정 클로즈업의 UC에 `close-up`, `portrait`, `cropped shoulders`를 관성적으로 넣지 않는다. 눈물·텍스트 등 요청한 요소를 UC에서 동시에 억제하지 않는다. 품질 프리셋과 중복되는 긴 제외 목록은 줄인다.

기존 JSON 작업에서는 키·모드·이름·순서·성별 슬롯을 유지하고, 앱의 프롬프트 조립 방식에서 랜덤 구문이 보존되는지 확인한다. 백업은 앱이 읽는 프리셋 목록 밖에 둔다. 감정 프리셋의 앱 내부 `pov` 모드 이름을 실제 프롬프트의 POV 요청으로 오해하지 않는다.

제출 전 랜덤 분기를 펼쳐 시선·입 상태·크롭·접촉 충돌과 가중치 닫힘을 검사한다. 검증된 태그와 자연어 보완, 정적 검수와 실제 이미지 생성 검수를 구분해 보고한다. 텍스트 블록과 seed만으로 외형·포즈의 완전한 일관성을 보장하지 않는다.
