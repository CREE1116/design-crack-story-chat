## 적용 범위

[crack-prompt-rules.md](crack-prompt-rules.md)의 `이미지 규칙`은 **완성된 이미지를 프롬프트에서 어떻게 부르는가**를 정한다. 이 문서는 **그 이미지를 실제로 어떻게 만드는가**를 정한다.

이미지 프롬프트는 손으로 관리하는 자료가 아니라 **파생 산출물**이다. `build/assets/image-prompts.md`(사람이 읽는 시트)와 `build/assets/prompts.json`(기계용)으로 매 컴파일마다 다시 생성하며, 외형 문구는 `characters.md`의 `Appearance`에서만 파생한다. 어느 한쪽을 직접 고치는 순간 인물의 외형에 주인이 둘이 된다. 둘은 같은 축 이름을 공유해야 하며, 축이 어긋나면 규칙은 맞는데 파일이 없는 상태가 된다.

**이 스킬은 이미지를 생성하지 않는다.** 어떤 도구로 그릴지는 제작자가 정하며, 생성기는 몇 달 단위로 바뀐다. 스킬이 책임지는 것은 생성기와 무관하게 유지되는 두 가지다 — 프롬프트가 무엇을 요구하는지, 그리고 만들어진 파일이 그 요구와 맞는지.

이미지는 항상 선택 사항이다. 이미지가 한 장도 없어도 텍스트만으로 플레이가 성립해야 한다. 이 조건을 못 지키면 자산 제작이 출시를 막는다.

## 축을 먼저 닫는다

축 조합은 곱셈이다. 프롬프트를 쓰기 전에 각 축의 값 목록을 닫는다.

```text
인물 15 × 상황 6 = 90장
장면 6 + 배경 6 + 위협 6 = 18장
합계 108장
```

- 상황 축은 6개 안팎에서 멈춘다. 7번째 상황은 인물 수만큼 곱해져 들어온다.
- 축 값은 짧고 안정된 ASCII 슬러그로 정하고 표시용 이름을 병기한다. 슬러그는 URL·출력 경로·프롬프트 자산에서 **같은 문자열**이어야 한다.
- 축을 닫은 뒤에도 부분 커버리지를 전제한다. 90장 중 12장만 만들어도 출시 가능해야 한다.

### 폴더 골격은 컴파일 산출물이다

축이 닫히는 순간 **어떤 파일이 어디에 들어가야 하는지가 전부 확정된다.** 그림을 한 장도 그리기 전에 알 수 있는 정보다. 그러므로 폴더 골격과 배치표는 사람이 손으로 만들 것이 아니라 컴파일 단계가 생성해야 한다.

사람이 폴더 이름을 타이핑하면 반드시 오타가 나고, 오타는 **조용한 깨진 링크**가 된다. 오류도 로그도 없이 플레이 중 이미지가 안 뜨는 것으로만 나타난다. 자동 생성은 이 실패 경로를 통째로 없앤다.

생성할 것:

- 축 목록대로의 빈 폴더 전부
- 폴더마다 그 안에 들어갈 **정확한 파일 이름 목록**과 각 자리의 뜻·권장 해상도
- 전체 배치표 한 장 — 어느 자리가 채워졌고 어디가 비었는지

배치표는 다시 실행할 때마다 채움 상태를 갱신해 진행 현황판이 되게 한다. 그림을 외주하거나 직접 그리는 경우, 이 목록이 곧 작업 지시서다.

프롬프트의 축 목록·생성 도구의 자산 목록·디스크의 폴더 이름은 **한 곳에서 파생된 같은 문자열**이어야 한다. 세 곳에서 따로 관리되는 순간 갈라진다.

## 프롬프트 자산은 계층으로 조립한다

한 장의 프롬프트를 통째로 쓰지 않는다. 다음 계층을 조립한다.

```text
품질 프리픽스 + 그림체 프리셋 + 베이스(축1) + 모디파이어(축2) + 공통 서픽스
네거티브 = 공통 네거티브 + 종류별 추가 네거티브
```

| 계층 | 역할 | 개수 |
|---|---|---|
| 품질 프리픽스 | 모델 계열이 요구하는 관용 태그 | 계열당 1 |
| 그림체 프리셋 | 작품 전체의 화풍 | 2~3 |
| 베이스 | 인물·장면·배경·위협 각각의 고정 특징 | 축1 값 수 |
| 모디파이어 | 상황·감정·조명 | 축2 값 수 |
| 공통 서픽스 | 구도·화질 마감 | 종류당 1 |
| 네거티브 | 배제 태그 | 공통 1 + 종류별 추가 |

계층으로 나누는 이유는 **그림체를 바꿀 때 한 줄만 고치기 위해서**다. 프롬프트를 통째로 쓰면 화풍 변경이 전수 수정이 된다.

베이스에는 변하지 않는 것만 넣는다. 현재 감정·부상·위치는 모디파이어의 몫이다. 이 경계는 `characters.md`의 `Appearance`가 "변하는 값을 제외한다"고 규정한 것과 같은 규칙이다.

## 모델 계열이 프롬프트 방언을 결정한다

체크포인트 **이름**이 아니라 **계열**이 프롬프트 문법을 정한다. 이름만 보고 프리셋을 고르면 안 된다.

| 계열 | 품질 프리픽스 | 본문 표기 |
|---|---|---|
| Illustrious / NoobAI | `masterpiece, best quality, amazing quality` | 단부루 태그 |
| Pony | `score_9, score_8_up, score_7_up` **필수** | 단부루 태그 |
| SDXL / Animagine 계열 | 가벼운 품질어 | 태그와 자연어 혼용 |
| Flux 계열 | 없음 | 완전한 자연어 문장 |

- 계열을 잘못 적용하면 조용히 품질만 떨어진다. 오류가 안 나므로 발견이 늦다.
- 그러므로 품질 프리픽스는 **설정 파일의 교체 가능한 프리셋**으로 두고, 프롬프트 본문에 하드코딩하지 않는다.
- 같은 이름의 모델이 EPS 판과 V-Pred 판으로 나뉘어 배포되는 경우가 있다. 이 둘은 실행 환경 요구가 다르므로 파일명·배포 페이지에서 어느 쪽인지 확인하고 기록한다.

## 캐릭터 일관성

- 외형 앵커는 `characters.md`의 `Appearance`에서 가져온다. 이미지 자산 파일에서 따로 새로 쓰면 두 문서가 갈라지고, 갈라진 사실은 반드시 나중에 충돌한다.
- **베이스의 첫 두세 태그가 그 인물의 식별 포인트여야 한다.** 뒤쪽 태그는 가중치가 낮아 묻히고, 썸네일 크기에서는 미묘한 차이가 전부 사라진다. 베이스 목록을 위에서 아래로 훑었을 때 앞부분만 읽어도 서로 다른 인물임이 드러나지 않으면, 생성된 이미지도 서로 닮는다.
- 인물 수만큼 베이스를 다 쓴 뒤 **명부 단위로 한 번 검토한다.** 개별로 보면 다 그럴듯한데 나란히 놓으면 절반이 같은 사람인 경우가 흔하다.
- 인물별 시드를 고정하면 같은 인물의 상황 변형끼리 닮는다. 시드는 자산 파일에 기록한다.
- 그래도 조합 생성만으로는 동일 인물성이 완전히 유지되지 않는다. 정확한 재현이 필요하면 로라 학습을 전제하고, 학습용 데이터셋 축을 별도로 둔다.

전용 모델을 학습시키는 경로를 택한다면 학습셋은 **변형 축을 넓게** 잡는다. 서로 닮은 이미지 열두 장은 과적합을 보장한다. 학습 과정은 이 스킬의 범위 밖이며 쓰는 도구의 문서를 따른다.

## 배포는 축 계약을 검사하는 마지막 지점이다

프롬프트는 축의 **닫힌 목록**을 싣고 모델은 그 목록 안에서만 슬러그를 조합한다. 그러므로 실제 파일 이름이 목록과 한 글자라도 다르면 그 조합은 영원히 깨진 링크다. 그리고 이 불일치는 **플레이 중에는 조용히 이미지가 안 뜨는 것으로만 나타나** 원인을 찾기 어렵다.

파일을 올리는 순간이 이 계약을 기계로 검사할 수 있는 마지막 지점이다. 업로드 도구는 업로드 전에 반드시 검사한다.

검사할 것:

| 항목 | 조치 |
|---|---|
| 축 목록에 없는 슬러그의 파일 | **중단.** 오타이거나 축 목록이 낡았다 |
| 축 목록에 있는데 없는 파일 | 통과. 부분 커버리지는 정상이다 |
| 확장자·경로 구조 불일치 | 중단 |
| 과도하게 큰 파일 | 중단 또는 경고 |

없는 파일을 실패로 취급하면 안 된다. 프롬프트가 "조합이 없으면 그 자리만 생략"을 이미 규정하므로 **부분 배포가 정상 상태**다. 반대로 목록에 없는 파일은 반드시 막는다. 그것은 프롬프트와 자산이 갈라졌다는 신호다.

### 호스팅

정적 파일이면 무엇이든 되지만 다음을 확인한다.

- **핫링크가 허용되는가.** 이미지 호스트 상당수가 외부 페이지에서의 직접 참조를 막는다.
- **주소가 축 구조를 그대로 표현할 수 있는가.** 업로드마다 임의 ID를 발급하는 호스트는 조합 주소 방식과 맞지 않는다. 그런 호스트를 쓰면 에셋 목록을 프롬프트에 나열해야 하고, 조합 주소로 아꼈던 글자 예산이 사라진다.
- **캐시 수명.** CDN을 끼면 갱신이 즉시 반영되지 않는다. 이미지를 교체할 때는 불변 태그·버전 경로를 쓰거나 캐시 무효화 수단을 확인한다.

배포 도구는 마지막에 **프롬프트에 넣을 기준 주소 한 줄**을 출력한다. 사람이 주소를 손으로 조립하면 축 구조가 틀어진다.

### 배포 후 표본 확인

푸시했다고 서빙되는 것은 아니다. 배포 직후 몇 개를 실제로 요청해 200이 오는지 확인한다. CDN은 첫 요청 때 원본을 가져오므로 잠깐 404가 날 수 있고, 그 구분을 도구가 알려줘야 한다.

## 환경 문제와 자산 문제를 분리한다

이미지가 안 나올 때 프롬프트부터 의심하면 시간을 크게 버린다. 먼저 범위를 가른다.

| 증상 | 결론 |
|---|---|
| 모든 모델에서 실패 | 환경 문제. 프롬프트·모델은 무관 |
| 특정 모델만 실패 | 모델 계열·설정 불일치 |
| 특정 조합만 실패 | 자산·슬러그 문제 |

범위를 가른 뒤 **최소 재현**으로 좁힌다. 확장 기능·로라·리파이너·업스케일을 전부 끄고 기본 해상도로 한 장을 뽑는다. 여기서 정상이면 하나씩 되돌리며 범인을 찾는다.

관리가 멈춘 실행기는 신형 하드웨어에서 조용히 실패한다. 낡은 수치 라이브러리를 고정해둔 도구가 새 칩에서 NaN을 뱉는 식이며, 증상은 "모든 모델에서 노이즈"로 나타나 프롬프트를 아무리 고쳐도 소용이 없다. 그래서 범위 가르기가 먼저다.

자산 제작 환경 문제는 **작품과 분리된 인계 사항**이다. 스토리챗 빌드 5종은 이미지가 0장이어도 검증을 통과해야 하며, 이미지 생성이 막혔다는 이유로 빌드를 미루지 않는다.

## 금지 패턴

- 축을 닫지 않은 채 프롬프트를 쓰기 시작한다.
- 그림체 문자열을 수십 개 프롬프트에 복사해 넣는다.
- 외형 앵커를 `characters.md`와 이미지 자산 파일에서 따로 관리한다.
- 체크포인트 이름만 보고 품질 프리픽스를 고른다. 계열이 문법을 정한다.
- 이미지가 없으면 응답이 성립하지 않는 출력 규칙을 쓴다.
- 이미지에 핵심 규칙·정사·판정 근거를 싣는다.
