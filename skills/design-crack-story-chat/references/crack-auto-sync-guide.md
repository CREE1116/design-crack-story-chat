# 크랙(Crack) 플레이라이트 자동 동기화 가이드 (Crack Auto-Sync Guide)

`tools/sync/crack_sync.py`는 로컬에서 빌드한 산출물(프롤로그, 시작 프롬프트, 7,000자 시스템 프롬프트, 15~20개 키워드북 항목, 단축어, 상세설명)을 **크랙(Crack) 웹 에디터 폼에 단 몇 초 만에 100% 자동 주입하는 Playwright 기반 브라우저 자동화 도구**입니다.

수십 번의 클릭과 복사-붙여넣기 노가다를 없애고, 브라우저를 띄워둔 채 실시간으로 프롬프트를 고치며 핫리로드할 수 있는 대화형 세션을 제공합니다.

## 1. 왜 비공식 API 대신 Playwright 자동화인가?

1. **🛡️ 계정 안전성 (약관 위반 및 제재 원천 차단)**:
   - 비공식 내부 API 직접 호출은 WAF(웹 방화벽) 봇 감지 및 계정 영구 정지(밴) 위험이 있습니다.
   - Playwright는 **사용자가 실제 로그인한 브라우저 화면에서 실제 타이핑/클릭 동작으로 폼을 채우므로** 가장 안전합니다.
2. **👀 실시간 육안 검토 (Headed Mode 기본 지원)**:
   - 브라우저 창이 직접 열려 각 필드가 채워지는 과정을 눈으로 확인할 수 있으며, 최종 저장/발행 전에 작가가 직접 검토할 수 있습니다.
3. **⚡ 60회 이상의 복붙 노동 종결**:
   - 20개에 달하는 키워드북 제목/키워드/본문, 단축어, 시스템 프롬프트를 일일이 손으로 등록하던 고통을 명령어 1줄로 끝냅니다.

## 2. 3단계 초간단 빠른 시작

### 1단계: 사전 준비 (Playwright 설치)
최초 1회만 실행하여 Playwright 패키지와 Chromium 브라우저 바이너리를 설치합니다.
```bash
# uv를 사용하는 경우 (권장)
uv run --with playwright python -m playwright install chromium

# 일반 pip 환경인 경우
pip install playwright && playwright install chromium
```

### 2단계: 1회 로그인 세션 캡처 (`auth`)
크랙 계정의 로그인 상태를 로컬(`~/.crack/auth_state.json`)에 안전하게 저장합니다. (쿠키/세션이 만료되기 전까지 재로그인 불필요)
```bash
uv run --with playwright python tools/sync/crack_sync.py auth
```
1. Chromium 브라우저가 열리면 크랙(Crack)에 로그인합니다.
2. 로그인이 완료되어 메인 화면이 뜨면, **터미널로 돌아와 `[Enter]` 키를 누릅니다.**
3. 세션 저장이 완료되고 브라우저가 닫힙니다.

### 3단계: 크랙 에디터 자동 주입 (`sync`)

#### 🐣 A. 신규 스토리를 처음 만들 때 (프로젝트 ID가 아직 없을 때)
**URL 옵션(`--url`)을 넣지 않고 그냥 실행합니다.** 크랙 스튜디오로 이동하여 자동으로 **[내 작품 ➡️ 작품 만들기 ➡️ 스토리]**를 클릭해 새 에디터 창으로 진입합니다!
```bash
uv run --with playwright python tools/sync/crack_sync.py sync examples/hunter --variant safe
```

#### 🔄 B. 이미 만들어둔 기존 프로젝트를 불러와 수정할 때 (로드 & 재동기화)
이미 생성된 프로젝트가 있다면, **해당 프로젝트의 에디터 URL을 전달하여 바로 로드**합니다.
```bash
uv run --with playwright python tools/sync/crack_sync.py sync examples/hunter \
  --url "https://crack.wrtn.ai/studio/projects/내프로젝트ID" \
  --variant safe
```
* 브라우저가 열리고 크랙 에디터 페이지로 이동합니다.
* 터미널에 **대화형 제어 메뉴**가 표시됩니다.

## 3. 산출물 사전 검사 (`inspect`)

브라우저를 띄우기 전에 로컬 빌드 파일들이 정상적으로 파싱되는지 미리 확인할 수 있습니다.
```bash
python3 tools/sync/crack_sync.py inspect examples/hunter --variant safe
```
* 프롤로그, 시작 프롬프트, 7,000자 시스템 프롬프트 글자 수 및 앞/뒤 요약 출력
* 키워드북 등록 항목 수(19개)와 제목/키워드/본문 파싱 상태 확인
* 단축어 항목 및 상세설명(`story-description.md`) 로드 상태 확인

## 4. 브라우저 상주 & 대화형 핫리로드 세션 활용법

`sync` 명령을 실행하면 **브라우저가 닫히지 않고 열린 상태를 유지**하며 터미널에 대화형 컨트롤러가 뜹니다:

```text
===========================================================================
🎮 [Interactive Mode] 원하는 작업을 선택하세요:
===========================================================================
  [a / Enter] 전체 탭 자동 순회 및 일괄 주입 (프롬프트+키워드북+단축어+상세설명)
  [p] 프롬프트 탭만 주입 (프롤로그 / 시작 프롬프트 / 시스템 프롬프트)
  [k] 키워드북 탭만 일괄 주입 (기존 항목 정리 후 15~20개 재등록)
  [s] 단축어(Shortcuts) 탭만 주입
  [g] [등록] 탭만 주입 (상세 설명 · 장르 · 타겟 · 대화 형태 · 권장 모드 · 출력량 · 해시태그)
  [v] 시스템 프롬프트 SAFE ↔ UNSAFE 실시간 전환
  [r] 로컬 파일 다시 읽기 (Hot-Reload: 코드 수정 후 즉시 재반영)
  [d] 현재 브라우저 DOM 구조 분석 (디버깅용)
  [q] 세션 종료 및 브라우저 닫기
===========================================================================
👉 명령을 입력하세요:
```

### 💡 실전 작가 워크플로우
1. **원클릭 일괄 주입**: 터미널에서 `[Enter]`만 치면 모든 탭을 순회하며 프롬프트와 키워드북 20개를 순식간에 채웁니다.
2. **코드 수정 후 즉시 반영 (핫리로드)**:
   - 에디터 화면을 보면서 로컬의 `story.md`나 `keyword-book.md`를 수정하고 빌드합니다.
   - 터미널에서 `r`(파일 리로드) ➡️ `p`(프롬프트만 재주입)를 누르면 **브라우저를 껐다 켤 필요 없이 1초 만에 최신 프롬프트로 덮어씌워집니다.**
3. **수위 버전 스위칭 (`v`)**:
   - `v`를 누르면 `SAFE` ↔ `UNSAFE` 버전으로 즉시 토글되어 프롬프트를 교체 주입합니다.
4. **수동 검토 및 안전 저장**:
   - 주입이 끝나면 브라우저 화면에서 스크롤하며 내용을 직접 확인하고 크랙의 [임시저장] 또는 [발행] 버튼을 누릅니다.

## 5. 자동 매핑 및 필드 주입 규격

`crack_sync.py`는 빌드 산출물을 크랙 웹 에디터의 각 탭과 필드에 1:1로 매핑합니다.

> **[시작 설정] 탭의 칸은 위치가 아니라 placeholder 문구로 찾습니다.** 보이는 `textarea` 순서로 잡으면 크랙이 칸을 하나 늘리거나 시작 세트를 추가하는 순간 전체가 한 칸씩 밀립니다. 실제로 프롤로그가 시작 상황 칸에, 시작 프롬프트가 플레이 가이드 칸에 들어간 사고가 있었습니다. 칸을 못 찾으면 **아무 데도 쓰지 않고 경고만** 냅니다 — 조용한 오주입보다 미주입이 낫습니다.

| 크랙 에디터 탭 / 필드 | 대상 소스 파일 | 주입 내용 및 규격 |
|---|---|---|
| **작품 제목 (Title)** | `story.md` (`- Title:`) | 스토리 공식 제목 |
| **한 줄 소개 (Logline)** | `story.md` (`- Logline:` / `- Premise:`) | 목록 카드용 로그라인 **(≤ 30자)**. 상세설명과 다른 필드다 — [story-description-guide.md](story-description-guide.md) 참조 |
| **프롤로그 (Prologue)** | `build/prologue.md` | ≤ 1,000자 도입부 서사. placeholder `자동 생성…초안` |
| **시작 상황 (Start)** | `build/start-prompt.md` | ≤ 1,000자 첫 턴 상황 압력. placeholder `사용자의 역할…` |
| **플레이 가이드** | `build/assets/play-guide.md` | 플레이어용 안내판 ([play-guide.md](play-guide.md)). placeholder `사용자를 위한 가이드` |
| **추천 답변 (최대 3)** | `build/assets/recommended-replies.md` | `---` 로 구분한 최대 3블록. 없으면 건너뜀 |
| **시스템 프롬프트 (Core)** | `build/integrated-prompt-{safe/unsafe}.md` | ≤ 7,000자 코어 시스템 규칙 (`--variant`에 따라 선택) |
| **키워드북 (Keyword Book)** | `build/keyword-book-{safe/unsafe}.md` (우선) 또는 `build/keyword-book.md` | **기존 등록 항목 자동 삭제(초기화) 후** 새 항목 일괄 등록 (SAFE/UNSAFE 자동 분기) |
| **단축어 (Shortcuts)** | 위 키워드북 파일 (Shortcuts 섹션) | 기존 항목 정리 후 단축어 등록 (이름 앞 슬래시 자동 정제) |
| **작품 상세설명 (Description)** | `build/assets/story-description.md` | **[등록] 탭** `상세 설명` 칸 **(≤ 1,000자)**. 마크다운 3대 블록 (배너+통계표 + 플레이 가이드 & 단축어 + 제작자 코멘트) |
| **장르 · 타겟 · 대화 형태** | `story.md` (`- Genre:` · `- Target:` · `- Chat form:`) | [등록] 탭 콤보박스. 선택지 이름을 **글자 그대로** 적는다 (아래 5.6) |
| **권장 모드 · 권장 최대 출력량** | `story.md` (`- Recommended mode:` · `- Max output:`) | 모드는 `하이퍼챗 1.0` 처럼 선택지 첫 줄 이름, 출력량은 `기본`·`1.5x`·`3x`·`5x` (일괄 설정) |
| **해시태그** | `story.md` (`- Hashtags: 카멜롯, 아서왕, …`) | 기존 칩을 지우고 선언 순서대로 다시 넣는다. 최대 10개 · 한 개당 10자 |
| *(참고: 써머리 코멘트)* | `build/assets/summary-comment.md` | 발행 후 **고정 댓글**에 복사할 순수 텍스트 4대 블록 (캐릭터 소개 + 이미지 규칙 + 세계관 + 등급 기준) |

## 5.5. 실측으로 확인된 크랙 UI 제약

문서로 공개된 값이 아니라 **실제로 넣어 보고 확인한** 것들입니다. 추측한 값은 여기에 적지 않습니다.

| 항목 | 상한 | 넘기면 |
|---|:---:|---|
| 한 줄 소개 | 30자 | 목록 카드에서 잘림 |
| 플레이 가이드 | 500자 | 초과분이 경고 없이 사라짐 (마지막 블록이 통째로) |
| 시작 세트 | 3개 | [설정 추가] 버튼 자체가 사라짐 |
| 추천 답변 | 3개 | [추천 답변 추가] 버튼이 사라짐 |
| 키워드북 항목 | 20개 | 21번째부터 [키워드 노트 추가] 가 `disabled` 로 바뀐다. 클릭 타임아웃만 반복되고 이유는 화면에 나타나지 않는다 |
| 미등록(임시저장) 작품 | 5개 | 더 만들 수 없음. 스토리·캐릭터 각각 5개 |
| 상세 설명 | 1,000자 | textarea `maxlength=1000` 이 초과분을 잘라 먹는다 |
| 해시태그 | 10개 · 한 개당 10자 | 입력칸 `maxlength=10`. 긴 태그는 조용히 잘린다 |

**프롤로그 칸에는 placeholder 가 없습니다.** 화면의 "자동 생성 기능을 활용하면…" 문구는 옆 [자동 생성] 버튼의 도움말이지 그 칸의 속성이 아닙니다. 그래서 이 칸만 문구로 찾을 수 없고, 시작 상황 칸을 앵커로 삼아 바로 앞 칸을 씁니다.

**세트가 이미 있는 작품을 다시 싱크할 때는 [설정 추가] 를 누르면 안 됩니다.** 상한에 걸려 버튼이 없고, 없는 채로 진행하면 앞 세트를 덮어씁니다. 제목이 같은 탭을 먼저 눌러 그 세트로 들어갑니다.

### 프로필 단계를 끝내야 작품이 생긴다

크랙의 신규 생성은 마법사입니다. `작품 만들기` 로 들어가 바로 값을 채워도 **작품 레코드가 없습니다.** 프로필 단계(대표 이미지·이름·한 줄 소개)를 채우고 **[다음] 을 눌러야** URL 에 `storyId` 가 붙고 그때부터 저장 대상이 생깁니다.

그전에 [임시저장] 을 누르면 **조용히 무시됩니다.** 버튼은 눌린 것처럼 보이고 오류도 나지 않습니다. 새로고침하면 넣은 값이 전부 사라집니다.

```
작품 만들기 → 스토리 선택 → [프로필: 이미지·이름·소개] → [다음]  ← 여기서 storyId 발급
                                                            → 나머지 탭 주입 → 임시저장
```

동기화 도구는 주입 순서 맨 앞에서 이 단계를 밟고, `storyId` 가 붙었는지 확인한 뒤에야 나머지를 넣습니다.

임시저장한 작품은 [내 작품] 의 **`미등록` 필터**에 들어갑니다. 전체 목록에는 보이지 않으므로, 저장됐는지 눈으로 확인하려면 그 필터를 봐야 합니다. 미등록은 5개까지만 둘 수 있어 시험 삼아 만든 것을 치우지 않으면 금방 막힙니다.

### 임시저장에는 대표 이미지가 필요하다

크랙은 프로필 탭의 **`이미지 *` 가 비면 [임시저장] 을 거부**합니다. 버튼은 눌린 것처럼 보이고 화면에는 안내 문구만 뜨므로, **로그만 보면 저장된 줄 압니다.** 실제로 그렇게 여러 번 작업을 잃었습니다.

- **규격**: 1,080 × 1,620px 세로 비율, 5MB 이하. 가로 배너는 받지 않습니다.
- **GIF 를 올릴 수 있습니다.** 목록 카드에서 움직이므로 정지 이미지보다 눈에 띕니다. 같은 5MB 한도 안에서 프레임 수와 화질을 맞바꾸게 되니, 표지로 쓸 몇 초짜리 루프를 따로 만드는 편이 낫습니다.
- **업로드는 세 단계**입니다: `[업로드]` → `기기에서 가져오기` → 파일 선택 → **`[자르기]`**. 중간에 멈추면 모달이 화면에 남아 [임시저장] 버튼까지 가립니다.
- 동기화 도구는 `CRACK_SYNC_THUMBNAIL=<경로>` 로 이 셋을 자동으로 탑니다. 제목·한 줄 소개가 비어 있으면 저장 전에 채웁니다.

> "이미지를 필수로 등록해주세요" 는 **등록한 뒤에도 남아 있는 안내문**입니다. 이 문구의 유무로 등록 성공을 판정하면 안 됩니다.

### 저장됐는지는 새로고침으로만 안다

토스트는 몇 초 만에 사라져 놓치기 쉽고, `[role='alert']` 같은 선택자는 무관한 라이브 영역에도 걸려 **거짓 성공**을 냅니다. 믿을 수 있는 근거는 하나뿐입니다 — **새로고침한 뒤에도 값이 남아 있는가.** 동기화 도구는 저장 후 페이지를 다시 읽어 제목이 남아 있는지 확인하고, 비어 있으면 저장되지 않았다고 말합니다.

### 칸을 못 찾으면 화면을 찍는다

동기화 도구는 칸이나 버튼 탐색에 실패하면 그 자리에서 **현재 화면의 입력 칸과 버튼을 전부 덤프**합니다(태그, `placeholder`, `data-placeholder`, `aria-placeholder`, `aria-label`, 현재 글자 수, 버튼 비활성 여부, 화면의 오류 문구). 상주 세션에서는 `d` 명령으로도 같은 것을 볼 수 있습니다.

덤프로도 모르겠으면 `CRACK_SYNC_SHOT=<경로.png>` 를 주면 실패 순간의 **화면을 그대로 캡처**합니다. 임시저장이 왜 거부되는지는 결국 이 캡처로 밝혀졌습니다 — 필수 이미지 칸이 비어 있다는 것은 DOM 속성 어디에도 나타나지 않고 화면에만 보였습니다.

placeholder 를 짐작해 셀렉터를 고치고 다시 돌리는 왕복 대신, **한 번 실패하면 사실이 나옵니다.** 위의 제약 세 가지가 전부 이 덤프로 밝혀졌습니다.

### 5.6. 상세 설명과 등록 설정은 [등록] 탭에 있다

탭 줄 맨 끝의 **`등록 *` 탭**(`step=register`)에 상세 설명 · 장르 · 타겟 · 대화 형태 · 권장 모드 · 권장 최대 출력량 · 해시태그 · 이용자 층이 모여 있습니다. 좁은 창에서는 이 탭이 가려져 보이지 않으므로, 도구는 탭을 못 찾으면 URL 의 `step` 만 `register` 로 바꿔 같은 작품에 머뭅니다. 예전 도구는 [엔딩 설정] → [다음] 화면에서 상세 설명 칸을 찾다가 매번 "textarea 를 찾지 못했습니다" 로 끝났습니다 — 그 화면에는 칸이 없습니다.

**상단의 [등록하기] 버튼은 누르지 않습니다.** 탭 이름과 글자가 겹치지만 발행 흐름입니다. 필수값이 비어 있으면 "스토리를 등록할 수 없어요" 팝업만 뜨고, 다 차 있으면 발행으로 넘어갑니다. 등록 탭의 값도 [임시저장] 으로 저장됩니다.

선택지 (2026-09-16 실측 — 크랙이 바꾸면 `inspect` 가 "없는 선택지" 로 알려줍니다):

| 칸 | story.md | 선택지 |
|---|---|---|
| 장르 설정 | `- Genre:` | 로맨스 · 로판 · SF/판타지 · 일상/현대 · 무협 · 시대 · BL · GL · 2차 창작 · 유틸리티 · 기타 |
| 타겟 설정 | `- Target:` | 남성향 · 여성향 · 전체 |
| 대화 형태 설정 | `- Chat form:` | 1:1 롤플레잉 · 시뮬레이션 |
| 권장 모드 | `- Recommended mode:` | 페이블챗 1.0 · 하이퍼챗 3.0/2.0/1.5/1.0 · 슈퍼챗 3.0/2.5/2.0 · 프로챗 2.5/1.0 · 파워챗 (요금·모델 구성은 크랙이 수시로 바꾼다) |
| 권장 최대 출력량 | `- Max output:` | 기본 · 1.5x · 3x · 5x (일괄 설정) |

- **선택지는 첫 줄 이름으로만 맞춥니다.** 권장 모드 선택지에는 `하이퍼챗 1.0` 뒤에 가격(`102개`)과 설명이 붙어 있어, 전체 글자로 비교하면 `슈퍼챗 2` 가 `슈퍼챗 2.5` 에 걸립니다. 고른 뒤에는 칸을 다시 읽어 실제로 바뀌었는지 확인합니다.
- **해시태그는 칩입니다.** 단어를 치고 엔터를 누르면 칩이 하나 생기고, 칩마다 삭제 버튼이 붙습니다. 도구는 기존 칩을 모두 지운 뒤 선언 순서대로 다시 넣고, 칩 목록을 읽어 선언과 같은지 확인합니다. 선언하지 않으면 크랙이 자동으로 채운 태그를 그대로 둡니다.
- **이용자 층은 도구가 설정하지 않습니다.** 크랙이 "이용자 층은 한번 설정하면 변경할 수 없어요" 라고 못박은 항목입니다. `- Audience:` 를 적어도 도구는 알림만 내고, 고르는 것은 사람이 합니다. 되돌릴 수 없는 값을 자동화가 대신 정하면 안 됩니다.
- **선언하지 않은 칸은 건드리지 않습니다.** 작가가 에디터에서 직접 고른 값을 싱크가 덮어쓰지 않게 하려는 것입니다.

### 표지 검사는 [프로필] 탭에서만 된다

표지 칸과 [업로드] 버튼은 [프로필] 탭에만 있습니다. 전체 주입이 끝나면 화면은 [등록] 탭에 머물러 있어, 그 자리에서 표지가 비었는지 검사하면 업로드 버튼이 없으니 "대상 아님" 으로 판정하고 넘어갑니다. 실제로 신규 작품이 표지 없이 저장됐습니다. 도구는 `CRACK_SYNC_THUMBNAIL` 이 있으면 저장 직전에 [프로필] 탭을 먼저 엽니다.

업로드 모달의 `기기에서 가져오기` 는 제목·설명 두 줄이 든 **버튼**입니다. `:text('기기에서 가져오기')` 로 잡으면 안쪽 글자 노드를 눌러 파일 선택창이 열리지 않으므로 `button` 으로 잡습니다.

> 2026-09-16 재실측: 프로필 단계를 통과해 `storyId` 가 발급된 작품은 **표지가 비어 있어도 [임시저장] 이 "임시저장이 완료되었어요" 로 끝나고 새로고침 뒤에도 값이 남았습니다.** 위 "임시저장에는 대표 이미지가 필요하다" 는 프로필 단계 이전의 관찰로 보이며, 어느 조건에서 거부되는지는 아직 확인하지 않았습니다. 표지는 목록 카드와 [등록하기] 검증에 필요하므로 어느 쪽이든 올려 둡니다.

## 7. 문제 해결 및 실전 꿀팁 (FAQ)

### Q1. "로그인이 풀려있거나 에디터 페이지로 이동하지 않아요."
* 크랙 웹사이트의 세션 쿠키가 만료된 경우입니다. `auth` 명령어를 다시 실행해 로그인 세션을 갱신하세요:
  ```bash
  uv run --with playwright python tools/sync/crack_sync.py auth
  ```

### Q2. "특정 탭에서 폼을 찾지 못하거나 입력이 멈춰요."
* 크랙의 UI 레이아웃이 변경되었거나 네트워크 렉으로 모달이 늦게 뜬 경우입니다.
* 터미널에서 `d` (DOM summary)를 입력하면 현재 브라우저 페이지의 버튼, 텍스트박스, 탭 목록을 콘솔에 덤프해 줍니다. 이를 통해 어떤 요소가 화면에 떠 있는지 즉시 진단할 수 있습니다.

### Q3. "발행 전 최종 확인은 어떻게 하나요?"
* 기본 모드가 **Headed(브라우저가 눈에 보임)** 모드이므로, 자동 주입이 완료된 후 브라우저 창에서 직접 마우스로 스크롤하며 내용을 점검할 수 있습니다.
* 확인이 끝난 뒤 크랙의 [발행하기] 버튼을 누르고, 터미널에서 `q`를 입력해 깔끔하게 세션을 종료하면 됩니다.
