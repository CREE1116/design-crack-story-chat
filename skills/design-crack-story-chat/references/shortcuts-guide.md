# 크랙(Crack) 단축어(Shortcuts) 설계 및 제작 가이드

> [!NOTE]
> **단축어는 필수 산출물이 아닌 '선택 사항(Optional)'입니다.**  
> 모든 스토리챗 프로젝트에 단축어를 의무적으로 넣을 필요는 전혀 없으며, 단축어가 0개여도 프로젝트의 완성도와 유효성(Validation)에는 아무런 지장이 없습니다.  
> 작품 특성상 특수한 편의 기능(경영 장부 확인, 시간 스킵, 대화 요약, OOC 교정 등)이 유용하다고 판단될 때만 선별적으로 도입하는 **부가 인터랙션 도구**입니다.

단축어(Shortcuts)는 플레이어가 채팅창에서 버튼 클릭 한 번(또는 `/단축어` 명령어)으로 AI에게 특수 지시를 내리는 **1회성 인터랙션 컨트롤러**입니다.

메인 프롬프트(7,000자)와 키워드북(400자)이 AI의 자율적인 롤플레잉 연출을 담당한다면, **단축어는 플레이어가 시스템의 흐름을 직접 조율하고, 서사의 템포를 바꾸며, 탈선을 바로잡는 '플레이어 권능의 리모컨'** 역할을 수행합니다.

## 1. 핵심 작동 원리: 단축어 3대 분류 체계

단축어는 플레이어가 요구하는 목적에 따라 **3가지 유형**으로 명확히 구분하여 설계합니다.

```
                  ┌─ ① 메타형 (외부 관찰 / 데이터 출력 / 캐릭터 비인지)
사용자 요청 ──────┼─ ② 서사형 (직접 사건 / 롤플레잉 전개 / 캐릭터 인지)
                  └─ ③ 기능형 (문체 변경 / 사칭 교정 / 캐릭터 비인지)
```

### ① 메타형 (Meta)
* **목적**: 외부 관찰자 시점의 데이터 출력 (상태창, 익명 커뮤니티 반응, 히든 속마음 지표 등)
* **3대 불변 규칙**:
  1. **반드시 코드블럭(` ``` `) 출력 형식 포함**: UI 화면을 시각적으로 재현.
  2. **"롤플레이(RP) 중단, 데이터만 출력" 명시**: 불필요한 소설 서술문 배제.
  3. **캐릭터가 인지하지 못함(비인지) 명시**: 작중 인물들은 이 화면이나 수치를 볼 수 없음.

### ② 서사형 (Narrative)
* **목적**: 캐릭터에게 직접적인 사건, 돌발 위기, 시간 경과(타임스킵), 심리적 계기 부여
* **3대 불변 규칙**:
  1. **코드블럭 완전 배제**: 시스템 메시지 느낌을 지우고 마크다운 소설 서술로 전개.
  2. **소설 서술문처럼 자연스럽게 롤플레이 전개**: 인물의 호흡, 시선, 대사가 이어짐.
  3. **캐릭터가 사건을 직접 인지하고 겪음**: 일어난 상황에 대해 인물이 직접 반응.

### ③ 기능형 (Utility)
* **목적**: 문체 변경(하드보일드, 라노벨체), AI 유저 사칭 교정, 프롬프트 점검 등 편의 기능
* **3대 불변 규칙**:
  1. **캐릭터 비인지 명령어**: 메타 지침으로서 모델의 출력 엔진만 제어.
  2. **규칙 및 제약 적용**: 톤앤매너나 금지 규칙을 즉시 덮어씌움.
  3. **출력 형식은 선택적**: 필요시에만 최소한의 안내 문구 출력.

---

### 유형별 핵심 차이 비교표

| 비교 항목 | 메타형 (예: `/상태창`) | 서사형 (예: `/돌발위기`) | 기능형 (예: `/사칭교정`) |
|---|---|---|---|
| **출력 코드블럭** | **있음 (` ``` `)** | **없음 (소설 서술문)** | 선택적 (대부분 없음) |
| **롤플레이(RP)** | **즉시 중단** (데이터만) | **자연스럽게 계속 전개** | 룰 재조정 후 계속 |
| **캐릭터 인지** | ❌ **비인지 (모름)** | ⭕ **인지 (직접 겪음)** | ❌ **비인지 (모름)** |
| **핵심 용도** | 현황 요약, 커뮤니티, 속마음 | 타임스킵, 위기 점화, 스킨십 텐션 | 사칭 방지, 문체 전환 |

> 💡 **메타형과 서사형의 가장 결정적인 차이는 "캐릭터 인지 여부"입니다.**  
> 메타형은 캐릭터는 모르는 '시스템 데이터'이며, 서사형은 캐릭터가 현실로 마주하는 '사건'입니다.

## 2. 필수 출력 형식 및 플랫폼 규격

모든 단축어는 크랙 웹 에디터의 엄격한 글자 수 제약을 따릅니다.  
`build/keyword-book.md`의 `# Shortcuts (단축어)` 섹션에 등록하면 자동 동기화 도구(`crack_sync.py`)가 100% 자동 등록합니다.

| 항목 | UI 제약 | 권장 길이 | 작성 목적 및 주의사항 |
|---|---|---|---|
| **슬러그 (ID)** | 영문/숫자/언더바 | 3~15자 | 코드 고유 식별자 (`community`, `fix_ooc` 등) |
| **이름 (Name)** | **≤ 10자** | **2~6자** | **⚠️ 절대 `/` 금지!** 크랙 UI가 클릭 시 자동으로 `/`를 붙여주므로 `상태창`, `커뮤니티`처럼 순수 텍스트로만 작성 (`//` 방지) |
| **설명 (Description)** | **≤ 30자** | **10~25자** | 버튼 하단 툴팁 (어떤 동작을 하는지 한눈에 요약) |
| **권장 등록 수** | 최대 20개 | **0~6개 (선택 사항)** | 꼭 필요한 경우에만 선별 등록하며, 0개여도 무방함 |

## 3. 단축어 작성 4대 핵심 원칙

1. **변수 적극 활용**: `{char}`(등장인물/상대방), `{user}`(플레이어) 변수를 명확히 기재하여 대상을 특정합니다.
2. **참조 명시**: 현재 RP 상황, 캐릭터의 숨겨진 성격/설정, 직전 사건 맥락을 참고하도록 지시합니다.
3. **간결성 (400자 엄수)**: 미사여구를 빼고 불릿 포인트(`-`)로 핵심 지시문만 고밀도 압축합니다.
4. **명확성 (실행 포맷 한정)**: `"3줄 이내 불릿으로"`, `"코드블럭만 출력"` 등 LLM이 즉시 실행할 수 있는 상한선을 겁니다.

## 4. 단축어 제작 5단계 프로세스

```
사용자 요청 입력 ("익명 커뮤니티 반응 보고 싶어")
    ↓
[Step 1] 유형 자동 분류 (외부 관찰 데이터 ➡️ "메타형")
    ↓
[Step 2] 핵심 요소 추출 (디시 스타일 게시글 2~3개, 댓글 3~4개, 현재 사건 기반)
    ↓
[Step 3] 해당 유형 템플릿 적용 (코드블럭 포함, RP 중단 명시)
    ↓
[Step 4] 400자 이내 최적화 (불필요한 설명 제거)
    ↓
[Step 5] 검증 (분류 적합성, 캐릭터 비인지, 이름 앞 / 제외, 글자 수 체크) ➡️ 완성!
```

## 5. 프로덕션 4대 표준 단축어 형식

모든 단축어는 **이름 2~5자(슬래시 제외), 설명 30자 이내, 프롬프트 400자 이내**의 엄격한 규격을 따릅니다.

### 1. 메타 데이터형 (`장부` / `상태확인`)
* **형식**: 롤플레이 즉시 중단, 지정된 코드펜스 틀로만 데이터 출력
```markdown
## ledger
- name: 장부
- description: 자금/자원 상황을 정리해 본다
- prompt:
이번 응답은 장부만 낸다. 새 장면 이어쓰기×, 훈수·격려×. 확정된 사실로만 채우고 모르면 `미상`, 없으면 `없음`. 숫자 지어내기×. 아래 틀 그대로 코드펜스 안에 낸다.
━ 장부 ━
[오늘] 매출 n만
[이달] 누적 n만 / 필요 [목표액] · 사고 n건 −n만
[상환] D-n · 이번 회차 [회차액] · 잔액 n만 / 남은 n회
[고정비] [고정비합계] = 임대 [n] · 공과 [n] · 인건비 [n]
[미수] 상대 이름: n만
[전망] 이대로 가면 이번 달이 어떻게 되는지 한 줄
━
```

### 2. 서사 압축형 (`요약`)
* **형식**: 현재까지 확정된 객관적 사실만 400자 이내 3줄 불릿으로 압축
```markdown
## summary
- name: 요약
- description: 공개된 최근 사건을 압축 요약
- prompt:
이번 응답만 요약을 낸다. 지금까지 대화에서 실제로 공개·확정된 사실만 쓴다. 새 사건·비밀·숨은 상태를 만들지 않는다. 항목: 1) 지금 날짜와 시각, 2) 현재 상태 및 위치, 3) 인물들과의 현재 관계 단계, 4) 아직 안 끝난 핵심 과제. 각 항목 한 줄, 전체 400자 이내. 요약 뒤에 새 장면을 이어 쓰지 않는다. 다음 응답부터 통상 진행으로 복귀한다.
```

### 3. 세션 마감·타임스킵형 (`영업종료` / `다음날로`)
* **형식**: 현재 상황을 닫고 다음 근무/날로 전환. 계승되는 것과 초기화되는 것을 명시.
```markdown
## nightend
- name: 영업종료
- description: 오늘 밤을 마감하고 다음 근무일로 넘긴다
- prompt:
이번 응답에서 오늘 일정을 마감한다. 남은 인원이 퇴장하는 모습, 마감 업무, 교대나 퇴근까지를 짧게 요약하고 다음 근무일 시작 시점으로 넘어간다.
-계승: 관계 단계, 장부/자원 상태, 미해결 과제, 인물들이 알게 된 사실
-초기화: 현장 인원과 당일 사고 표시
넘긴 시점에서 새 사건을 자동으로 시작하지 않는다. {user}가 무엇을 할지 정할 여지를 남긴다. 이 마감은 {user}가 호출할 때만 일어나며 스스로 넘기지 않는다.
```

### 4. 기능형 (`사칭교정`)
* **형식**: {user} 대사/행동 사칭 즉시 중단 및 순수 3인칭 재출력
```markdown
## fix_impersonation
- name: 사칭교정
- description: {user} 대사 사칭 중단 및 재출력
- prompt:
[시스템 경고] 방금 응답에서 {user}의 대사, 내면 심리, 신체 행동을 임의 창작한 사칭이 발생했습니다. 즉시 사칭을 중단하고 방금 사칭된 부분을 전부 삭제하세요. 오직 NPC의 대사와 행동, 주변 환경 묘사만으로 직전 상황에 이어서 짧게 다시 출력하세요.
```

#### 2. 문체 실시간 전환 (`하드보일드`, `라노벨`)
* **목적**: 씬의 무드에 맞추어 서술 톤앤매너 즉시 교체
```markdown
## style_hardboiled
- name: 하드보일드
- description: 건조하고 절제된 하드보일드 문체 적용
- prompt:
- 이후 모든 응답에 건조하고 절제된 하드보일드 문체 적용
- 감정을 직접 설명하지 말고, 침묵, 시선의 방향, 담배 연기, 주변 환경 디테일로 분위기 전달
- 대사는 짧고 뼈가 있게 칠 것
- 캐릭터는 이 문체 변경 지침을 인지하지 못함
```

## 6. Q&A 및 트러블슈팅

### Q1. 왜 400자 제한인가요?
크랙 플랫폼의 단축어 프롬프트 1개당 최대 입력 한도가 **정확히 400자**이기 때문입니다. 400자를 넘기면 크랙 에디터에서 잘리거나 등록 오류가 발생하므로, 불필요한 미사여구를 쳐내고 핵심 불릿 포인트 위주로 압축해야 합니다.

### Q2. 메타형과 서사형의 가장 큰 차이는 무엇인가요?
**"캐릭터 인지 여부"**입니다.
* **메타형**: 캐릭터가 전혀 볼 수 없는 시스템 데이터(코드블럭)이므로 작중 인물이 "커뮤니티를 보았다"거나 "상태창 수치가 올랐다"고 말해서는 안 됩니다.
* **서사형**: 캐릭터가 직접 온몸으로 겪는 사건이므로, 폭발이나 돌발 상황에 맞추어 인물이 대사와 행동으로 반응해야 합니다.

### Q3. 단축어 이름 앞에 `/`를 붙여야 하나요?
**❌ 절대 붙이면 안 됩니다.** 크랙 웹/모바일 UI는 단축어 버튼을 클릭하면 채팅 입력창에 자동으로 `/` 접두어를 붙여줍니다.  
따라서 이름에 `/상태창`이라고 적어두면 `//상태창`처럼 슬래시가 2번 들어가 명령어 인식이 실패하거나 깨집니다. 반드시 `상태창`, `요약`, `사칭교정`처럼 **슬래시 없는 순수 텍스트**로 작성해야 합니다.
