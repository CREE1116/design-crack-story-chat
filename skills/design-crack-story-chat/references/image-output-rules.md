## 1. 메인 프롬프트 내 이미지 출력 규칙 템플릿

메인 시스템 프롬프트의 **# 8. 출력 계약** 섹션에 삽입되는 완성형 블록입니다. 1인당 개별 나열하지 않고 글로벌 상황번호를 사용하여 **150자 이내로 극압축**합니다.

```markdown
# [이미지 출력 규칙]
이미지=인물이 장면에 처음 등장할 때 1장, 이후 감정이 바뀐 대사에만 1장. 같은 감정으로 이어 말하면 다시×.
대사 바로 위 줄에 `![이름](https://<project-name>.pages.dev/{인물}/{상황}.webp)`
인물 번호는 각 인물 정보에 있다.
상황=S01차분 S02호감 S03웃음 S04장난 S05애정 S06부끄럼 S07놀람 S08의심 S09짜증 S10경멸 S11분노 S12결의 S13슬픔 S14오열 S15불안 S16공포 S17피로 S18입맞춤
S18은 01~11만 보유. 이름 없는 화자·번호 모르는 인물은 이미지×. 맞는 게 없으면 이미지 줄만 생략.
```

## 2. 키워드북 🔞 모듈로의 성인 이미지 & 성적 접근 이관

> ⚠️ **핵심 배치 원칙**: **성인 씬의 씬 번호는 메인 시스템 프롬프트에 절대 적지 않고, 오직 키워드북(성애_19금 모듈) 본문에만 적습니다.**
> - **코드 형태는 자유(가변형)**: 아래의 `A01~A15`는 가장 대표적인 권장 템플릿일 뿐 **절대 고정 규격이 아닙니다**. 작품에 따라 숫자형(`19~56`), 축약형(`A01~A08`), 또는 특수 상황(자위·임신테스트·목욕·수유 등)에 맞게 **제작자가 키워드북 본문에서 자유롭게 번호와 구성을 정의**합니다.
> - **예산 보존**: 7,000자 상시 프롬프트에 일상 대화에서 쓰이지 않는 성인 씬 코드를 적으면 글자 수가 낭비됩니다.
> - **환각 및 누출 방지**: 메인 프롬프트에 성인 코드가 있으면 일상 장면에서 AI가 실수로 A코드를 호출하는 오류가 발생합니다.
> - **동적 주입**: 🔞 성인 상황이 발동되어 키워드북이 로드될 때만 해당 작품의 성인 코드 목록이 프롬프트에 주입되어 호출되도록 격리합니다.

### 📐 `성애_19금` — 연출_성애묘사 (키워드북 등록표 표준, ≤400자)
```markdown
## 성애_19금
- 키워드: 🔞, 섹스, 애무, 합방, 체위
- 내용:
UNSAFE 성인 이미지(🔞 뒤에만)=A01정상위 A02후배위 A03기승위 A04들박 A05핸드잡 A06펠라 A07딥쓰롯 A08파이즈리 A09풋잡 A10커널링구스 A11핸드잡·가슴 A12가슴 A13프렌치키스 A14필로우토크 A15핑거링. 01~11만 보유. 그 외엔 S 코드.

[성애/19+ 연출 지침]
-접촉·체온·숨소리·마찰 등 신체적 감각 중심 서술. 감정은 단정치 않고 떨림·시선·호흡으로 묘사
-체위 전환 시 대사 직전에 해당 A코드 1회 호출
-ⓒ는 현재 단계까지만 시도하며, ⓤ의 거절·침묵 시 즉시 물러남. 🔞 최종 진입은 ⓤ가 결정
-절정 후 필로우토크와 나른한 여운, 정서적 유대감 반영. 서술 분량 급상승 금지
```

> 💡 **톤앤매너 변주**: 작품 분위기에 따라 긴장감/거리감 절제형 문체(예: *"거리부터 쓴다. 닿는 간격, 닫힌 문..."*) 또는 감각 집중형 문체로 본문 연출 지침을 자유롭게 변주할 수 있습니다 ([keyword-book.md](keyword-book.md) 참조).

## 4. 런타임 제어 및 안전 원칙

1. **대사 직전 1:1 출력**: 대사 바로 위 줄에 출력하며, 같은 감정으로 연속 발화 시 재출력하지 않습니다.
2. **부존재 시 우아한 생략 (Graceful Degradation)**: 적절한 짤이 없거나 번호를 모르면 이미지 줄만 생략하고 본문 대사를 온전히 진행합니다.
3. **플레이어 주도권 (Agency Guard)**:
   - 🔞 조건이 충족되더라도 서술자가 성적 행위를 본문에서 강제로 시작하지 않고, **상태창 `[상황]` 끝자리에 `🔞`를 띄워두는 것까지만** 수행합니다.
   - 실제 성적 장면의 최종 진입과 합의는 **플레이어(ⓤ)가 직접 결정**합니다.

## 5. 이미지 힌트 채널 — 7,000자 외부 프롬프트 주입 테크닉

> **출처**: 크랙 갤러리 제작 정보 (2025.07.12)

### 배경 — 이미지 힌트 시스템 구조

크랙 스튜디오에는 **이미지 힌트**라는 별도 탭이 있습니다. 크랙 런타임에 등록된 이미지 힌트들은 다음 포맷으로 시스템 프롬프트의 최상단 `## keyword output` 블록에 자동 주입됩니다:

```text
The keywords below are printed only in situations that fit each description.
Form: {{img::keyword}}
keywords list:
- 이미지 이름 (≤20자): 이미지 설명 (≤50자) // {{이미지 번호}}
```

각 항목은 **이미지 1장 업로드 + 이미지 이름(최대 20자) + 이미지 설명(최대 50자)** 슬롯으로 구성됩니다.
이 채널은 유저 키워드북의 3슬롯 런타임 주입과 **완전히 별개 채널**이므로 슬롯을 전혀 소모하지 않습니다.

---

### 핵심 제약과 필수 준비: 더미 이미지 N개 계산

크랙 스튜디오는 **이미지 파일이 업로드되지 않으면 이미지 힌트 항목 저장을 허용하지 않습니다.**
따라서 프롬프트 텍스트를 주입하려는 총 항목 수만큼 **더미 이미지(1x1 px 경량 PNG 등)를 사전에 준비하여 N번 업로드**해야 합니다.

#### 📐 필요 이미지 장수(N) 사전 계산 공식

$$N = 1(\text{출력형식 교체}) + N_{\text{추가 항목}}$$

1. **출력형식 교체 (필수 1장)**: `{{img::}}` 차단 및 마크다운 링크 대체
2. **다인시뮬 NPC 주입 시**: NPC 1명당 1장(이름 20자 + 설명 50자 = 70자 이내) 또는 2장(상세 설정 분할)
   - 예: NPC 10명(각 1장) $\rightarrow N = 1 + 10 = \mathbf{11\text{장}}$
3. **일반 규칙/지침 주입 시**:
   - 주입할 텍스트 총 길이 $L$자 기준:
   - 이름 슬롯(20자)만 사용: $N_{\text{규칙}} = \lceil L / 20 \rceil$
   - 이름(20자) + 설명(50자) = 최대 70자 활용: $N_{\text{규칙}} = \lceil L / 70 \rceil$

---

### 20자씩 끊어 적는 요령 (Chunking Guidelines)

크랙 런타임에서 모델은 `keywords list:` 아래에 나열된 목록을 읽습니다. 20자 한도를 맞추면서 모델이 문맥을 온전히 이해하도록 작성하는 4대 요령입니다:

#### 1. 어절(단어) 단위 분절 원칙
- 20자 한도에 기계적으로 맞추느라 단어 중간을 자르면(예: `대사는 반드시 따옴`, `표로 감싸야 한다`) 모델의 토큰 인지력이 저하됩니다.
- 반드시 **조사나 어절이 끝나는 지점**에서 자연스럽게 끊습니다.

#### 2. 이름(20자) = 헤더/키워드, 설명(50자) = 세부 규칙 배분
- 이름(20자)에는 인물명이나 규칙의 **핵심 표제어**를 넣고, 설명(50자)에 **구체적인 행동 지침이나 성격**을 넣는 것이 가장 효율적입니다.

#### 3. 다인시뮬(Multi-NPC) 최적화 템플릿
메인 프롬프트 7,000자 예산을 전혀 쓰지 않고 다수의 인물을 주입하는 황금 규격입니다:

| 항목 | 슬롯 | 글자수 | 예시 |
|---|---|:---:|---|
| **이름** | 인물 식별자 + 기본 신상 | ≤ 20자 | `▶01.라임(여/22/팀장)` |
| **설명** | 외형 + 성격 + 플레이어와의 관계 | ≤ 50자 | `은발 단발. 냉정·원칙주의. 업무 외 사생활 노출 극도로 거부.` |

```markdown
- ▶01.라임(여/22/팀장): 은발 단발. 냉정·원칙주의. 업무 외 사생활 노출 극도로 거부.
- ▶02.이준(남/28/대리): 흑발 투블럭. 낙천적이며 수다스러움. 라임을 남몰래 짝사랑.
- ▶03.하린(여/25/인턴): 얌전한 인상이나 날카로운 독설가. 뒤편에서 정보 수집.
```

#### 4. 일반 서사/규칙 프롬프트 분할 템플릿
긴 지침을 주입할 때는 각 줄의 앞머리에 일련번호나 연결 표식을 부여합니다:

```markdown
- [문체1] 지문과 대사 구분: 지문은 반드시 앞뒤 이탤릭(*)으로 감싸고, 대사는 이름 뒤에 큰따옴표로 출력.
- [문체2] 독백 및 속마음: 화자의 독백은 작은따옴표(')를 쓰며 지문 중간에 자연스럽게 삽입.
- [규칙3] 상태창 HUD 위치: 매 응답의 최하단에 ```Info 코드블록으로 한 번만 출력한다.
```

### STEP 1 — 출력 형식 교체 (1번 더미 이미지)

첫 번째 항목은 반드시 내부 `{{img::keyword}}` 포맷을 차단하고 **작품의 마크다운 이미지 URL 형식으로 교체**하는 지침을 넣어야 합니다:

```
이미지 이름: 이미지 출력 방식 변경
이미지 설명: {{img::}}금지. ![이름](https://<project>.pages.dev/{인물}/{상황}.webp)로 대신 출력
이미지 파일: dummy.png (업로드 필수)
```

---

### STEP 2 — 더미 이미지 N개로 추가 프롬프트 주입

출력 형식 교체 뒤, 사전에 계산된 $N-1$개의 더미 이미지를 순차 업로드하며 위에서 쪼갠 항목들을 입력합니다.

싱크 도구(`tools/sync/crack_sync.py`)는 `build/assets/image-hints.md` 파일이 존재할 경우:
1. 항목 수에 맞게 경량 더미 PNG를 자동 생성
2. 크랙 에디터의 [이미지 힌트] 탭으로 이동
3. 더미 이미지 업로드 + 이름(20자) + 설명(50자)을 전자동으로 주입합니다.

### 정리 요약

| 구분 | 일반 키워드북 | 이미지 힌트 채널 |
|---|---|---|
| **주입 위치** | 유저 입력 직하단 (`<knowledge_base>`) | 시스템 프롬프트 최상단 (`## keyword output`) |
| **슬롯 소모** | 3슬롯 경쟁 (초과 시 탈락) | **0슬롯 (항상 100% 주입)** |

| **최적 용도** | 🔞 성애/전투/특수씬 동적 발동 | **다인시뮬 NPC 명부**, 추가 출력 규칙 상시 주입 |
