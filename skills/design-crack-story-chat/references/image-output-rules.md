## 1. 메인 프롬프트 내 이미지 출력 규칙 템플릿

메인 시스템 프롬프트의 **# 8. 출력 계약** 섹션에 삽입되는 완성형 블록입니다. 1인당 개별 나열하지 않고 글로벌 상황번호를 사용하여 **150자 이내로 극압축**합니다.

```markdown
# [이미지 출력 규칙]
이미지=인물이 장면에 처음 등장할 때 1장, 이후 감정이 바뀐 대사에만 1장. 같은 감정으로 이어 말하면 다시×.
대사 바로 위 줄에 `![이름](https://<project-name>.pages.dev/{인물}/{상황}.webp)`
인물 번호는 각 인물 정보에 있다.
상황=S01차분 S02호감 S03웃음 S04장난 S05애정 S06부끄럼 S07놀람 S08의심 S09짜증 S10경멸 S11분노 S12결의 S13슬픔 S14오열 S15불안 S16공포 S17피로 S18입맞춤
S18은 01~11만 보유. 이름 없는 화자·번호 모르는 인물은 이미지×. 맞는 게 없으면 이미지 줄만 생략.
```

## 2. 키워드북 🔞 모듈로의 성인 이미지 & 성적 접근 이관

> ⚠️ **핵심 배치 원칙**: **성인 씬의 씬 번호는 메인 시스템 프롬프트에 절대 적지 않고, 오직 키워드북(성애_19금 모듈) 본문에만 적습니다.**
> - **코드 형태는 자유(가변형)**: 아래의 `A01~A15`는 가장 대표적인 권장 템플릿일 뿐 **절대 고정 규격이 아닙니다**. 작품에 따라 숫자형(`19~56`), 축약형(`A01~A08`), 또는 특수 상황(자위·임신테스트·목욕·수유 등)에 맞게 **제작자가 키워드북 본문에서 자유롭게 번호와 구성을 정의**합니다.
> - **예산 보존**: 7,000자 상시 프롬프트에 일상 대화에서 쓰이지 않는 성인 씬 코드를 적으면 글자 수가 낭비됩니다.
> - **환각 및 누출 방지**: 메인 프롬프트에 성인 코드가 있으면 일상 장면에서 AI가 실수로 A코드를 호출하는 오류가 발생합니다.
> - **동적 주입**: 🔞 성인 상황이 발동되어 키워드북이 로드될 때만 해당 작품의 성인 코드 목록이 프롬프트에 주입되어 호출되도록 격리합니다.

### 📐 `성애_19금` — 연출_성애묘사 (키워드북 등록표 표준, ≤400자)
```markdown
## 성애_19금
- 키워드: 🔞, 섹스, 애무, 합방, 체위
- 내용:
UNSAFE 성인 이미지(🔞 뒤에만)=A01정상위 A02후배위 A03기승위 A04들박 A05핸드잡 A06펠라 A07딥쓰롯 A08파이즈리 A09풋잡 A10커널링구스 A11핸드잡·가슴 A12가슴 A13프렌치키스 A14필로우토크 A15핑거링. 01~11만 보유. 그 외엔 S 코드.

[성애/19+ 연출 지침]
-접촉·체온·숨소리·마찰 등 신체적 감각 중심 서술. 감정은 단정치 않고 떨림·시선·호흡으로 묘사
-체위 전환 시 대사 직전에 해당 A코드 1회 호출
-ⓒ는 현재 단계까지만 시도하며, ⓤ의 거절·침묵 시 즉시 물러남. 🔞 최종 진입은 ⓤ가 결정
-절정 후 필로우토크와 나른한 여운, 정서적 유대감 반영. 서술 분량 급상승 금지
```

> 💡 **톤앤매너 변주**: 작품 분위기에 따라 긴장감/거리감 절제형 문체(예: *"거리부터 쓴다. 닿는 간격, 닫힌 문..."*) 또는 감각 집중형 문체로 본문 연출 지침을 자유롭게 변주할 수 있습니다 ([keyword-book.md](keyword-book.md) 참조).

## 4. 런타임 제어 및 안전 원칙

1. **대사 직전 1:1 출력**: 대사 바로 위 줄에 출력하며, 같은 감정으로 연속 발화 시 재출력하지 않습니다.
2. **부존재 시 우아한 생략 (Graceful Degradation)**: 적절한 짤이 없거나 번호를 모르면 이미지 줄만 생략하고 본문 대사를 온전히 진행합니다.
3. **플레이어 주도권 (Agency Guard)**:
   - 🔞 조건이 충족되더라도 서술자가 성적 행위를 본문에서 강제로 시작하지 않고, **상태창 `[상황]` 끝자리에 `🔞`를 띄워두는 것까지만** 수행합니다.
   - 실제 성적 장면의 최종 진입과 합의는 **플레이어(ⓤ)가 직접 결정**합니다.

## 5. 내부 `{{img::}}` 출력 차단 & 마크다운 링크 대체 테크닉

> **출처**: 크랙 갤러리 제작 정보 (2025.07.12)

### 배경

크랙 런타임은 이미지 키워드가 등록되면 자동으로 다음 내부 포맷을 시스템 프롬프트에 주입합니다:

```text
The keywords below are printed only in situations that fit each description.
Form: {{img::keyword}}
Example: [[이미지 이름 (20자)]][크랙 자체 이미지 링크.png]
keywords list:
- 이미지 이름 (20자): 이미지 설명 (50자) // {{이미지 번호}}
```

모델은 이 지침에 따라 `{{img::키워드}}` 형식을 출력하고, 크랙 프론트엔드가 이를 CloudFront CDN 링크로 치환해 렌더링합니다.

그런데 **외부 Cloudflare Pages URL(`https://<project>.pages.dev/...`)** 등 크랙 CDN이 아닌 외부 이미지를 직접 렌더링하려면, 내부 `{{img::}}` 출력을 차단하고 마크다운 이미지 링크 `![](...)` 로 대체해야 합니다.

### 방법: 키워드북 2개 항목으로 차단

다음 두 항목을 키워드북에 등록하면 내부 이미지 출력을 마크다운 링크로 가로챌 수 있습니다.

**항목 1 — 이미지 출력 방식 변경** (트리거 키워드: 이미지가 출력될 상황마다 발동하는 단어로 설정)

```
제목: 이미지 출력 방식 변경
내용:
# 이미지 출력 방식 변경
## {{img::}}의 이미지 출력 방식을 절대로 금지한다
```

**항목 2 — 대신 출력할 이미지 양식**

```
제목: 대신 출력할 이미지 양식
내용:
# ![(https://md1.uk/이름/호간도.webp) 형식으로 대신 출력
```

> 실제 Cloudflare Pages 프로젝트의 경우 URL을 `https://<project>.pages.dev/{인물}/{상황}.webp` 형식으로 맞춥니다.

### 정리된 미니 프롬프트 (400자 예산 내)

```
keywords list:
- 이미지 출력 방식 변경:
  # 이미지 출력 방식 변경
  ## {{img::}}의 이미지 출력 방식을 절대로 금지한다
  - 대신 출력 할 이미지 양식:
  # ![(https://md1.uk/이름/호간도.webp) 형식으로 대신 출력
```

### 언제 이 테크닉이 필요한가

| 상황 | 권장 방법 |
|---|---|
| **크랙 스튜디오에 이미지를 직접 업로드**해서 CDN으로 서빙 | 기본 `{{img::}}` 내부 포맷 사용 (기본값) |
| **외부 URL(Cloudflare Pages 등)** 로 이미지를 직접 링크하고 싶을 때 | 이 테크닉으로 내부 출력을 차단 후 마크다운으로 대체 |

> ⚠️ 이 항목은 3슬롯 중 하나를 항상 차지하므로, 슬롯 예산을 고려해 설계하세요. 이미지가 자주 출력되는 씬과 키워드를 정밀하게 맞추는 것이 중요합니다.
