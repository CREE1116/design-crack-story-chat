## 역할과 아키텍처

크랙 스토리챗은 마크다운 이미지 태그(`![](URL)`)를 통해 외부 호스팅(CDN, GitHub, jsDelivr 등)된 이미지를 대화 중간에 실시간으로 호출할 수 있습니다.

- **[image-assets.md](image-assets.md)**: 이미지를 오프라인에서 **어떻게 일관성 있게 그릴 것인가 (자산 제작)**
- **[image-output-rules.md](image-output-rules.md) (본 문서)**: 만들어진 이미지를 시스템 프롬프트에서 **어떤 양식으로 정의하고 언제 출력할 것인가 (출력 규약 & 런타임 제어)**

## URL 구조 및 표준 축 매핑

크랙의 이미지 호출은 **베이스 URL + 카테고리/이름 + 상황/표정 번호.png** 구조를 표준으로 사용합니다.

```markdown
![](https://domain.com/[작품ID]/[카테고리]/[번호].png)
```

### 4대 표준 카테고리
1. **`장소/` (배경/환경)**: `https://.../장소/21.png`
2. **`[인물명]/` (캐릭터 표정/의상)**: `https://.../주세은/7.png`
3. **`몬스터/` (적/괴수/메카ニック)**: `https://.../몬스터/32.png`
4. **`이벤트/` (특수 컷씬/CG)**: `https://.../이벤트/1.png`

## 시스템 프롬프트 내 이미지 규칙 작성법

시스템 프롬프트(7,000자 상한) 안에서는 토큰을 아끼기 위해 긴 URL을 매번 반복하지 않고, **베이스 URL 매크로(`{IMG}`)와 1인 1줄 번호 매핑**으로 극압축합니다.

### 📐 1줄 번호 매핑 압축 포맷
```markdown
# 이미지 출력 규칙
-기본URL: {IMG} = https://domain.com/OR
-출력문법: `![]({IMG}/[카테고리]/[번호].png)`
-장소: [1:에덴중앙광장, 2:벌처암시장, 21:지상폐허3구역, 22:붕괴마천루]
-몬스터: [31:스카우트드론, 32:3급아머트론, 33:셀트론]
-세라: [1:기본·미소, 2:비웃음, 3:진지·살벌, 4:당황, 5:부끄러움, 6:담배, 7:전투]
-주세은: [1:기본·단정, 2:경계, 3:통신·다급, 4:홍조, 5:화남, 6:사복, 7:무전]
-박한솔: [1:자신감, 2:도발, 3:경악, 4:부상, 5:진지]
```

## 출력 타이밍 및 스로틀링 4대 원칙

아무리 좋은 일러스트라도 남발되면 모바일 화면의 스크롤이 터지고 로딩 렉이 발생합니다. 모델에게 엄격한 **출력 빈도 제어(Throttling)**를 명령해야 합니다.

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 장소 이미지 : 씬/공간 전환 시 응답 맨 위에 단 1회         │
│ 2. 인물 이미지 : 화자 전환 또는 강한 감정 변화 시 대사 직전 1회 │
│ 3. 중복 출력 금지: 한 턴에 같은 인물 이미지 2장 이상 연속 금지 │
│ 4. 턴당 총량 제한: 1개 응답당 최대 2장 이내 (장소1+인물1 등)  │
└─────────────────────────────────────────────────────────────┘
```

### 1. 장소/배경 이미지 (Scene Transition)
- ⓤ가 새로운 장소로 이동하거나, 시간대/국면이 전환될 때 **응답 최상단(1번째 줄)**에 1회만 출력합니다.
- 장소가 바뀌지 않고 같은 공간에서 대화가 이어질 때는 장소 이미지를 다시 출력하지 않습니다.

### 2. 인물/표정 이미지 (Character Expression)
- 특정 캐릭터가 처음 말을 시작하거나, 대화 중 표정이 급변할 때 **해당 대사 바로 윗줄**에 1회 출력합니다.
- 평범한 일상 대화가 짧게 오갈 때는 매 대사마다 억지로 부르지 않습니다.

### 3. 동일 인물 연속 출력 금지 (Anti-Spam)
- 같은 턴에 세라가 3문장을 말한다고 해서 세라의 짤을 3장 연달아 부르는 것을 엄격히 금지합니다.

### 4. 턴당 최대 2장 상한 (Mobile Clamping)
- 모바일 화면 가독성과 트래픽 최적화를 위해 **1턴당 최대 2장(장소 1장 + 인물 1장, 또는 인물 2장)**을 상한으로 못박습니다.

## 키워드북 분리 패턴 (특수/성인 CG)

평소에는 전혀 쓰이지 않는 **19+ 성애 씬 체위 CG, 히든 각성 컷씬, 엔딩 CG**는 상시 프롬프트에 넣으면 토큰 낭비이자 일상 씬 오염의 원인이 됩니다.

이러한 특수 이미지는 [keyword-book.md](keyword-book.md)의 **키워드북 연출 모듈**로 분리합니다.

### 📐 키워드북 내 19+ 이미지 매핑 예시
```markdown
# `kb.directive_nsfw` — 연출_성애묘사
- activation_setting: 전체 시작 설정
- activation_when: 사용자 메시지 또는 모델 출력에 키워드가 감지될 때
- keywords: [🔞, 섹스, 애무, 합방, 체위]

## Entry text
[성애 연출 및 이미지 지침]
-성애 전용 CG: `![]({IMG}/이벤트/[번호].png)`
 -세라_합방: [101:애무, 102:정상위, 103:후배위, 104:절정, 105:사후여운]
 -주세은_합방: [201:키스, 202:기승위, 203:절정, 204:나른함]
-체위가 전환될 때 해당 대사 직전에 1회 호출
-상태창에 체위 및 [🔞특수밀회] 상태 태깅 필수
```

## 안전성 및 예외 처리 원칙

### 1. 환각 번호 생성 절대 금지 (Strict ID Check)
- 모델이 목록에 없는 가상의 번호(예: `세라/99.png`, `장소/999.png`)를 지어내어 깨진 이미지 엑스박스(`[X]`)가 뜨는 현상을 방지합니다.
- **프롬프트 명령**: `목록에 명시된 번호 외 임의의 번호 생성 엄격 금지. 적합한 번호가 없으면 이미지 생략`

### 2. 텍스트 자립성 (Text Independence)
- 이미지는 시각적 양념일 뿐, **이미지가 로딩되지 않거나 차단되더라도 텍스트 지문과 대사만으로 모든 상황이 완벽히 전달**되어야 합니다.
- "위 사진과 같은 표정으로 말했다" 식의 이미지 의존적 서술을 엄격히 금지합니다.

## 실전 시스템 프롬프트 미디어 룰 템플릿

통합 시스템 프롬프트에 그대로 삽입하여 사용할 수 있는 완성형 미디어 룰 블록입니다:

```markdown
# [이미지 출력 규약]
-기본 URL: {IMG} = https://domain.com/OR
-문법: `![]({IMG}/[카테고리]/[번호].png)`
-출력 원칙:
 1. 장소: 공간 이동 시 응답 최상단에 1회만 출력 (장소 유지 시 생략)
 2. 인물: 주요 대사/감정 변화 직전에 1회 출력 (동일 인물 연속 출력 금지)
 3. 상한: 1개 응답당 최대 2장 이내 엄수
 4. 안전: 목록에 정의된 번호만 사용, 없는 번호 날조 금지
-장소: [1:에덴중앙광장, 2:벌처암시장, 21:지상폐허3구역, 22:붕괴마천루]
-몬스터: [31:스카우트드론, 32:3급아머트론, 33:셀트론]
-세라: [1:기본·미소, 2:비웃음, 3:진지·살벌, 4:당황, 5:부끄러움, 6:담배, 7:전투]
-주세은: [1:기본·단정, 2:경계, 3:통신·다급, 4:홍조, 5:화남, 6:사복, 7:무전]
-박한솔: [1:자신감, 2:도발, 3:경악, 4:부상, 5:진지]
```
