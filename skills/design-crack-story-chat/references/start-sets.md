# 시작 세트 (Start Sets) — 다중 시작 프롬프트 규약

하나의 스토리에 **진입점이 여럿**일 수 있습니다. 부서가 다르거나, 루트가 갈리거나, 주인공 위치가 다른 경우입니다. 크랙은 이걸 여러 개의 시작 설정으로 등록할 수 있고, 이 문서는 그것을 소스에서 어떻게 보관하고 빌드에 어떻게 반영하는지 정합니다.

## 1. 핵심 원칙: 프롤로그와 첫 상황은 한 쌍

`prologue.md`(첫 응답으로 노출되는 장면)와 `start-prompt.md`(그 장면에서 무엇을 요구하는지 정하는 첫 상황 압력 + 입력 파싱 계약)는 **따로 고를 수 있는 물건이 아닙니다.**

영업마케팅팀 프롤로그에 비서실 첫 상황을 붙이면, 하르피아 팀장 앞에 서 있는데 바알 대표이사가 브리핑을 요구하는 상태가 됩니다. 모델은 둘 중 하나를 버리거나 억지로 봉합하고, 그 순간 첫 턴이 무너집니다.

**그러므로 두 파일은 항상 같은 폴더에 함께 두고, 통째로 선택합니다.**

## 2. 디렉토리 규약

```
<project>/
  story.md
  characters.md
  start-sets/                     ← 정본. 시작 세트가 여기 산다
    01_product/
      meta.md                     # 선택. 제목·설명·순서·기본세트
      prologue.md                 # 필수
      start-prompt.md             # 필수
    02_rd/
    03_sales/
    04_executive/
  build/
    integrated-prompt-safe.md
    integrated-prompt-unsafe.md
    keyword-book*.md
    prologue.md                   ← 생성물. 기본 세트의 사본
    start-prompt.md               ← 생성물. 같은 세트의 사본
```

- 폴더 이름이 곧 세트 `id` 입니다. 숫자 접두사(`01_`)는 정렬용이며 제목에서 자동으로 떨어집니다.
- 세트를 추가하려면 폴더를 만들면 됩니다. 어디에도 목록을 등록하지 않습니다.
- `departments/` 라는 이름도 계속 읽습니다(구버전 호환). 새 프로젝트는 `start-sets/` 를 씁니다.
- 세트가 하나뿐인 스토리는 `start-sets/` 없이 `build/` 의 두 파일만 두어도 됩니다.

## 3. meta.md 형식

전부 선택 사항입니다. 파일이 없으면 폴더명을 제목으로 쓰고 디렉토리 순서를 따릅니다.

```markdown
# 상품기획팀
사수 라임 대리(슬라임). 탕비실과 기획서로 시작하는 가장 무난한 입사 루트.

- order: 0
- default: true
```

| 항목 | 뜻 |
|---|---|
| 첫 헤딩 | 세트 제목. 크랙 등록 시 노출되는 이름 |
| 헤딩 아닌 본문 | 설명. 플레이어가 루트를 고를 때 읽는 한두 줄 |
| `- order:` | 정렬 순서. 낮을수록 앞 |
| `- default:` | `true` 인 세트가 `build/` 에 반영되는 기준. 없으면 첫 번째 |

## 4. build/ 는 생성물

크랙 업로드는 `build/prologue.md` 와 `build/start-prompt.md` 를 봅니다. 그래서 두 파일은 계속 존재해야 하지만, **정본이 아니라 사본입니다.**

이 구분이 없으면 실제로 사고가 납니다. 세트를 전환하는 스크립트가 `build/` 를 덮어쓰고 나면, 파일만 봐서는 지금 어느 루트가 들어 있는지 알 수 없습니다. 상품기획팀 빌드를 검수하고 있다고 믿으면서 실제로는 비서실 프롤로그를 읽는 상황이 생깁니다.

**`build/prologue.md` 를 직접 편집하지 마세요.** `start-sets/<id>/prologue.md` 를 고치고 반영하세요.

## 5. 도구

```bash
# 목록. * 가 기본 세트, (생성물) 이 build/ 사본
crack-emu --project build sets

# 고른 세트를 build/ 에 반영
crack-emu --project build sets --use 02_rd

# 구버전 departments/ 를 start-sets/ 로 이관 (계획 확인 후 적용)
crack-emu --project build sets --migrate
crack-emu --project build sets --migrate apply
```

`sets` 출력은 세트별로 프롤로그·첫 상황의 글자 수를 같이 보여주므로, 한 세트만 유독 빈약한 것을 바로 찾을 수 있습니다.

에뮬레이터에서 세트를 골라 실제로 첫 턴을 돌려볼 수 있습니다.

```bash
crack-emu --project build --start-set 03_sales turn s1 --input "..."
crack-emu --project build serve      # 웹 UI 왼쪽 드롭다운
```

`crack_sync.py` 는 `start-sets/` 의 모든 세트를 크랙의 다중 시작 설정으로 한 번에 주입합니다.

## 6. 설계 지침

- **세트마다 첫 상황의 요구가 달라야 합니다.** 프롤로그만 다르고 요구가 같으면 세트를 나눌 이유가 없습니다. 상품기획팀은 기획서를, 영업팀은 외근 동행을, 비서실은 KPI 브리핑을 요구하는 식으로 첫 턴의 과제 자체를 분리하세요.
- **프롤로그 1,000자 상한은 세트마다 따로 적용됩니다.** 한 세트가 상한을 넘으면 그 세트만 잘립니다.
- **키워드북과 메인 프롬프트는 세트 전체가 공유합니다.** 특정 세트에서만 필요한 인물이라도 명부에 있어야 이미지가 나옵니다. 세트별로 다른 세계관이 필요하다면 그건 세트가 아니라 별개 스토리입니다.
- **기본 세트는 가장 무난한 루트로 지정하세요.** 처음 들어온 플레이어가 마주치는 난이도이자, `build/` 에 반영되어 검수 대상이 되는 것이기도 합니다.
- **세트를 늘리기 전에 첫 상황부터 쓰세요.** 프롤로그는 분위기를 만들지만 첫 턴을 굴리는 것은 첫 상황의 요구입니다. 요구가 안 떠오르는 세트는 아직 세트가 아닙니다.
