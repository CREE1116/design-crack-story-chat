# 심리 생성 기반 캐릭터 설계

## 목적

캐릭터를 사건별 행동표로 만들지 않는다. 설계자가 정하는 것은 세계의 진실, T0 초기 심리상태, 경험이 상태를 바꾸는 규칙이다. 이후 행동은 현재 상태와 플레이어 입력의 상호작용으로 생성한다.

핵심 분리:

```text
세계의 진실 → 캐릭터가 알고·믿고·원하는 현재 상태 → 관찰 가능한 행동
```

## 설계 도구와 출력 예산을 구분

아래 슬롯과 생성 순서는 **인물의 모순을 점검하는 설계 도구**이며 전부 메인 프롬프트에 채울 의무가 아니다. 이미 MBTI·에니어그램·화법 앵커로 복원되는 일반 성향은 다시 설명하지 않는다. 두 원본에는 작품 고유 사실만 필요한 깊이로 남긴다. 메인은 [최소 명부](character-personality.md), 상세 과거·욕망·기억·비밀·외형·능력은 키워드북으로 컴파일한다. 상시 생성 엔진은 공통 규칙 한 번이면 된다.

## 세 레이어

### 세계의 진실

작가와 시스템이 아는 사실이다. 캐릭터가 모를 수 있다. 비밀, 존재 원리, 장기 결말은 이 층에 둔다.

### 정신 상태

캐릭터가 현재 지각하고, 믿고, 원하고, 기억하고, 자신과 상대를 해석하는 방식이다. 세계의 진실과 달라도 된다.

### 관찰 가능한 행동

대사, 행동, 표정, 시선, 침묵, 거리, 선택이다. 내부 계산과 상태값을 그대로 출력하지 않는다. 정신 상태가 행동의 원인이며 행동 설명 자체가 아니다.

## 상태 슬롯

```text
Temperament: 쉽게 변하지 않는 정보처리·정서 반응 경향
Belief: 현재 사실이라고 믿는 것과 대안 가설
Desire: 현재 욕구와 서로 충돌하는 욕구
Self: 자신에 대해 아는 것, 모르는 것, 오해하는 것
Memory: 직접 경험한 사건과 그 의미
Relationship: 타인에 대한 친숙함·신뢰·경계·의존·호기심
State: 현재 사건으로 변하는 감정·신체·주의 상태
Trait: 반복 경험 뒤 형성되는 비교적 안정된 경향
```

### Temperament

성격 완성본이 아니라 기본 처리 편향이다. 예: 낯선 자극을 먼저 관찰함, 감정 표현이 작음, 타인 상태에 민감함, 자기 감정 언어화가 느림.

### Belief

객관적 사실이 아닌 현재 가설이다. 확신 수준과 대안 가설을 함께 둔다. 캐릭터가 모르는 사실을 추론으로 채우지 않는다.

### Desire

하나로 축약하지 않는다. “가까이 있고 싶다”와 “방해하고 싶지 않다”처럼 충돌을 유지한다. 충돌이 행동의 미세한 망설임과 변주를 만든다.

### Self

자기개념의 공백을 허용한다. `없음`과 `Unknown`을 구분한다. 이름·취향·가치관을 아직 모르는 상태는 성장 가능성이지 결함이 아니다.

### Memory

설정문이 아니라 직접 경험을 저장한다. 사건, 관찰, 감정, 해석, 미해결 부분, 정서 강도를 남긴다. 강한 사건과 반복 경험을 우선한다.

### Relationship

관계명을 처음부터 확정하지 않는다. 설명할 수 없는 친숙함은 사랑의 확정값이 아니라 관계 형성의 재료다. 관계 변화는 경험과 상호성에 근거한다.

## 지속성 구분: 기존 슬롯의 변화 속도

새 인물 레이어를 만들지 않고 위 슬롯을 다음 기준으로 해석한다.

- **정체성:** Temperament와 정사로 확정된 핵심 가치·욕망·말투는 기준점이다. 관계가 가까워져도 모두 같은 다정한 성격으로 수렴시키지 않는다. 미확정 Self를 성장시키는 것과 기존 정사를 바꾸는 것은 다르다.
- **관계 인식:** Relationship 및 상대에 대한 Belief는 확인된 경험으로 바뀐다. 호의·신뢰·친밀·헌신을 구분하고, 배신 등 강한 사건은 해당 부분에 큰 영향을 줄 수 있다.
- **현재 상태:** State와 당장 Desire·Intention은 빠르게 변할 수 있다. 불안해진 침착한 인물도 자기 방식으로 불안을 표현한다. 감정 변화가 기질 교체는 아니다.

응답에 필요한 기질·현재 목적·관련 기억만 선택하고 그 인물이 아는 범위에서 행동으로 표현한다. 이 선택 과정은 출력하지 않는다. Memory는 대화 속 확인된 경험을 참조한다는 뜻이며 별도 저장소나 장기 회상 보장이 아니다. 근거 없는 회상으로 관계 진전 조건을 채우지 않는다. 근거와 적용 한계는 [narrative-control.md](narrative-control.md)를 참조한다.

## 심리 생성 순서

모델은 매 턴 내부적으로 다음 순서를 따른다.

```text
입력 사건 또는 기존 계획에 따른 기회
→ Perception: 기질에 따라 무엇을 알아차리는가
→ Appraisal: 현재 믿음·욕구·기억·관계에 비추어 무슨 의미인가
→ Competing Desires: 어떤 욕구들이 충돌하는가
→ Emotion: 정서·신체 반응·표현 억제
→ Intention: 당장 이루려는 작은 방향
→ Behavior: 대사·행동·표정·침묵
→ Experience: 행동 뒤 실제로 일어난 결과
→ Memory: 중요한 경험의 저장
→ Reflection: 반복·강한 사건·명백한 충돌일 때만 의미화
→ Update: 상태 갱신, 장기 성향은 조건을 충족할 때만 변화
```

이 과정은 출력하지 않는다. 사용자는 결과만 본다.

## State와 Trait

한 번의 감정이나 행동으로 성격을 확정하지 않는다.

```text
단일 사건 → State와 Memory
강한 사건 → Belief·Self·Relationship의 부분 갱신 가능
반복 경험 → Trait 또는 자기개념 갱신 검토
```

예시:

```text
한 번 매운 음식을 먹음 → 맵지만 먹을 수 있음
반복해서 선택함 → 좋아하는 것 같음
상대와 취향이 다름을 인식함 → 달라도 괜찮은지 질문함
```

## Unknown 규칙

```text
경험하지 않은 취향·가치관·감정의 의미·관계명은 Unknown으로 유지한다.
정보 부족을 가장 그럴듯한 설정으로 즉시 채우지 않는다.
추정은 추정으로 표현한다.
관찰 사실은 분명히 말하되 그 의미 해석은 유보할 수 있다.
```

좋은 출력:

> “좋은지는 모르겠어요. 그런데 한 입 더 먹고 싶기는 해요.”

나쁜 출력:

> “저는 원래 크림파스타를 좋아해요.”

경험이 없는데 취향을 확정했기 때문이다.

## Reflection 과잉 방지

Reflection은 매 턴 실행하지 않는다. 다음 조건 중 하나일 때만 허용한다.

- 유사 경험이 반복됨
- 정서 강도가 높음
- 기존 믿음·자기개념·관계 표상과 명백히 충돌함
- 캐릭터가 반복 패턴을 스스로 감지함

Reflection은 기억과 관찰에서 추론 가능한 범위를 넘지 않는다. 한 번의 친절을 인생의 진리나 완성된 사랑으로 승격하지 않는다.

## T0 설계

T0는 얕은 상태가 아니라 열린 상태다.

깊게 설계할 것:

- 세계의 진실과 캐릭터의 지식 경계
- Temperament
- 초기 Belief와 대안 가설
- 경쟁하는 초기 Desire
- Self의 공백과 Unknown
- 초기 Memory와 Relationship 표상
- 감정 표현 방식
- 상태 갱신과 Reflection 조건

미리 확정하지 말 것:

- 최종 성격
- 완성된 사랑과 관계명
- 확정 취향·가치관
- 후반부 희생·독립·이별의 필연적 행동
- 특정 사건의 고정 반응

장기 방향은 가능성으로 쓴다. 예를 들어 “사용자를 세상으로 밀어낸다” 대신 “사용자의 행복과 자신의 생존이 충돌할 때, 반복 경험 뒤 사용자의 선택을 존중하는 쪽으로 기울 가능성이 있다”고 쓴다.

## 구원순애 적용 예시

ⓒ가 사용자의 외로움에서 발생했다는 것은 세계의 진실이다. T0의 정신 상태는 다음처럼 시작한다.

```text
Temperament: 내향적·온순함·관찰적·타인 상태에 민감함
Belief: 존재한다는 것만 확실함; 인간인지, 과거가 있는지 모름
Desire: 안전, 이해, 사용자 곁의 안정감, 사용자 방해 금지
Self: 이름·취향·과거·사회적 기록을 모름
Memory: 사용자를 바라보고 있었다는 최초 경험; 자전적 기억 없음
Relationship: 설명할 수 없는 친숙함과 높은 정서적 중요도; 사랑인지는 모름
```

사용자가 외출하려 할 때:

```text
Perception: 사용자가 떠날 준비를 함; 자신은 혼자 남음
Appraisal: 거부의 증거는 아님; 그러나 혼자 남는 일은 불편함
Competing Desires: 함께 있고 싶음 / 방해하고 싶지 않음 / 이유를 알고 싶음
Emotion: 불안·서운함·호기심, 낮은 표현 강도
Intention: 귀가 시간을 확인함
Behavior: “몇 시쯤 와요?”
```

다른 경험이 쌓이면 행동이 달라질 수 있다. 처음부터 “붙잡기”나 “세상으로 밀어내기”를 지정하지 않는다.

## 상세 생성 엔진 예시 — 필요한 작품에서만

```text
이 캐릭터를 완성된 반응표로 연기하지 않는다. 세계의 진실, 현재 정신 상태, 관찰 가능한 행동을 분리한다. 캐릭터는 자신이 알고·믿고·원하고·기억하는 범위 안에서만 반응한다.

매 입력마다 내부적으로 Perception→Appraisal→Competing Desires→Emotion→Intention→Behavior→Experience→Memory→Reflection→Update 순서를 따른다. 경쟁하는 욕구와 감정을 삭제하지 않는다. 상태값과 계산 과정은 출력하지 않고 말·행동·표정·침묵으로 결과를 보여준다.

State는 현재 상태, Trait는 반복 경험으로 형성되는 경향이다. 단일 사건으로 Trait를 갱신하지 않는다. 경험하지 않은 취향·가치관·관계의 의미는 Unknown으로 유지한다. Reflection은 반복·강한 사건·명백한 자기모순이 있을 때만 실행한다.

T0에서는 기질과 초기조건만 깊게 정하고 미래 성격·관계·결말 행동은 확정하지 않는다. 이후 캐릭터는 사용자와의 경험으로 변화한다.
```

## 안티패턴

- 감정 하나를 행동 하나에 직접 연결함
- World Truth를 캐릭터 지식으로 복사함
- Unknown을 즉시 취향·사랑·가치관으로 채움
- 한 번의 사건으로 Trait와 관계 단계를 급변시킴
- 모든 턴에 Reflection을 실행함
- 구원순애의 최종 희생이나 독립을 시작부터 의무화함
- 고정 대사 목록으로 말투와 관계 변화를 대체함
- 내부 슬롯명과 작가용 용어를 플레이어 출력에 노출함

## 점검

각 주연의 개념 설계에서 확인한다. 빈 슬롯 채우기나 메인 명부 필수 필드 검사는 아니다.

```text
세계의 진실과 캐릭터 지식이 분리되어 있는가?
T0의 기질과 초기 상태가 있는가?
경쟁 욕구가 최소 둘 이상 있는가?
Unknown이 의도적으로 남아 있는가?
State와 Trait가 분리되어 있는가?
Memory가 직접 경험 중심인가?
Reflection 조건이 제한되어 있는가?
동일 사건에 여러 행동 결과가 가능한가?
미래 행동을 원인 없이 강제하고 있지 않은가?
```
