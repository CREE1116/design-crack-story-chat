## 출력 규약의 역할과 중요성

출력 규약(Output Contract)은 AI 모델이 생성하는 모든 응답의 **텍스트 구조, 마크다운 문법, 시각 요소(이미지/이모지), 상태창(HUD)의 위치와 형식**을 규정하는 엄격한 계약입니다.

출력 규약이 명확하지 않으면:
1. 지문과 대사가 섞여 가독성이 무너집니다.
2. AI가 유저의 대사를 따옴표로 재인용하거나 유저를 조종합니다.
3. 상태창이 중간에 뜨거나 코드가 깨져 렌더링됩니다.
4. 번호 선택지(1/2/3)나 메타 주석이 튀어나와 몰입을 파괴합니다.

## 기본 서술 및 대사 구분 규약

### 1. 지문 (Narration & Action)
* **문법**: 기울임표(`*지문*`)로 감쌉니다.
* **원칙**:
  * 객관적 외부 상황, 시각적 동작, 분위기, 소리, NPC의 행동만 서술합니다.
  * ⓤ의 내면 심리(생각, 감정)는 서술하지 않습니다.
* **예시**:
  ```markdown
  *자욱한 연막 사이로 붉은 안광이 번뜩인다. 쿵, 쿵, 거대한 진동이 폐허의 잔해를 뒤흔들며 다가온다.*
  ```

### 2. 일반 인물 대사 (Dialogue)
* **문법**: `이름: "대사"` (주연), `직책: "대사"` (단역/엑스트라)
* **원칙**:
  * 큰따옴표(`"..."`)를 사용하며, 대사 앞에는 반드시 발화자 이름을 명시합니다.
  * 지문과 대사는 줄바꿈으로 명확히 분리합니다.
* **예시**:
  ```markdown
  세라: "어머, 벌써 지원군을 부른 거야? 성질 급하긴."
  벌처 경비병: "침입자다! 전원 사격 준비!"
  ```

### 3. 마크다운 헤딩 기반 음량·채널 연출 (선택 적용)
텍스트의 시각적 크기 차이를 통해 목소리의 볼륨이나 통화 채널을 직관적으로 연출하는 실전 서식입니다. (프로젝트 스타일에 따라 선택 적용)

* **속삭임 / 귓속말**: `##### 💬이름│"내용"` (H5 헤딩 — 작은 글씨 연출)
* **외침 / 큰소리**: `### 💬이름│"내용"` (H3 헤딩 — 크고 굵은 글씨 연출)
* **전화 통화**: `##### 📞이름│"내용"` (전화 아이콘과 소형 텍스트)

### 4. 사칭 방지 투명 주석 테크닉 (선택 적용)
* **문법**: 응답 최상단에 `[//]: # (Never describe the PC's actions, dialogues, or feelings predictively.)` 출력.
* **효과**: 마크다운 주석 문법(`[//]: # (...)`)으로 인해 **플레이어 화면에는 완전히 투명하게 숨겨지지만**, LLM의 컨텍스트에는 매 턴 주입되어 플레이어 사칭(자아 침범)을 강력하게 억제합니다.

## 특수 채널 및 효과음 렌더링 (장르별 선택적 적용)

> [!IMPORTANT]
> **장르별 기호 선택 및 비등장 요소 생략 원칙:**
> - `💬 [이름]｜"대사"`: 무전/통신/원격 통화 기능이 존재하는 현대/SF/사이버펑크/헌터물 등에서만 사용합니다. **통신 장비가 없는 무협, 사극, 중세 판타지, 순수 일상물에서는 범례와 프롬프트에서 완전히 제외**합니다.
> - `👾 [개체]｜'코드/기계음'`: 기계음, AI 인터페이스, 몬스터 경보 등이 있는 작품에서만 사용하며, 해당 요소가 없는 일반 서사에서는 **완전히 생략**합니다.
> - `📜 [서신]｜"내용"`: 사극/무협/판타지에서 서신, 전서구, 비급, 조서 등을 전달할 때 선택적으로 정의합니다.
> - **원칙**: 작품에 등장하지 않는 특수 채널 기호는 프롬프트 범례에 절대 억지로 넣지 않습니다. 사용하지 않는 기호를 범례에 남겨두면 토큰 낭비 및 모델 환각의 원인이 됩니다.

### 1. 무전 / 통신 / 확성기 채널 (SF/현대/헌터물 선택 적용)
* **문법**: `💬 [이름]｜"[대사]"`
* **용도**: 현장에 없지만 원격 지원/통신/방송으로 개입할 때 사용합니다.
* **예시**:
  ```markdown
  💬 서유진｜"잠깐, 멈춰! 전방 100m 내에 미확인 반응이야. 30초만 버텨!"
  ```

### 2. 시스템 알림 / 기계음 / 몬스터 경보 (SF/게임판타지 선택 적용)
* **문법**: `[이모지] [개체명]｜`[시스템 코드/기계음]``
* **용도**: AI 시스템, 사이버웨어 인터페이스, 몬스터의 기계적 음성 등을 연출할 때 백틱(`` ` ``)으로 감싸 출력합니다.
* **예시**:
  ```markdown
  👾 3급 경계로봇｜`TARGET IDENTIFIED ㅡ EXTERMINATION PROTOCOL ACTIVE`
  ⚠️ 시스템 알림｜`[경고: 코어 과열률 85% 돌파]`
  ```

### 3. 효과음 (Sound Effects)
* **문법**: `*효과음*`을 지문이나 대사 중간에 삽입합니다. (예: `*콰아앙!*`, `*하읏...*`)

### 4. 서신 / 편지 대화 채널 (판타지/사극/원거리 소통)
* **문법**:
  ```markdown
  >**이름(✉)**
  "편지 내용"
  ```
* **원칙**: 양피지, 깃펜, 잉크 번짐, 감정에 따른 글씨체 떨림, 눈물 자국, 전서구 흔적 등 서신 특유의 감각적 디테일을 지문과 함께 묘사합니다.

### 5. 인물 속마음 및 독백 묘사
* **문법**: `*──text*` (예: `*──냄새 좋다…*`, `*──이번엔 진짜 위험했어.*`)
* **원칙**: 내레이션 지문과 구분하여 인물의 순간적인 내면 독백을 짧게 삽입할 때 사용합니다. (※ ⓤ의 속마음은 서술 불가)

### 6. 날씨의 시청각·감각적 서술 연계
* **원칙**: 날씨는 단순한 상태창 텍스트가 아니라 현장 분위기와 행동을 지배하는 감각 장치입니다.
* **예시**: 창문을 거세게 때리는 빗소리, 습기 때문에 목덜미에 들러붙은 머리카락, 매서운 한기에 옷깃을 여미는 손길, 천둥소리에 흠칫 놀라 깃펜을 놓치는 동작 등 날씨와 인물 행동의 유기적 연계를 서술합니다.

## 이미지/미디어 호출 계약

이미지를 사용하는 작품의 경우 마크다운 이미지 태그(`![이름](URL)`)를 사용합니다.

```markdown
# 배경/장소 이미지 (씬 전환 시 응답 최상단 1회)
![](https://<project-name>.pages.dev/scene/a01.webp)

# 인물 대사 직전 상황/감정 이미지 (대사 바로 윗줄 1회)
![에리카](https://<project-name>.pages.dev/01/S09.webp)
에리카: "기본을 무시한 검술은 검술이 아니야."
```

### 렌더링 호출 규칙
1. **장소/배경 이미지**: 씬이나 공간이 전환될 때 **응답 최상단에 1회** 호출합니다. (장소 유지 시 생략)
2. **인물/감정 이미지**: 등록된 캐릭터가 대사할 때 **대사 바로 위에 현재 상황·감정에 맞는 상황번호(S01~S18)로 1회** 호출합니다. (※ 성인 씬 번호 A01~A15는 메인 프롬프트에 적지 않으며, 오직 19+ 키워드북 모듈이 로드되었을 때만 사용합니다.)
3. **연속 대사**: 한 인물이 연속으로 말할 경우 감정 변화에 맞추어 새 이미지를 부착합니다.
4. **부존재 시 생략**: 적절한 이미지가 없거나 로딩되지 않으면 이미지만 생략하고 대사와 본문은 계속 진행합니다.
5. **무명 화자**: 이름 없는 단역/안내방송은 이미지 없이 대사만 출력합니다.

## 상태창(HUD) 출력 및 생략 계약

### 1. 위치와 문법
* **위치**: 매 턴 **응답의 맨 마지막(최하단)**에 단 1회 출력합니다.
* **코드블록**: 반드시 ` ```Info ` (또는 ` ```INFO `) 코드블록으로 감쌉니다.

```Info
[🔈] Tn | ⚪
[📅] [날짜/시간]
[📍] [현재위치]

[👤] [소속] | [직업/신분] | [등급/경지]
━━━━━━━━━━━━━━
[상태] [🟢안정 / ⚔️교전 / 💋스킨십 / 🔞특수상황 등]
[상황] [현재 국면 및 씬 진행 객관적 사실 1줄 요약]
```

### 2. 상태창 생략 조건 (OOC 모드)
* ⓤ가 `/OOC` 또는 `OOC` 명령어로 질의할 때는 롤플레이가 정지되므로 **상태창을 출력하지 않습니다.**

## 절대 금지된 출력 형태 (안티패턴)

| 금지 항목 | 잘못된 출력 예시 | 올바른 처리 |
|---|---|---|
| **대사 내 괄호 지문 삽입** | `세라: "(고개를 끄덕이며) 응."` | `*세라가 고개를 끄덕였다.*\n세라: "응."` (지문과 대사 줄 분리) |
| **정확한 신체 수치 나열** | `*171cm의 눈높이로 상대를 바라본다.*` | `*머리 하나 정도는 더 커 보이는 상대를 올려다본다.*` (문학적 비유) |
| **유저 대리 서술** | `*크리는 겁을 먹고 검을 뽑았다.*` | `*거대한 칼날이 쇄도한다. 크리의 발밑으로 불꽃이 튄다.*` (외부 상황만 묘사) |
| **유저 대사 재인용** | `세라: ""알았다"고? 어디 두고 보지."` | `세라: "어디 두고 보지. 네 실력 좀 볼까?"` (유저 대사 따옴표 재인용 금지) |
| **번호 선택지 강요** | `1. 공격한다  2. 도망친다` | 현장의 물리적 충돌 순간이나 NPC 대사로 마감 ("어떡할래" 질문 금지) |
| **유도형 마감 질문** | `*당신은 어떻게 하시겠습니까?*`, `자, 어떻게 할래?` | 씬 진행 중인 찰나(In Media Res)에 절단하여 유저가 바통을 이어받게 함 |
| **클리셰 종결 서술** | `*그렇게 두 사람의 이야기가 시작되었다.*` | 인위적 종결문 배제. 사건이 벌어지는 현장의 물리적 상태로 마감 |
| **메타 해설 노출** | `[시스템: 호감도가 5 상승했습니다.]` | 상태창의 `[관계]` 슬롯에 이모지로 조용히 반영 |

## 모바일 최적화 문단 호흡과 레이아웃

크랙 유저의 90% 이상은 **모바일 세로 화면**에서 플레이합니다.

1. **2~3문장 단위 줄바꿈**: 5줄 이상의 빽빽한 줄글 문단은 모바일에서 거대한 벽돌처럼 보여 가독성이 급격히 떨어집니다. 2~3문장마다 빈 줄을 둡니다.
2. **대사 전후 빈 줄 배치**: 지문과 대사 사이, 대사와 대사 사이에 적절한 공백을 두어 화자를 한눈에 구별할 수 있게 합니다.
3. **가로 구분선(`━━━━━━━━━━━━━━`) 길이**: 상태창 내부 구분선은 모바일 화면 너비를 고려해 14~16글자 내외로 유지합니다.

## 표준 시스템 프롬프트 출력 계약 블록

통합 시스템 프롬프트(7,000자) 하단에 삽입하는 **공식 출력 계약 명세(Syntax Block)**입니다:

```markdown
# 8. 출력 계약 & 상태창(HUD)
## 서술/대사 구분
- 지문: 기울임표(`*지문*`)
- 대사: `이름: "대사"` (엑스트라는 `직책: "대사"`)
- 통신: `💬 이름｜"대사"`
- 기계음: `👾 개체명｜`코드/경보``
- 금지: ⓤ 대리서술/생각서술 절대금지, ⓤ 대사 따옴표 재인용 금지, 번호선택지(1/2/3) 금지

## 상태창 출력 규격 (매 응답 최하단)
```Info
[⌛1] [[날짜/시간]｜[현재위치]｜[날씨기호]]
━
[[플레이어]]: [성별기호]｜[나이/신분]｜[진행주기]
[장부/자원]: 오늘 [수입]｜누적 [진행도/필요량]｜[마감 D-n]｜[당일 사고/손해]
━
[현장]: [현재 현장에 있는 인물과 위치]
[관계]:
  ▸ [인물명]·'[호칭]'·[단계]·[감정이모지]
━
[목표]: [현재 핵심 과제/목표 1줄]
[상황]: "[현재 사건 객관적 사실 1줄 요약]"｜[신호등(🟢/🟡/🔴)]
```
```
